## 1. 谓词定义（**先定义，再判**）

> 方向约定：`s —P→ t` 表示"s 与 t 之间是 P 关系"；谓词定义里写明**方向**。
> 判据者**看不到原类型**（盲化）；原类型只用于事后对照（`contain/extend/reference` 到谓词的映射是否一致）。
> 本库三种边类型都是"枚举名"，目前**没有谓词定义**（B：`edge_types.py:29-54` 只有常量与默认 relevance）。所以这一节本身就是 G2 的产品输入。

### P1 组成/包含（part-of）

```
符号       s —part-of→ t        含义  t 是 s 的一个组成部分 / 集合成员
方向       s = 整体/集合，t = 部分/成员
传递性     可传递（part-of 链可折叠：A part-of B, B part-of C ⇒ A part-of C）——但**折叠后仍是结构信息，不算新语义**
成立条件   ① t 的概念/内容范围落在 s 内；② 去掉 t，s 的"组成清单"不完整；③ 不是"同名自指"
正例（本库真实边）  数字通信系统的基本组成 —part-of→ 信道（L2-20，教材/01）
                    数字通信系统的性能指标 —part-of→ 信噪比（L2-17）
反例（本库真实边）  ※线性相位理想低通滤波器 —part-of→ ※线性相位理想低通滤波器（L2-13，同名自指，不成立）
                    (1) 两个正交的脉冲信号 —part-of→ (2) 两个正交的已调信号（L2-16，同级并列，疑似错误包含）
                    （假想对）信噪比 —part-of→ 信道（无关）
现有类型映射       contain 应只承载 P1（派生）；reference/extend 不应冒充 P1
```

### P2 前置/依赖（prerequisite）

```
符号       s —prereq→ t        含义  要理解 t，必须先掌握 s（先读 s 再读 t）
方向       s = 前置，t = 后继
传递性     可传递（prerequisite 链可折叠）
成立条件   ① t 的定义/推导**确实使用** s 的概念；② 不是"只是排在前面"（顺序≠前置）；③ 不是"并列变体"
正例（候选真实边）  低通和带通信号抽样定理 —prereq→ 低通信号理想抽样（L2-07：先定理再具体抽样）
                    均匀量化 —prereq→ 非均匀量化（L2-09：均匀量化是理解非均匀的基线）
反例（候选真实边）  引言 —prereq→ 低通和带通信号抽样定理（L2-03：引言是背景，不是前置依赖）
                    低通信号自然抽样 —prereq→ 低通信号理想抽样（L2-12：属"对比/并列"，不是前置）
现有类型映射       extend 中**一部分**可能是 P2；须人判拆分
```

### P3 例证/实例（exemplify / is-a）

```
符号       s —exemplify→ t     含义  s 是 t 的一个具体例子 / 子类（t 更一般）
方向       s = 实例/子类，t = 一般/父类（**方向反了就是 Q4 要抓的错**）
传递性     可传递（is-a 链可折叠）；但与 part-of 混合时不可跨谓词折叠
成立条件   ① s 是 t 的一个具体实现/特例；② 不能说成 t 是 s 的例子；③ 不是"同义重复"
正例（候选真实边，注意当前箭头常反）  标量量化 —exemplify→ 模拟信号的量化（一般）  [当前边是 模拟信号的量化→标量量化，方向相反]
                                       A 律与 μ 律 PCM 编码 —exemplify→ 常用的PCM编码方式（L2-06 当前方向相反）
反例（本库真实边）  数字通信系统的基本组成 —exemplify→ 信道（是 P1，不是 P3）
现有类型映射       extend 中"子题展开"类可能是 P3；当前方向定义未区分
```

### P4 对比/并列（contrast）

```
符号       s —contrast→ t     含义  s 与 t 在同一层级/同一维度上可比较、互补或相反
方向       **对称**（Q4 选"不适用"）
传递性     不传递（对比不是等价关系；也不可与 P1/P2/P3 组合）
成立条件   ① 同层级/同维度；② 存在"X 与 Y 的区别/变体"关系；③ 不是包含、不是前置
正例（本库真实边）  低通信号自然抽样 —contrast→ 低通信号理想抽样（L2-12）
                    简单增量调制 —contrast→ 数字压扩自适应增量调制（L2-08：变体对比）
反例（本库真实边）  瑞利分布与莱斯分布的比较 —contrast→ 余弦信号加窄带高斯随机信号（L2-24：跨度不对，疑似松引用）
现有类型映射       reference 中一部分可能是 P4；extend 中"平行变体"也可能是 P4
```

### P5 引用/无断言（see-also / no-assert）

```
符号       s —see-also→ t     含义  此处可以跳去看 t；**不承诺任何关系/真假**
方向       **对称**（或方向无意义）
传递性     不传递（引用链不产生语义）
成立条件   ① 无真值断言；② 仅"延伸阅读/上下文跳转"
正例（本库真实边）  增量调制编码的误码性能分析 —see-also→ 两种编码的抗误码性能比较（L2-10）
                    差分脉冲编码调制（DPCM） —see-also→ 预测编码的基本概念（L2-11）
反例（本库真实边）  低通信号自然抽样 —see-also→ 低通信号理想抽样（L2-12 是 P4，不是纯引用）
现有类型映射       reference 类型按定义（`reference` = 无断言跳转，B：`kg-ontology-v0.md:48-56`）应只承载 P5
```

### D 退化标签：仅顺序（sequence-only，**不是语义谓词**）

```
符号       s —order→ t        含义  文档/教学顺序在 t 之前；除此之外没有可表述关系
判定用途   若大量 extend 被判为 D ⇒ 该类型"语义≈目录顺序"，不能作为语义关系类型（falsifier）
典型候选   引言 —order→ 模拟信号的量化（L2-03 邻居）；章节链 抽样定理→理想抽样→混叠→带通
处理       在统计中单列；**不计入"语义有效"分子**
```

## 2. 人判协议

### 2.1 判定者（几人？）

| 方案 | 人数 | 一致性 | 允许作证据？ |
|---|---|---|---|
| **A（优先）** | **3 名真人**独立 | α + Fleiss κ，可按人两两报 | ✅ 主证据 |
| **B（最低）** | **2 名真人**独立 | Krippendorff α（2 coder 可算）+ % agreement | ✅ 最低可接受；α 单值 |
| C（降级） | 1 真人 + 2 个 agent 代理 | α **只作内部一致性参考**；必须标"agent 代判≠人判" | ⚠️ 只作参考，**不独立支撑产品门禁** |

**本协议建议**：Lead 本人 + 另 1–2 名真人（若人同意安排）；不足 2 真人时按 C 执行并显式标注。
**判定者不看**：原类型、origin、derived、relevance、别人的答案；**只看**：两端名称 + 原文首句 + 所在文件/章节 + 谓词定义。
**培训**：10 分钟，用 8 条校准边（含 2 条已知坏、2 条已知好）练习；校准集不计入正式 24 条。
**注意检查（M2 判别力）**：正式 24 条里**故意放 3 条同名自指坏边**（L2-13/14/15）。若判据者把 3 条都判"保留/有语义"，则该判据者训练不合格，需重训或换人——这是"方法能区分好坏"的最低证明。

### 2.4 一致性怎么算

```
Q3(真值)/Q5(去留)/Q6(置信度)  → 序数：Krippendorff α（ordinal），bootstrap 2000 次给 CI
Q2(谓词)                      → 分类：Fleiss κ（≥3 人）或 Cohen κ（2 人，两两）
                              → 同时报"简单一致率 %"
判据者间差异                   → 先报 α/κ；α 达标后才做多数表决 + 分歧裁决（裁决记录写理由）
agent 代判                     → 单独一组，不与人混算主 α；人-机一致性作参考值
```

**预注册门槛**（全部先写死，避免事后挑数）：
- α ≥ **0.80**：一致性良好，结果可作证据；
- **0.667 ≤ α < 0.80**：暂定可用，但必须按 §2.5 扩样后才能当产品门禁；
- **0.50 ≤ α < 0.667**：marginal ⇒ 扩样（触发 E1）；
- α < **0.50**：**停止**，说明谓词定义/题目不可靠 ⇒ 改定义、重训、只保留校准集结论。
- Q2 的 Fleiss κ 门槛同 0.667（分类一致性）。

**级 1：人侧图谱效用（现在可做；不需要 agent 读边）**
```
目的   回答"人看图/看边是否真的帮助理解/检索"，是 L2×U 的人本版本
设计   被试内：同一 24 条候选边，条件 G（显示边）vs 条件 N（不显示边，只给节点列表）
任务   每题："给定起点知识点，下一步最该读哪个？为什么？"（答案=一组后继 KP + 理由）
指标   选择准确率、理由质量（0–2）、任务时间；配对检验
样本   24 名被试 × 24 题（每名被试 2 条件 × 24 题 ≈ 30–40 分钟）
功效   配对比例差 Δ=15pp、discordance≈0.3 ⇒ n≈24 可达 80% power（α=.05，McNemar）；
       若只招到 12 人，只能作 pilot（可检 Δ≈22pp）
成本   12–24 名被试 × 40 分钟 = 8–16 人时；无 GPU/LLM 成本
```

**级 2：agent 侧边消融（G6 接线之后；当前做不了）**
```
前置   agent 必须真正消费边（例如"按边扩展候选/按前置链路由"），否则 Δ=0
任务集 100 条真实问题：
  · 60 条"目标边"问题：12 条候选作者边 × 5 条/边？→ 太重。取 12 条 × 3 = 36 条
    + 24 条覆盖谓词/方向/溯源（P1–P5 各若干）
  · 40 条控制问题（不需要任何边；用于证明"删边不影响无关问题"）
  · 每题带：gold 答案 + gold 推理链（节点序列 + 边谓词），由 2 名标注者**从原文独立标注**（不从图抽）
数据来源  教材 + 真实会话问题（D 可作种子，需重放验证）；不得用图本身构造 gold 链（循环）
条件   全图 / 去目标边组（12 条）/ 去随机同数量边（控制）/ 去 extend 组 / 去 contain 组
指标   答对率、iters、tokens；McNemar（对错）、Wilcoxon（iters）
功效   n=100 配对、discordance≈0.2 ⇒ 检 Δ≈13pp@80%；分组消融（整体 extend 21 条）可检 ~10–12pp
宣布条件  单边必要性：**不做统计**，只做案例研究（3 条问题/边，报告个案与机制）
成本   100 题 × 2 条件 × 3 seeds = 600 次 agent run（≈10–20 h 机器 + token 成本）
```

### 3.3 功效表（写进预注册，防事后改口）

| 设计 | n | 可检最小效应（80% power, α=.05） | 能否支撑 |
|---|---|---|---|
| 现有真实问题 | 20 | Δ≈30pp（且无 gold 链） | ❌ 只能案例 |
| 分组消融（extend vs 全图） | 40 | Δ≈20pp | ⚠️ 只能粗判 |
| 分组消融 | 100 | Δ≈10–13pp | ✅ 分组级 |
| 单边（每条 3 题） | 3/边 | 无统计功效 | ❌ 仅案例（这是诚实结论） |

### 3.4 一句给 Lead 的直答

> **"当前数据量根本不可能"给出单边统计结论**；**分组级最小方案 = 100 条带 gold 链的真实问题 + 4 个条件**；
> **而 agent 侧消融在 G6（agent 读边）之前连测都是 0 效应**，所以 G2 阶段 L2×U 只能先做"人侧图谱效用"（级 1）。

## 4. build 状态字段清单（GUE 测量记录，缺一数字不可比）

> 依据：`kb_build` 会回写源 md/sidecar，实测同一副本 build 前 404 边 → build 后 454 边（B：`kg-visualization-v0.md:273-278`）。

|---|---|---|---|

| 5 | `build_sha` / 构建代码 commit | `collect_graph_data` 所在 commit | 同 build_state 下才可比 |
| 6 | `measurement_source` | `collect_graph_data()` / `build_knowledge_base()` | 两条后端路径看到不同边集 |
| 7 | `excluded_dirs` | `.memoria/{agent,build,cache}` | 缓存/会话不得入图 |

| 12 | `result_sha256` | 结果 JSON 的 hash（剔除 timestamp） | 可复跑/反查 |

**附加纪律**：① 同 commit + 同脚本 + 同参数连跑 2 次，除时间戳外逐字节一致（本次 G1/G2 已验）；
