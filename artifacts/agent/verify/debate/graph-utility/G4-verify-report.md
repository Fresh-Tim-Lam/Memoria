## 4. FAIL 明细（行号 + 原句 + 复算 + 建议）

### FAIL-1（关键）§3.1 的 357 帧"同文件"列与 BA 错误 + 原因句前提不成立

**原文**（lines 228-229、233）：
```
| `all_357_over_raw_graph`（357 / 62 边 raw） | 127,092 | 0.049% | 0.634% | 0.097% | 1.27% | 0.994* | 0.997* |
| `all_357_over_clean_graph`（357 / 54 边） | 127,092 | 0.043% | 0.618% | 0.0905% | 0.86% | 0.996* | 0.997* |
`*` = 帧伪影：357 帧含 278 个不在边里的孤立节点（无 file）⇒ 规则 BA 被孤立点抬到 ≈0.99，不能当可用基线
```

**独立复算（产品 `collect_graph_data()`，357 节点逐个读 `file` 字段）**：
- **357 个节点全部有非空 file（0 个为空）**；文件分布：`img/ch02-3` 161、`img/ch02-2` 81、`img/ch02-4` 42、`教材/03` 28、`教材/01` 21、`教材/02` 21、其余 3 个文件各 1。
- 357 帧同文件有序对 = **35,558**（`35,558 / 127,092 = 27.9782%`），**不是** 1,612（raw 帧写的 1.27%）或 1,094（clean 帧写的 0.86%）——这两个数是 **raw_79 / clean_65 的分子**（只统计被边覆盖节点的同文件对），却被放在 357 帧的分母（127,092）上 ⇒ **分子/分母混帧**。
- 正确平凡规则 BA（规则"两端同文件 ⇒ 判正"，正例=23 条 2 跳链）：
  - `all_357_over_raw_graph`：**BA = 0.8602**（不是 0.994）
  - `all_357_over_clean_graph`：**BA = 0.8602**（不是 0.996）
- 同分量列（0.634%/0.618%、BA 0.997/0.997）**正确**，与我的复算一致。

**根因**（`scripts/G4-path-census.py:143-151`）：
```python
def same_file_pairs(files, universe_nodes):
    ...
    # 只统计"有 file 的节点"之间的同文件对；无 file 的节点（孤立）算不同文件
```
该函数收到的 `files` 只来自边端点（覆盖节点），脚本没有为 278 个未被边覆盖的节点加载 `file`（输入只有 G1-baseline 的节点总数）；注释"无 file 的节点（孤立）"是**不符合产品数据的错误前提**（实际全部有 file）。census v2 的 `frame_note` 复制了同一错误前提。

**影响**：
1. §3.1 两行 ★ 数据不成立（虽然文件自己标注"不作可用基线"，但数字仍必须正确，否则 §0.1 ①b"平凡基线全报"的合规声明不成立）；
2. §0.1 line 29"R_file / R_comp 的 BA 可用帧 0.905–0.935"因此也错（见 FAIL-5）；
3. **不改变结论方向**：随机负例仍太易（正确 357 帧 BA 0.860 也 > 0.80；可用帧 0.869–0.871 > 0.80）。

**建议**：修 `same_file_pairs()` 的 universe 口径（357 帧用全部节点 file）并更新 §3.1 两行、§0.1 line 29、census `frame_note`；或删掉 357 帧的"同文件/BA 同文件"两列只保留同分量与可达。**不要**把混帧解释成"孤立点伪影"。
