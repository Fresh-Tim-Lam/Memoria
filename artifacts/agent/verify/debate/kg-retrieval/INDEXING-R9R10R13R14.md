### 9.2 指标怎么组合（否则会自欺）
- **检索门禁（可选项，因 n 小）**：M1 + M2。只有当 M1≥70% 且 M2 有害=0 时才允许把索引作为「先读索引再读切片」的唯一入口；否则保留 grep/全文兜底。**依据**：name-only 的 hit@3 只有 53.8%，而 45% 的问题在词法上直接跑偏（Q4/Q5/Q8/Q11/Q16 的 top-1 是无关幻灯片或错误单元）。
- **维护门禁（必须项）**：M4 + M5。这两个不达标时，索引越全越危险（返回错切片的概率随条数线性上升）。
- **成本/规划**：M6 + M7。
- **M3 是「description 是否值得写」的判据**：M3 从 45%→85% 是 R2 的目标；如果写完 description 后 M3 仍 <70%，说明问题不在描述而在**单元边界**（该合并/拆分），转去修 R1。

### 9.3 一个反直觉但重要的实测
**把原文前 40/160 字塞进条目反而让路由变差**：V0 53.8% → V2 38.5% → V3 38.5%（hit@3，13 问）。原因：原始 snippet 是「## 3.3 …」式标题+公式噪声，稀释了名称里的判别词（BM25 长度归一化 + 噪声 bigram）。
⇒ **description 必须是「人工/模型改写的问句型文本」，不是「正文截断」**。这一条直接否掉了「自动截首段当描述」的省成本方案（见 R10 的顺序设计）。

### 10.1 候选信源的质量对比（全部实测）

**判断**：块不是「比标题更可靠的基点」，而是**另一种可靠**——标题给语义边界，块给精确边界。正确做法是**两层叠加**，不是二选一。
**为什么块数不能当指标**：我口径下 502 块/文件，Lead 口径 525 块/文件（语料/定义不同）；块数随切分定义变化 → **块数是实现细节，不是质量指标**（falsifier：若换一种块定义得到同样的索引质量，说明块定义无关紧要）。

### 10.2 标题层级被压平时的切分算法（可执行）

```
输入：md 文本
1) 章：匹配 ^#{1,6}\s*第(\d+)章  或 文件名前缀 \d+_第N章 → chapter_id
2) 节：匹配 heading 文本 ^(\d+(?:\.\d+)+)\s*(.*)  → section_number="3.2.1", title
   （实测 373 个标题里 300 个可解析；教材全书 H1=1/H2=371/H5=1，标题深度无信息，必须用编号）
3) 无编号标题（slides/notes）：按出现顺序继承上一个 kind=section 的父节点；
   若整文件无编号（如 img/*.md）→ 不进入 section 模式，退化为 "page" 模式：
   unit = 一个 ## 页 + 其块范围，name = 标题原文（并标 source_kind=slide）
4) 单元范围 = 本 heading 行 → 下一个编号层级 ≤ 本级的 heading 前一行
5) 若单元 > 上限（建议 3,000 tok / 约 7,000 字）：
   a. 先在下级编号 heading 处拆（3.2.1 拆 3.2）
   b. 仍超 → 在块边界拆（相邻块，不切公式块/表格块），保留 1 块重叠
6) 锚点 = (section_number, 首块 hash → 末块 hash, 唯一 snippet ≥24 字)；
   line_hint 只作提示；块 hash 作缓存键，section_number 作重定位键
```

**依据（实测）**：教材 03 有 32 个 `##` / 28 个 KP（≈1.14 标题/KP，说明小节级粒度可行）；教材 02 有 19 个 `##` / 21 个 KP；p90 单元 9,421 字（≈3,957 tok）说明「按 `##` 直接切」仍会产出 4k tok 的大单元，需要第 5 步的拆分规则。

### 10.3 顺序：结构优先 + 用量驱动加深（不是「先问题反推」）

推荐流水线（每步都有成本与依据）：

| 阶段 | 做什么 | 成本（实测/投影） | 依据 |
|---|---|---|---|
| **S0 骨架** | 全库解析标题+编号 → chapter/section 树（不含正文语义） | **373 标题 = 2,935 tok**（0.5% 全书） | 一次建成，永不重新读正文；解决「这是哪一章/哪一节」与行号↔单元映射 |

**为什么不是「先从真实问题反推该建哪些」**：19 条问题太稀缺，反推会**过拟合**。
- 我用 19 问反推的「最小可用索引（MVI）」= **7 个单元、索引条目仅 143 tok、覆盖 15/15 内容+行锚定问题**——看起来极好；
- 但这 7 个单元全部落在第 3 章（抽样/量化/PCM），**下一条问第 4 章的问题时覆盖率立刻掉到 0**。
- **falsifier**：如果后续 10 条问题里有 ≥5 条落在非第 3 章，则「问题反推优先」失效，必须回到结构优先。

**可用的折中**：问题反推不用于「建哪些单元」，而用于**校验**（M1/M2 的标注集）和**给热点单元加描述**。

### 13.3 可执行规则（按优先级；每条带 falsifier）

- **R13-A（默认，有使用信号）**：**建「学习前沿」章 + 其前置 1 章**；其余章只留 S0 骨架。
  - 前沿信号（按可靠性）：最近打开的 md → 最近批注/高亮所在文件 → 最近会话提问涉及的文件。
  - 依据：19 问全部落在第 3 章；会话工具调用 36/37 次读第 3 章；第 3 章正好是「正在学」。
  - **falsifier**：用户并行学两章，或提问跨章（如「第 3 章和第 5 章的带宽定义区别」）时，单章前沿失效 → 改为「最近 N 个文件/最近 7 天」集合。
- **R13-B（冷启动，无使用信号）**：**从第 1 章按书序向后建**，不要按重要性排序。
  - 依据：P1 100% vs P3 18.2% vs P7 45.5%。
  - **falsifier**：若课程从中间章开始（如专题课只讲第 7–8 章），书序会浪费预算 → 此时用「教材目录中被标注为'本次课'的章」。
- **R13-C（有考纲/复习队列）**：按考纲顺序；**falsifier**：考纲章节与教材章节不是一一对应时，需先做章节映射。
- **R13-D（预算 = 20% token）**：第 1–3 章 = 111,943 tok，恰好覆盖本次真实使用的 100%；第 4 章起只放骨架（每章 0 额外读成本）。
- **R13-E（永不采用）**：按「重要性/中心度/公式密度」排序建 —— 实测 18.2% / 45.5%，低于或接近随机，且这些排序本身要**先读完全书（608k tok）**，成本等于「全都建」。

### 13.4 回答「为什么不是按重要性排」
1. **重要性没有可测的无监督代理**：中心度（词汇复用）实测 18.2%，接近随机 16.6%；「体量大=重要」63.6%；「公式多=重要」45.5%。
2. **算重要性比建索引还贵**：任何内容型排序都要先读全书（608,157 tok = 全量建索引的读成本）。而**书序是免费的**（文件名/标题编号直接给出）。
3. **真实使用服从「学习顺序」而不是「学科重要性」**：19 问集中在第 3 章，因为学生正在学第 3 章，不是因为第 3 章最重要（第 8 章最大 120k tok，0 问）。
4. 【判断】若数据里出现「跨章跳问」「复习课集中问第 8 章」等模式，上述结论会反转 —— 这也是 R13-A 需要「前沿信号」而不是「固定书序」的原因。

## R14 什么情况**不该建索引**（以及「错索引更糟」的具体形态）

### 14.1 不该建（或必须降级）的语料类型（实测）

| 语料类型 | 实测证据 | 判决 | 规则 |
|---|---|---|---|
| **OCR/PPT 提取的 md（`img/*.md`）** | 285 条现有单元：过「可描述」闸门的仅 **22.5%**；**42.1% 硬性不可描述**（formula-only 53、image-only 5、too-small 60、toc 2）；**32 组同名**（102 条）全部来自这里 | ❌ **不按知识点粒度建** | 要么不建；要么只建 **page 级**（一页一块）并标 `source_kind=slide`，禁止进入「先读索引」路径；或等 OCR 重排/人工校对后再建 |
| **公式块 / 图片块** | formula-only 3,557 块（24.4%）、image-only 984 块（6.8%） | ❌ 不作单元 | 作**附件索引**：`formula→unit`、`figure→unit`；绝不给它们写「这节讲什么」 |
| **目录/前言/附录/答案页** | 目录类 KP 11 条（span 35–143 字，内容是链接列表）；检测到 2 条 toc-like + 12% 的抽样单元「名字像正文、实为目录」 | ❌ 不建「知识」索引 | 标 `nav` 类型，只用于「书有几章」类问题；**不得写会承诺内容的 description**（这正是 Phase 1 的 C 类错误来源） |
| **纯公式密集页（无散文）** | formula-heavy(warn) 111 条（31.0%） | ⚠️ 降级 | 可作单元，但 description 必须从**相邻散文**生成；若相邻也无散文 → 不建 |
| **作业/习题 md** | 4 个 homework 文件，0 个 KP | ⚠️ 另建 | 习题/答案应建独立「题目索引」（题干+考点），不要混入教材知识索引，否则「求定义」会命中习题 |

**判断（我的判断）**：这套语料里 **幻灯片/OCR 部分不值得按知识点建索引**——它贡献了 80% 的条目、却贡献了 100% 的同名冲突和 42% 的不可描述单元。教材正文（66.2% 过闸）才是索引的主体。

### 14.2 「错索引比没索引更糟」的 4 种具体形态（都已有实测证据）

| 形态 | 机制 | 证据（可复跑） | 后果 |
|---|---|---|---|
| **① 静默错锚** | line_hint 漂移后仍被信任 | `02`：前插 40 行 → hint 平均错 **37–40 行**，snippet 仍 100% 找到；若实现用 hint 取片 → 返回**别的段落**且不报错 | agent 读到错内容但以为读对了（Phase 1 已证：产品自己的高亮写入会改写锚点句） |
| **② 同名异内容** | 查询命中同名条目，但内容不同 | `07` E5：32 组 / 102 条；22 组内容相似度 <0.30；按名查询的**期望读错实例 = 77.6%** | 「查 A 得到 B」，且 B 名字完全对得上 → 不会触发怀疑 |
| **③ 名不副实单元** | 名字承诺知识、实际是目录/公式 | Phase 1 抽样：C 类 2/20=10%（`连续时间信号的复频域表示` span 只有 92 字提纲；`性质3：展缩特性` 无主语）；`07`：37.2% 单元不过可描述闸门 | 「读到了，但学不到」，agent 误以为已获取知识（最隐蔽） |
| **④ 陈旧描述/锚在维护后仍坏** | 重算 range 时把坏锚一起"保留" | §0.2：12:01 重算后 `linear-pcm-error-performance` 的 `end="$$"` 仍解析到 2752（start 2792）→ range 反转，无人报错 | 越"维护"越可信，实际已坏 |

### 14.3 怎么**证明**「错索引更糟」（而不是只声称）
【判断 + 可执行实验设计】定义**假确信率**并做 A/B：
```
实验：同一批 ≥30 条真实问题，两组 agent：
  A 组：可用索引（先读索引再读切片）
  B 组：无索引（grep + read_document 全文窗口，同 token 预算）
测量：
  (1) 答案正确率（人工盲评 0/1/2）
  (2) 假确信率 = agent 读取的单元内容不含答案要点、但最终答案仍引用该单元的比例
  (3) token 成本
预测（待验证）：A 组 token 显著低、正确率不低；若 A 组假确信率 > B 组 2 倍，则「错索引比没索引更糟」成立。
falsifier：若 A 组正确率与假确信率都不劣于 B 组，则「更糟」是伪命题，索引只剩省 token 价值。
```
**在实验做完之前，上面的 4 种形态只能证明「错索引会产生错误内容」，不能证明「比没索引更糟」**——区别在于：没索引时 agent 会去全文检索（成本高但不易被误导），有错索引时它会**停止搜索**。

### 14.4 不该建的决策树（可机器执行）
```
for each md file:
  if cjk_ratio < 0.05 and formula_lines > 0.5: skip          # 纯公式页
  if image_only_lines / nonblank_lines > 0.4: skip           # 图片为主
  if headings >= 2 and numbered_sections >= 1: section_mode  # 教材正文
  elif headings >= 2: page_mode + source_kind=slide          # 幻灯片
  else: file_level_only                                      # 无结构长文
  if unit_pass_rate(prose gate) < 0.4: do not build unit index for this file
  if toc_like(unit): mark nav, no knowledge description
```

## 6. 我不确定的点 / 需要别人补的

1. **路由实验的检索器是我写的 BM25 字符 bigram**，不是产品检索；它只用于**相对比较**（变体之间/策略之间），绝对值不代表产品 hit 率。产品真实检索的失败证据仍是会话日志（`search_kb("量化")`=0 命中、6 次 top-1 跑偏）。
2. **labeled 问题只有 13 条可文本路由**，1 条 = 7.7pp；合格线（M1≥70%）是【判断】而非统计结论，n 太小无法给置信区间。
3. **「有害误路由」阈值 0.25 是【判断】**：实测错路由相似度 0.01–0.18，所以 0.25 下有害=0；若阈值降到 0.15，V7 的 Q3/Q9/Q16/Q18 会变成「有害」（似是而非）。这个阈值需要更大标注集来标定。
4. **同名碰撞 77.6%** 是按「用户以名字查询」的假设计算的；如果检索器总会返回 top-3，风险会降到 1-C(1/n,?) 量级，需要实测。
5. **覆盖策略的验证只用了一个学生的一次会话**（19 问、全在第 3 章）。R13-A/B 的 falsifier 是明确的，但证据强度有限；需要第二/第三个用户/课程的数据。
6. **R10 的块稳定性实验只做了 03 一章**的三类编辑（插空行/删空行/改一行）；插入段落导致的行号平移已在 Phase 1 测过，但「块偏移平移」的精确量纲未逐块统计。
7. **复习记录/批注信号未分析**（`.memoria/agent/review/**` 未读），R13-A 的「前沿信号」优先级排序缺少这部分证据。
8. **12:00–12:01 的新建/修改来自谁未确认**（可能是人/另一个 agent 的实时操作）；我只记录事实，不推断动机。相关文件：`notes/非均匀量化噪声推导-附录.md`、其 sidecar、`教材/03`。

## 7. 一句话总结（给 Lead 汇总用）

**科学建索引 = ① 用「编号标题」做骨架（免费、稳定）＋ ② 用「空行块」做精度层（内容寻址、但不能当语义单元）＋ ③ 只给「有兄弟竞争/热点/大单元」写问句型 description（不是截原文）＋ ④ 覆盖按「学习前沿/书序」而不是「重要性」（重要性代理实测 18%≈随机，且算它要先读完全书）＋ ⑤ 每次写入同事务重算 range 并校验 snippet（否则"维护成功"也会留坏锚）。**
判据用 M1–M7：检索看 M1/M2，维护看 M4/M5，成本看 M6；**M3 决定值不值得写 description，M7 只是过程指标**。
不该建：OCR/PPT 提取页、纯公式/图片块、目录/答案页（它们贡献 42% 不可描述单元和 100% 同名冲突）。
