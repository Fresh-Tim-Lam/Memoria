## R1 锚点：**P0，且与露 id 串行**

### 裁决
```
① 锚点修复是 P0；露 kp_id 是 P1，不得独立上线。
② 必须加 anchor gate（三个判据，缺一不可）：
   · range_ok == False                    → ANCHOR_UNRESOLVED（拒绝返回内容）
   · snippet 在文档内出现 >1 且无法消歧    → AMBIGUOUS_ANCHOR
   · end 非唯一 / 超预算 / 解析失败        → 夹到下一同级标题
③ 只有 anchor_verified 的 KP 才允许把 id 露给模型。
④ 正文写入必须【同事务重算 range】——不得事后补。
```

### 依据
- **A**：真库 357 KP 中 132 条（**37.0%**）snippet 不唯一；前插 50 行后 67 条（**18.8%**）静默钉错且 `ok=True`。
- **C（本轮最重发现）**：`read_kp` **连 `range_ok` 都不检查** —— `kb.py#L344-L351` 用 `start_line or 1`，range 解析失败时**静默返回第 1 行内容**。这不是"锚点漂了还能勉强用"，是"坏了返回错内容且不报错"。
- **语料（现场事故链）**：产品自己的"划高亮"改写 ch03:302 定义句 ⇒ 该 KP snippet 当场失效；随后插入使行号漂移；`linear-pcm-error-performance` 的 `end="$$"` 导致 **range 反转（2788→2748，span=0）**，无人报错。12:01 的"重算"把 start 修 fresh 了，end 仍坏 ⇒ **"维护成功"可以继续坏着**。
- **影响面已实测**：`read_kp` 6 次 + `search_kb` 用 `line_hint` 报位置 7 次 = **13/92 = 14.1% 的读取路径**已踩在上面。

### Falsifier（会推翻 R1）
- 若加 gate 后 **>50% 的 KP 变成 ANCHOR_UNRESOLVED/AMBIGUOUS** ⇒ 说明"修复"其实是"停用"，必须先做重建管线再谈 gate。
- 若能证明 agent 实际**从不消费** range（只读整篇）⇒ 降级为体验问题（但 C+语料已证伪此前提）。

### 影响面
产品行为改变（读取路径会开始报错而不是静默返回错内容）；需回归测试。

## R2 索引单元：**身份 = kp_id，单元 = 带 `kp_ids[]` 的切片视图**

### 裁决
```
① 不新建第二套语义 id。kp_id 是唯一身份（FSRS / 图谱 / 引用 / 会话 anchors 的共同锚）。
② 索引单元 = 切片视图 (file, section_number, char_range, kp_ids[])。
③ 允许有 slice_id，但它是【视图键】，只用于缓存与定位，禁止承载语义。
④ 切片必须能映射回 kp_id；映射孤儿率作为门禁（阈值见下）。
```

### 依据
- **B 与 C 独立收敛到同一结构**（这是本轮最强的交叉验证）：
  - B：覆盖=派生切片（不新建 id，带 kp_ids[]）+ 语义=保留 KP + KP→切片映射
  - C：身份=kp_id，单元=带 kp_ids[] 的切片视图，slice_id 只做视图键
- **C 的硬依据**：FSRS 卡 **105/114 张以 kp_id 为锚**；review 工具行含 kp_id（`kb.py#L4732`）；图节点 id = kp_id（`collector.py#L55-L65`）；ontology node 含 kp_id；会话 anchors 按 (file,line,kp_id) 去重（`history.py#L583-L587`）。
  ⇒ 换新 id 会让「已复习/到期」无法进入 agent 路由，"agent 已读"与"用户已复习"错位。
- **粒度依据**：KP 尺寸口径已统一（见 §0）；教材 KP 下 >1200 字占 **69.0%**、全部 KP 占 **24.6%** ⇒ 教材正文的标题级边界确实过粗，需要切片；但**不需要换身份**。

### Falsifier
- 若 KP→切片映射孤儿率 **>20%**（切片找不到归属 KP）⇒ 视图方案退化为并行事实源，必须重设计。
- 若切片与 KP 的边界长期不一致导致用户困惑（UX 验证）⇒ 考虑让 KP 直接采用切片边界（改边界不改身份）。

### 影响面
**用户数据语义（边界会变，id 不变）** → 列入 R7 需人确认清单。

## R3 检索通道：**结构不走 RRF**

### 裁决
```
① 索引/结构不作为 RRF 的第 3 条臂（RRF 是 rank-only，表达不了邻接/顺序/多跳）。
② 结构的作用位置：
   · 检索前：确定性过滤（章节范围、section_number 序）
   · 检索后：有界跳数扩展（限定 hops，超界标 not_shown）
   · 排序：确定性结构序（章序 / section_number），不是相关度
③ 若必须与 lexical/semantic 融合，用【分数加权线性】并单列 A/B，不叫 RRF 臂。
④ 现有 `retrieval_fusion.py#L47-L51` 的 `graph` 权重占位标记为"未启用/未验证"。
```

### 依据
- **外部**：查遍四类真实实现，**没有**"图/结构通道进 RRF"的实例 ——
  HippoRAG = **PPR 传播**（arXiv:2405.14831）；GraphRAG = **社区摘要 map-reduce**；
  LightRAG = **按 id 轮转合并 + 配额截断**（`operate.py#L5811-L5814`）；
  XERJ = **跳数邻域遍历的独立 API**（`brain_ego` hops≤2 + `not_shown`）。
- **B**：RRF 只融合 rank（`retrieval_fusion.py#L7,L68-L95`），数学上不含顺序；本体已裁边不服务 agent（35 会话 0 次 edge_type）⇒ 只能表达"相关"，不能答"先学哪个"。

### Falsifier
- 给出「图通道进 RRF 后 iterations 降且答对率不降」的实测 ⇒ 可推翻。
- 若确定性结构序在跨章节问题上覆盖 <30%（B 实测 7/15 需跨 ≥2 KP）⇒ 需补"覆盖集 + plan 步"设计。

### 影响面
不改变现有检索栈（只是不作为第 3 臂），风险低。

## R4 KPI 与验收

### 裁决
```
P0 门禁（确定性、全量、可复跑）：
  M4 锚点健康：fresh ≥99%、inverted = 0、anchor_verified 覆盖率
  M5 陈旧：增量 = 0、静默坏 = 0
  M2 有害误路由：= 0（同名碰撞必须消歧）
  M12 新增：索引上线后 Δhit ≥ −5pp（不得破坏缓存前缀）
P0 观测（不作为通过与不通过的门槛）：
  峰值 prompt（现状 845,926 = 1M 的 84.6%）
P1 观测：iters/answer、tool calls、compaction 次数、单次工具结果 max
已废弃：
  · M1 hit@3 ≥70% / M3 可判性 ≥85% → 降为【预注册 smoke】，只做回归比较，不作门禁
    （n=13 时 Wilson95=[49.7,91.8]；n=20 时 C=0 上界 16.1% ⇒ 统计上不可证）
  · iterations 作为主 KPI → 候选（需三臂实验，尤其 Arm-1「只注入索引 token 不改行为」）
```

### 依据
- **D（自攻）**：放大系数算错 9 倍、token 放大 ≠ 费用放大；`-20.5%` 是算术；命中率 94.17% 但 compaction 后掉到 61–84%（8 次）⇒ **峰值才是真危险（84.6%）**。
- **语料（自攻）**：M1/M3 阈值在自己的样本量上不可证；建议门禁改用确定性全量指标。
- **C**：给出精确关系 21 轮 / **116 iterations** / 135 calls；`iteration = 一次 LLM 请求 = step/start 1:1 assistant/message`（116=116 验证）；calls/iteration = 1.164；iterations/turn = 5.524；并行分布 {0:21,1:60,2:31,3:3,4:1} ⇒ 30.2% 为多调用并行。
  **建议新增 `step/usage` 埋点**（`loop.py#L306-L316` 已有累积）—— 这是把"省 1 iteration"从算术变实测的前置。

### Falsifier
- 若 M4/M5/M2 全绿但用户体感仍差 ⇒ 说明确定性门禁覆盖不到价值维度，需补（但仍不能用不可证的小样本阈值）。

## R5 字段：**1 必填机器字段 + 1 可选人读 note**（推翻 B 的撤回）

### 裁决
```
① `description`（必填，机器读）：问句型，≤80 字，必须含"何时不该读"。
   —— 实测：截原文 hit@3 53.8%→38.5%；改写问句型 → 76.9%。
② `note`（可选，人读）：可空、不阻塞落盘、不参与机器判据；落盘率【分开计】。
③ 禁止：把正文前 N 字塞进 description（实测会使路由变差）。
④ v1 验收：`description` 落盘率 ≥70%（当前大库 0/357、Vocab 25/134）；
   note 填写率仅作观察（预期 <10% 属正常）。
```

### 依据
- **外部（反打 B）**：主流做法全是**按消费者分层字段** —— LlamaIndex `MetadataMode` + `excluded_embed_metadata_keys`/`excluded_llm_metadata_keys`（`schema.py#L242/#L294-316`）；LightRAG 实体 6 字段 + 4 字段强校验（`operate.py#L753-L760`）；XERJ catalog 机器字段 vs `notes`；AOCI F/R/A/S + 独立证据身份。
- **B 自己的一手证据**（`PROPOSAL-todo-owner.md#L64-L68`）：AAA_Vocab 25 条真实混用两种用途、明确写"一个字段无法同时最优服务两个受众" ⇒ B 的撤回**与自己的证据矛盾**，故不接受。
- **B 的担心（作者负担）已被 R5② 覆盖**：note 可空、不阻塞、不影响机器判据。

### Falsifier
- pilot 显示"带 note 组落盘率显著更低"或"note 填写率 <10% 且造成困扰" ⇒ 降为纯可选 UI 字段（不进 schema）。

## R6 第一性原理修正：**索引的价值不是"目录"，是"跳过往返"**

### 裁决
```
① 原假设「建骨架索引 → agent 先看目录 → 再决定读哪章」【不成立】。
   实测：section 标题骨架（373 条 / 2,227 tok）hit@1 55% / hit@3 70%；
        无索引直接 grep 同量级 55% / 70%；跨库 157 条会话 hit@3 50.3% vs grep 52.9%。
   ⇒ 骨架索引在冷启动【不比 grep 更好】。
② 因此 0.5.x 的价值主张必须改写为：
   「索引的价值 = 让 agent 用更少的往返（iterations）直接命中切片」，
   而不是「给 agent 一张目录」。
③ 推论：判决性指标是**往返次数**与**错切片率**，不是"有没有索引"。
④ 冷启动策略（替代原"书序建深"）：
   C0 导入只建 section 骨架（2.2–2.9k tok）→ C1 首问 grep/read 定位 →
   C2 命中即 lazy 深化该章 → C3 失败（约 30–50%）读 top-3 候选 / 让用户点章 →
   C4 **禁止冷启动按书序建深**。
```

### 依据
- **语料（实测）**：见上；且真实会话 Q1 就是 **0 KP 时** 完成的（`search_kb("量化")` MISS → `kb_overview` → `grep` → `read_document(教材/03,293)`）。
- **语料（反事实）**：真实 4 库中「书序」覆盖 9.7%/15.2%/100%/89.8%，前沿优先 2 胜 2 平 0 负 ⇒ 书序只能作冷启动兜底，且兜底本身不可靠。
- **C**：`read_kp` 采用率低的真因是 kp_id 不可见；但锚点未修时露 id 会放大错误（R1）⇒ 价值必须由"命中质量"体现。

### Falsifier
- 若加入切片级 description 后，索引组的 **iterations 不比 grep 组低** ⇒ R6 的价值主张失败，应放弃索引路线（或改为纯工具结果预算优化）。
- 若 lazy 深化的首次提问质量显著低于预建（A/B）⇒ 需改回预建，但优先建"用户已打开的章"。

### 影响面
**这是 0.5.x 立项前提的改写** → 列入 R7 需人确认清单。

## 8. 不做什么（明确边界）

```
· 不做 GraphRAG 全局检索（机制不匹配：我们 97.5% 读同一章）
· 不做 RAPTOR 递归摘要树（建树成本无公开数据，收益场景不匹配）
· 不做 Self-RAG / Adaptive-RAG（需训练管线）
· 不做语义切分（成本不抵收益；且我们的问题是"边界不可靠"不是"切分算法不够好"）
· 不新建第二套语义 id
· 不以"提高缓存命中率"为目标（已 94.17%；改为 Δhit ≥ −5pp 否决条件）
· 不搬 AOCI 的完整重写回环（可搬：证据身份 / 哈希基线 / 软失效）
· 不把 M1/M3 的小样本阈值当门禁
```
