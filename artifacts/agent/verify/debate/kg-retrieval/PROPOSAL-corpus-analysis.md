## 1. 结论摘要（≤12 行）

1. **现有 KP 不能直接当索引单元，但「KP（小节级）+ range + 一句描述」这个形态可以——前提是重建而不是复用。**
2. 现状索引只覆盖 **4/14 教材章**：10 章零 KP；**61.8% 的教材 token 没有对应 KP**；407KB 的第 8 章只有 1 个测试 KP。真实会话前 6 个问题发问时，第 3 章 **0 个 KP**——索引不是「已有待复用」，是「要现建」。
3. 粒度是「标题切分」不是「学习单元」：教材 KP 的 span **p50 1,822 字 / p90 9,421 / max 18,198**；93.3% 的 KP 起点就是 markdown 标题行；教材标题层级被压平（H1=1、H2=371、H5=1），层级只能靠编号 `3.2.1` 还原。
4. **可判性实测：20 个 KP 里 45% 只看 name（+首尾 snippet）判断不了**（其中 10% 会判错/读不到内容，35% 只能判主题、不能判「读不读/读哪条」）。瓶颈不是「缺例子」，而是**缺范围、缺与兄弟 KP 的边界、缺结论要点**。
5. 名称机制不可靠：名称 p50 12 字、35.6% ≤6 字、**29.7% 重名**、11.2% OCR 脏；实测会话里 `search_kb("量化")` 直接 **0 命中**（另有 6 次检索 top-1 完全跑偏）。
6. **锚点今天基本健康但很脆**：353/357 start hint fresh；但 37% start snippet 在同一文件出现 ≥2 次（p50 仅 16 字）、15% end snippet ≥2 次；已坏 4 类（1 个 end 找不到、1 个 end=`$$` 导致 range 反转、4 个 start 漂移）。
7. 漂移实验：前插 40 行 → **snippet 仍 100% 找到，但 line_hint 平均错 37–40 行**；改动锚点行本身的文字 → snippet 只剩 **0–53% 能找到**。「共享锚点」不能只存行号，必须是「唯一 snippet 为主、行号为提示」。
8. 结构上「按块切分」可行，但必须按**小节编号**切而不是按标题深度切：教材正文是公式密集（9,441 inline + 2,827 display）、477 图、12 个 ≥2,000 字段落（max 14,186 字）。
9. **真实提问只集中在极少 KP 上**：19 问 = 15 内容问 + 4 元问题；15 内容问里只有 **5 个能靠单个 KP 名定位**，**7 个需跨 KP 综合**，2 个只能靠行号；3 个问题**根本没有对应 KP**（对比/设计理由/公式层面对比）。
10. 会话成本结构：19 轮 prompt 合计 **4,299,246 tok**、均值 **226,276**、峰值 **656,818（65.7% of 1M）**、**8 次 compaction**。但 `read_document` 37 次**全部是 offset/limit 窗口切片**、合计仅 117,103 字——「整章读入」不是主要成本，**累积历史**才是。索引层的真实收益是「选对切片、少走弯路」，不是「少读文件」。
11. **R1**：索引单元 = 小节级 KP（目标 800–2,000 字 ≈ 350–850 tok），一章 25–40 个；沿用 `{id,name,range}` 并新增 `description`（+沿用 `tags`/`edges`）。
12. **R2**：description ≤40 字，模板固定三段「讲什么｜关键结论/公式｜与相邻单元的区别/适用条件」；当前真实库 **0/1590 条 KP 有 description**，数据管道必须先保证落盘。**R4**：snippet ≥24 字且全库唯一 + line_hint 仅提示 + 打开前校验，拒绝 `$$`/空行/纯编号结尾。

## 2. ① 现有 KP 粒度：是「标题切分」不是「学习单元」

### 2.1 目标库 KP 总览（实测）

| 指标 | 值 |
|---|---|
| sidecar 文件 | 12（教材 5：01/02/03 为真实章、00 空、08 仅测试；img/slides 5；notes 1；根目录测试 1） |
| KP 总数 | **357** |
| 教材 KP / slides KP / notes KP | **71 / 285 / 1** |
| 有 KP 的教材章 | **4/14**（01、02、03 真实；08 只有 1 个测试 KP） |
| 无任何 KP 的教材章 | **10**（00、04、05、06、07、09、10、11、12、13） |
| 教材未索引 token 占比 | **61.8%**（375,142 / 606,619 tok） |
| 索引条目本身成本 | names-only **2,063 tok**（5.8 tok/KP）；+tags 3,581；+首 40 字 snippet 4,601 |

### 2.2 span 大小分布（我的复算；与 Lead 独立复算一致）

| 口径 | n | p50 | p90 | max | <200 字 | >3000 字 |
|---|---|---|---|---|---|---|
| **全部 KP** | 357 | 535 字 | 2,903 字 | 18,198 字 | 72（20.2%） | 33（9.2%） |
| **教材 KP** | 71 | **1,822 字（≈766 tok）** | **9,421 字（≈3,957 tok）** | 18,198 字（≈7,643 tok） | 12 | — |
| **slides KP** | 285 | 472 字 | 1,688 字 | 7,400 字 | 60（21.1%） | — |

**判断（我的判断）**：教材 KP 的尺寸是「节」而不是「学习单元」——p50 766 tok 已经超过「一句话能说清的范围」，p90 近 4k tok 意味着 **10% 的 KP 读一条就等于读半章**。相反 slides 的 KP（p50 472 字）更像「一页 PPT 的小概念」。**同一套 KP 概念在两种文档上落成了两种粒度**，所以「KP 能不能当索引单元」不能一刀切回答：**slides 的切法接近可用，教材的切法不可直接复用**。

### 2.3 KP ≈ 标题切分（实测，而非判断）

- **333/357（93.3%）** 的 KP 起点就是一行 markdown 标题（`#`…`######`）；
- 起点所在父标题层级：H2 **350**、H3 3、H5 3、H1 1 → **KP = `##` 小节**；
- 教材 14 章的标题层级合计：**H1=1、H2=371、H5=1**（没有 H3/H4）。也就是说书里的「3.2.1」也是 `## 3.2.1 …`，**标题深度不编码层级，层级只能从编号字符串解析**；
- 教材 03 章：**28 个 KP / 2,956 行 / 91.7% 行被某个 KP 覆盖**；教材 02：21 KP / 93.7%；教材 01：21 KP / **64.2%**（第 1 章有 35% 正文不在任何 KP 内）。
- 结论：**现有 KP 是「标题 → 条目」的机械映射，不是按「一个可学习/可检索的语义单元」切的。** 证据：`2.4 希尔伯特变换及应用` 一条吞了 17,344 字；`非均匀量化` 一条吞 13,057 字；而 `线性 PCM 编码的误码性能分析` 的 range 甚至反转（见 §5）。

## 3. ② 可判性实测（本任务最重要）

### 3.1 协议（可复核）

- 样本：`data/sample20.json`，**分层抽样**（教材 10 / slides 8 / notes 2，seed=20261027）。分层理由：真实提问全部落在教材，slides 是辅助资料；若按 285:71 的比例抽样会几乎抽不到教材。
- 给定信息：**只有** `name` + `file` + `heading_path` + `range` 首尾 snippet + 行号（即索引层能暴露的全部信息）。
- 步骤：先凭名字写「这个 KP 回答什么问题 / 要不要为某个真实问题读它」，**再**打开 span 首尾核对；判定 A/B/C 记入 `data/manual-judgments.json`。
- 局限：判定由我一个人做（见 §8 不确定点），但 20 条样本、判据、正文首尾全部落盘，可复核/重判。

### 3.3 ★「判断不出来时缺什么」分类 → description 字段设计依据

| 缺失类型 | 样本 | 频次 | 对 description 的字段要求 |
|---|---|---|---|
| **范围 / 子主题清单**（这节覆盖哪些子问题） | 4, 6, 8 | **3/9** | 描述必须能回答「这节有哪些内容」；长节（>3k tok）需要子主题列举，而不只是主题名 |
| **与相邻 KP 的对比 / 唯一性**（读哪一条、和谁不同） | 3, 11, 15 | **3/9** | 描述必须写「本 KP 与同名/近邻 KP 的差异」；重名必须靠描述或 id 消歧 |
| **结论 / 公式要点**（名字是主题，不知道结论） | 17 | 1/9 | 描述要含一条可判定的结论（含关键符号/条件），而不只是名词短语 |
| **所属对象 / 前提**（这条性质是谁的性质） | 14 | 1/9 | 描述要含主语 + 前提（对象、定义域、适用条件） |
| **内容形态**（名字承诺正文，实际只有目录/提纲） | 12 | 1/9 | 需要「内容形态」位（正文/目录/公式/例题/习题），避免把目录页当知识 |

**两个反直觉的实测结论：**

1. **「缺例子」不是路由瓶颈。** 20 条里没有一条是因为「不知道有没有例题」而判断不了。例子在长节内部，影响的是「读完能不能讲清楚」，不是「该不该读」。→ **description 的优先级：范围 > 边界 > 结论 > 例子**。
2. **45% 的不可判性中有 1/3 来自「兄弟 KP 边界」，不是「单个名字太短」。** 这批 KP 名（如「非均匀量化」「零输入响应」）本身是教材黑话，学生/模型都认识，但**无法在同族 KP 里选对**。→ description 必须写成**可比较**的（「与 X 的区别是…」），而不是百科式定义。

### 3.4 名称机制的机械佐证（全量 357 条，非抽样）

| 指标 | 数量 | 占比 |
|---|---|---|
| 名称 ≤6 个汉字 | 127 | 35.6% |
| 名称在库内重复 | 106 | 29.7% |
| 名称带 OCR 噪声（`u `/`n `/`※`/`(续)`） | 40 | 11.2% |
| 名称是导航性条目（目录/单选题/小结/定义：/求解过程/引言/本章小结） | 18 | 5.0% |

**真实检索失败证据（会话日志，实测非判断）：**
- 第 1 问「什么叫量化」→ `search_kb("量化")` 返回 **「未在知识库中检索到与 '量化' 匹配的内容（lexical 通道，库内 329 条 KP 记录）」**；
- 之后的 6 次 `search_kb` 虽然返回 HIT，但 top-1 多次完全跑偏：查 `脉冲编码调制 PCM 定义` → top-1 `狄拉克(Dirac)定义`；查 `量化电平 二进制 码组…` → top-1 `比特能量与噪声密度比`。
- 我另做了一个**朴素 bigram 词法基线**（`data/question_kp_lexical.json`，**不是产品 BM25**）：19 问的 top-3 候选里，「什么叫量化」→ `瑞利分布与莱斯分布的比较(1)`；「带通抽样条件」→ `对数量化(6)`。→ 纯名称/纯字面匹配不足以路由。

> 与 Lead 独立复算一致：snippet 歧义 **132/357 = 37.0%**。

### 5.2 漂移实验（在内存里改副本，**不碰磁盘**；`02_anchors.py`）

| 编辑类型 | line_hint 偏移 | snippet 还能找到 |
|---|---|---|
| 锚点前插入 40 行 | 平均 **37–40 行**（每章 40.0/40） | **100%** |
| 锚点前删除 20 行 | 平均 **17.6–31 行** | **97.6–100%** |
| **改写锚点行本身**（在 snippet 中部插入「（改写）」） | — | **教材章 0–4.8%**；slides 16.7–52.8% |

**判断（我的判断，但实验是实测）**：
- **行号锚点对「别处插入/删除」100% 静默失效**——行号会整体漂移，而且不报错（Lead 独立测得「前插 50 行后静默钉错 67/357 = 18.8%」，方向一致，口径不同）。
- **snippet 锚点对行漂移免疫，但对「锚点自身被编辑」几乎必死**（教材章 0% 找回）。教材正文会被用户/agent 编辑（本轮会话就写了 8 次 `propose_write`、改了 3 个文件），所以这不是理论风险：**`线性 PCM 编码的误码性能分析` 的 `end.snippet="$$"` 已经是现场事故**。
- **架构含义**：不能只存行号（会静默错），也不能只存 snippet（会被编辑打断且 37% 本就不唯一）。**可行组合 = 唯一长 snippet + 章节号/id + 行号提示 + 打开前校验**：校验失败时按「章节号 → 全库唯一 snippet → 行号邻近」三级重定位，仍失败就报错（让失败可见），绝不静默钉错。
- 另一个现场证据（**比模拟更强：这是真实发生过的**）：
  - 会话 01:20:23 的第一次 `propose_write` 是「给刚学过的核心概念划高亮关键词」，作用在 `03 章:302` 的定义句上，`expect` 是「所谓模拟信号的量化，就是将抽样获得的…」，操作是 `replace_lines`；
  - 会话开始时的备份（`.memoria/agent/backups/session-…/origin/files/教材/03…md:302`）里这句原文还在；01:20 写入之后的所有备份里 **`所谓模拟信号的量化` 这句话已经消失**——高亮改写重写了这一行；
  - 也就是说：**产品自己的「划关键词」功能就会改写 snippet 锚定的那一行**，`snippet` 锚点当场失效（但 `line_hint` 仍指向旧的 302）；
  - 02:20 又在 `:293` 后插入学习笔记，把这句推到 `:344`，**行号也失效**。agent 随后补了 `bandpass-sampling` 的 range，但 `linear-pcm-error-performance` 的 end 没补 → range 反转。→ **写入/重建必须原子化地重算 range**（这是 R4 的验收条件，不是建议）。

## 7. ★ 对 R1 / R2 / R4 的直接建议（均基于本文实测）

### R1（索引单元）

1. **单元 = 教材小节级 KP，目标 800–2,000 字（≈350–850 tok），一章 25–40 个。** 依据：教材 KP 现状 p50 1,822 字（≈766 tok）但 p90 9,421（≈4k tok）——把 p90 以上的大节拆到子主题；slides 的 472 字粒度可直接沿用。
2. **不要复用现有 357 条当索引**：真实索引覆盖只有 4/14 章、61.8% 教材 token 无 KP、5.0% 非知识点、28.6% 同文件重名、11.2% OCR 脏名、1 条 range 反转。**索引必须重建（或至少对现有 sidecar 做一次清洗+补全）。**
3. **索引条目字段（最小集）**：`id`、`name`、`range{start,end}`、`description`（见 R2）、`tags`（沿用，实测 357 条里 28 条已有 tags 先例）、`chapter/section`（编号路径，用于消歧和 range 失效时重定位）。索引本身开销可忽略：357 条 names-only = 2,063 tok，加 description（每条 ≤40 字）预计 +3–5k tok，**全教材 400–500 条索引 ≈ 6–10k tok，占 1M 的 <1%**。
4. **必须允许「一条 KP 只覆盖局部」**：真实问题里 2 个只能靠行号（L499/L675）定位，说明索引需要一个 **`section_number` / `line-range` 的一级检索键**，否则用户引用 `#L499` 时无法路由。
5. **需要单元间的边**：46.7% 的内容问题要跨 KP 综合，3 个问题没有任何单一 KP 能回答（对比/设计理由/公式对比）。建议至少 `extend`（下一层）/`reference`（相关）/`compare`（易混）。真实先例：agent 在会话里自建了 20 条 `extend/reference` 边，格式已被产品接受（`edges[]`）。

### R2（description 模板）

**先决条件（实测）**：真实库 **0/1590 条 KP 有 `description`**——尽管 `kb-spec.zh-CN.md` §2 把 `description` 列为官方字段、写入 API 接受 `description`（`apply.py` 注释：`upsert_kp` 带 description 时再跟一条 `update_kp()`）、UI 有 `suggest_description`。本轮 agent 在 01:46 建 28 个 KP 时**明确传了 description**（如「本章开篇：模拟信号数字化的三步——抽样、量化、编码」），但落盘 sidecar 里 **0 条**。→ **R2 的第一条验收标准不是「怎么写」，而是「必须真正落盘且被索引/检索消费」**（成因我未验证，见 §8）。

**模板（≤40 字，三段式）**：

```
[讲什么] <主题 + 覆盖的子问题>；[结论] <1 条可判定的结论/公式>；[边界] <与相邻 KP 的区别/适用条件>
```

- 必含字段优先级（按 §3.3 实测频次）：**范围(3/9) > 边界(3/9) > 结论(1/9) > 前提(1/9) > 内容形态(1/9)**；**例子不是路由必需字段**（0/9）。
- 具体写法（用第 3 章真实 KP 举例，均为我据实测拟写）：
  - `非均匀量化`（现状 B）→「讲非均匀量化的动机(语音 30dB 动态范围)与最佳量化/压扩两种实现；结论：M≫1 时最佳量化退化为均匀量化；与均匀量化的区别是量化阶距随信号变化」。
  - `带宽利用率`（现状 B）→「讲比特带宽利用率 η_b=R_b/W 与符号带宽利用率 η_B=R_s/W 两套定义及单位；问『带宽利用率怎么算』时按比特/符号两种口径分别给公式」。
  - `连续时间信号的复频域表示`（现状 C）→「**内容形态=目录页**：只有 5 条提纲，无正文；应读其子 KP」。→ 说明**「内容形态」字段能直接消灭 10% 的 C 类错误**。
  - `性质3：展缩特性`（现状 C）→「**对象=单位冲激信号 δ(t)**：δ(at)=δ(t)/|a|；与 Fourier/Laplace 的展缩性质区别开」。
- **重名 KP 必须靠 description 或 id 区分**（28.6% 条目重名）：如 12 条 `连续时间Fourier变换的性质` 应写成「第 3 页：线性/时移…」或直接合并为 1 条 + 子范围。

### R4（锚点）

1. **锚点 = 唯一长 snippet（≥24 字，且全 KB 唯一）+ line_hint 仅作提示 + section_number 兜底。** 依据：现有 start snippet p50 只有 16 字 → 37% 不唯一；end snippet 15.3% 不唯一。
2. **禁止的 snippet**：`$$`、空行、纯编号（`3.3.19`）、纯图注、长度 <24 字、在全库出现 >1 次。依据：`linear-pcm-error-performance` 的 `end="$$"` 已造成 range 反转。
3. **打开前校验（必须机器化，不靠记忆）**：校验 hint 行附近 K 行内是否仍能匹配 snippet；失败→按 section_number → 全库唯一 snippet → hint 邻近三级重定位；仍失败→**报错而不是静默返回错误切片**。现场案例：`03 章:302` 的定义句被会话 01:20 的高亮写入改写后，原句 `所谓模拟信号的量化…` 在全文中消失（我比对 origin 备份确认），任何钉在这句上的 snippet 锚点会 **0% 找回**（教材章改写锚点行后 snippet 找回率实测 0–4.8%）。
4. **写入/重建时原子重算 range**：本轮会话里 agent 在 `:293` 插入 33 行后，自己的 KP 行号整体漂移，补了一条、漏了一条（反转）。→ **任何正文写入必须同事务重建所有受影响的 KP range**，否则「共享锚点」会在用户每次编辑后静默腐化。
5. **接受「锚点会失效」这个事实**：设计上把 range 当**可重建的派生数据**（从 `id + snippet` 或 `section_number` 重算），而不是唯一事实源；编辑器/预览/检索三处共用同一重定位函数（这是「共享锚点」能成立的前提）。
