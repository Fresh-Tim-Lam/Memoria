## 0. 结论（先给判定，对应 Lead 的三分支）

**判定：命中分支 1，并部分命中分支 3。**
1. **「按书序」降级为【冷启动兜底】，主策略改为【前沿优先】。** 【判断，依据下表】
   - S2（用到 ch5–7，【假设】）：A 书序 **0%**，B 前沿+前置 **56.3%**（B-frac 62.9%），C 随机 15.4%。

   - **三种场景 × 两种预算口径下，A 从未优于 B**（最多在 S1 打平）。
2. **真实 KB 复核（比假设硬）：** 【实测】用 4 个真实库的真实 `read_document` 章节分布当权重：
   - 现代操作系统：A **9.7%** / B 75.3% / B-frac 77.8% / D 80.8% / C 18.0%（top 使用章 = ch3）
   - 计算机网路：A **15.2%** / B 39.0% / B-frac 32.1% / D 45.5% / C 13.7%（top = ch5，位于全书 55.6% 处）
   - 软件工程概论：A 89.8% / B 89.8% / B-frac 90.3%（top = ch3，早期章 → 打平）
   - 数字通信原理：A 100% / B 100%（S1 同义反复）
   ⇒ **2/4 真实库 B 显著优于 A；2/4 打平；0/4 出现 A>B。**
3. **「20% 预算」这个前提部分不成立（分支 3 局部触发）：** 若要求 **100% 覆盖**，S1 需 9.1%、S3 需 19.6%、S2 需 **31.4%**；真实库全量覆盖用到章需 **2.5–3.1 倍** 20% 预算（现代操作系统 317,723 tok、计算机网路 372,140 tok）。⇒ **20% 只够"单章前沿"，不够"多章使用"；必须允许章内按节部分建造（B-frac）或提高预算。**

**对「什么叫按书序，我的知识库都是单书的」的回答**【判断】：
单书 KB 里「书序」= **章号顺序**（第 1 章→第 2 章→…），不是跨书优先级——它**可执行**（文件名/标题编号直接给），但只在「用户从第 1 章线性学到当前章」时有效。**单书并不使书序天然正确**：3 个有真实使用的 KB 里，top 使用章位于全书的 **23.1% / 55.6% / 20.0%**（章号/总章数）；计算机网路在第 5/9 章（55.6% 处），20% 预算下书序只建到第 1–3 章 → 覆盖 15.2%。所以「按书序」是一种**学习进度线性假设**，不是文档属性。

### 1.3 三场景与词义

**三点读法**：

### 4.2 可执行规则（建议写入设计）

```
每章计算 frontier_score(ch) =
      3 × review_card_count(ch)          # 最强、最直接（有则用）
    + 2 × session_read_count(ch)         # 最通用（无复习卡时靠它）
    + 1 × annotation_macro_count(ch)     # 补充；需过滤 agent 写入的高亮
frontier = argmax(frontier_score)
tie-break: 最近 mtime 优先
若所有分数为 0（冷启动/新库）: 回退【书序】（第 1 章起）

建造顺序 = frontier → frontier-1 → … → 1 → frontier+1 → …
           （前置链是理解前提；实测现代操作系统 B=75.3% vs B0=69.9% 的差来自前置章恰好也被用；
             网路 B=39.0% vs B0=0% 的差来自大章建不下时前置链顶上）
若 frontier 章成本 > 剩余预算: 允许【章内按节建】（B-frac），按 R10 的 section 顺序，
           不停建（网路 ch5 整章超预算时这是唯一可行路径）
```

**为什么用三信号加权而不是单一信号**：单信号各有失效场景（无复习卡 / 无会话 / agent 污染高亮 / mtime 噪声）；三信号在 4 个真实库上**没有互相矛盾**（复习卡与会话 top 章 2/2 一致、批注 1/1 一致；mtime 单独会错）。【判断】

**前端成本**：解析会话日志 + 读 cards.json + 扫 md 宏 = 一次全库扫描（秒级、零 LLM token），远低于建索引成本。⇒ 前沿信号本身不贵，**贵的是建造**。

## 5. Falsifier（什么结果会推翻"前沿优先"）

1. **若 ≥3 个真实库出现 A 覆盖 ≥ B 覆盖 +10pp** → "书序稳健"，前沿优先降级。**现状：0/4（A 最好也只是打平）。**
2. **若用户学习始终从第 1 章线性推进**（S1 那样），A 与 B 覆盖率打平（但 B 成本仍低 2 倍）；此时"前沿优先"的收益只剩成本，不改变覆盖 → 若产品对建造成本不敏感，A/B 差别可忽略。
3. **若前沿信号缺失率 >50%**（新用户、只有文件没有会话/复习/批注）→ 加权规则全 0，退化为冷启动书序；此时"前沿优先"不成立，必须有书序兜底（本报告已把书序降为兜底，而非删除）。
4. **若预算提到 40% 以上**：需要重跑（`BUDGET_FRAC=0.40`）。预判 S1/S2 差距缩小，但 S3 仍要 A 花 81.8% 才到 ch8 → **A 的失败不是预算太小，而是"顺序假定"与"使用位置"不匹配**；若实测高预算下 A≥B，则本结论需修正。
5. **若真实建造成本远高于"读一遍"**（如多轮校验 / 人工复核），所有策略绝对覆盖下降，但 A/B 相对序由顺序决定、不受成本规模影响 → 结论方向不变；若成本函数变成**非可加**（章之间共享缓存/合并），需重算。
6. **若"使用"不再集中**（例如学生同时学 5 章、或考试周随机跳章）→ frontier 信号会给出多峰；加权规则只取 argmax 会漏 ⇒ 需要 `top-k frontier`（k=2–3）而不是单点。**本数据不支持也不否定这一点**（4 个库 top1 占比 42–98%）。

## 7. 我不确定的点

1. **S2/S3 是假设场景**（Lead 指定），不是实测；真实使用分布只有 4 个库、且都集中在 1–2 章（top3 占 81–98%）。因此"多章使用"下的结论强度弱于"单章前沿"。
2. **成本模型假定建索引=读该章一遍+写条目**；若真实流程含抽取/校验/重试，绝对百分比会降，但 A/B 顺序结论由顺序决定，影响小。
3. **B-frac/D 的"章内按节等比例覆盖"是理想化**：真实章内各节价值不均（Phase 1 显示热点集中在少数节），因此 B-frac 是**下界**（真实可以更高，也可以因选错节更低）。
4. **复习卡只有 2/5 个库有**，且 `cards.json` 的 `file` 字段是否总是教材章路径未全量验证（我读了 2 个库的样例）。
5. **批注信号被 agent 污染**：数字通信 ch3 的 45 个高亮宏包含本轮 agent 写入的高亮，需用"人类写入"标识或时间窗口过滤（产品当前是否区分未验证）。
6. **20% 预算是外生假设**（来自 Lead 的讨论设定），不是产品约束；我报告了不同预算下的阈值，但没有"预算从哪来"的成本—收益分析（那是 R11 的活）。
7. **A 在 S1 的 100% 与 R13 原文一致**，我保留原实验的可复现性；但我把解释从"书序最优"改成"场景巧合+2 倍成本"——这是对原始结论的**归因修正**，不是数据修正。
