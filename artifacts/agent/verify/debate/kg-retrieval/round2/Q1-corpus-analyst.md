## ② 孤儿率（R2 falsifier，阈值 **20%**）

定义：切片与任何 KP **零重叠** = orphan_any；KP 覆盖不足切片字符 **50%** = orphan_lt50。
**"切片建在哪一层"决定孤儿率——这不是同一个数：**

| 视图范围 | A2（section 分区）orphan_any / <50% | B2（section+1200）orphan_any / <50% | 对 20% 阈值 |
|---|---|---|---|
| **只统计"含 KP 的 section"**（视图只给 KP 覆盖的正文建） | **0.0% / 1.9%**（414 片） | **0.0% / 2.6%**（868 片） | ✅ 通过（远低于 20%） |
| 统计"有 KP 的文件"（整文件建视图） | **31.5% / 32.8%**（604 片） | **35.7% / 37.4%**（1,349 片） | ❌ 超阈值 |
| 全库 26 md（整库建视图） | **61.3% / 62.1%**（1,070 片） | **66.9% / 67.8%**（2,623 片） | ❌ 大幅超阈值 |

**为什么差这么多**：全库 61.8% 的教材 token 没有 KP（10/14 章零 KP，见 Phase 1）。全库建视图时，那些"没有 KP 的 section"天然是孤儿——不是映射算法坏，是**索引覆盖没建到那里**。
⇒ 对 R2 的判定只有一句话：**视图必须建在「KP 已覆盖的 section」范围内，孤儿率 0–2.6%（通过）；若建在全库/整文件，孤儿率 32–68%（直接触发重设计）。** 全库覆盖率是另一个问题（Phase 1.5 的覆盖策略），不能拿它否定视图层。

## ③ 同名碰撞消歧后的剩余风险

现状（冻结快照）：**33 组 / 106 KP 同名（29.7%）**；
按名查询、随机落到某个实例的期望错配率：**全部组 68.9%**；**top-15 组 78.6%**（与旧口径 77.6% 同一量级，差异来自分组/加权定义）。

**递进消歧键：**

| 消歧键 | 仍碰撞的组 / KP | 占 357 KP | 说明 |
|---|---|---|---|
| 仅 name（现状） | 33 / 106 | 29.7% | 旧口径 32 组 102 条 = "name+file" 之后 |
| **+ file** | **32 / 102** | **28.6%** | 旧口径 32 组 102 条正是这一层 |
| + file + **起始行** | **7 / 14** | **3.9%** | 结构位置消歧掉 88 条 |
| + file + 起始行 + **context_hash** | **5 / 10** | **2.8%** | 残余 5 组/10 条 |

**残余 5 组/10 条是什么**：同一文件、同一行、且开头上下文 hash 相同 = **真正重复的条目**（例：`img/ch02-3` 里 `img-ch2-3-60-1-线性特性` 与 `img-ch2-3-61-1-线性特性` 都在第 1579 行、内容相同；另有 4 组同类）。它们不是"消歧问题"，是**应去重的重复 KP**。
⇒ 消歧后剩余风险：**内部可消歧到 2.8%（10 条 = 重复条目，去重后为 0）**；跨文件同名组仅 **3 组**（其余 30 组同文件），所以"用 file 上下文"就能消掉绝大多数。

## ④ anchor_verified 覆盖率（R1 falsifier，阈值 **50%**）

R1 三判据：`range_ok`（start/end 解析成功且 start≤end）、`snippet 唯一或可消歧`（hint 仍指向该 occurrence）、`end 不可靠时夹到下一同级标题`（夹紧算"已修复"，不算失败）。

| 人群 | n | **ANCHOR_VERIFIED（R1 口径）** | 严格（仅 snippet 唯一） | UNRESOLVED | AMBIGUOUS | 需夹 end |
|---|---|---|---|---|---|---|
| 全部 KP | 357 | **353 (98.9%)** | 226 (63.3%) | **0 (0.0%)** | **4 (1.1%)** | 74 (20.7%) |
| **教材 KP** | 71 | **71 (100.0%)** | 70 (98.6%) | **0** | **0** | 17 (23.9%) |
| slides KP | 285 | 281 (98.6%) | 155 (54.4%) | 0 | 4 (1.4%) | 57 (20.0%) |

- **对 50% 阈值：98.9%（全部）/ 100%（教材）—— 远超，R1 的 falsifier（>50% 变 UNRESOLVED/AMBIGUOUS）不触发。** 加 gate 不会"把索引停用"。
- 但 **end 需要夹紧的有 20.7%**（教材 23.9%）：这不是"坏到不能用"，而是 gate 必须真的实现「end 坏 → 夹到下一同级标题」这条修复；不做夹紧时这些 KP 的 end 就是坏的（与 Phase 1 的 end 漂移结论一致）。
- AMBIGUOUS 只剩 4 条（1.1%，全是 slides，snippet>1 且 hint 也已陈旧）；教材 0 条。
- 严格口径（只认 snippet 唯一）只有 63.3%，说明 "hint 消歧" 是 R1 gate 里真正承重的机制——如果产品不接受"用 hint 校验消歧"，覆盖率会从 98.9% 掉到 63.3%（仍 >50%，但余量小）。

### 与 D 方（metrics-baseline）`q1-probe.json` 的口径对照（防止再次"口径打架"）

| 口径 | 数字 | 含义 |
|---|---|---|
| D 方 `anchor_verified_upper_bound` | **204 / 357 = 57.14%** | 上界：`range_ok=True` 且 **start+end snippet 都全局唯一**；**不含** end 夹紧、不含 hint 消歧 |
| 我「严格」 | **226 / 357 = 63.3%** | 只要 **start snippet 唯一**（end 由 R1 夹紧兜底） |
| 我「R1 gate 口径」 | **353 / 357 = 98.9%** | start 唯一 **或 hint 仍指向该 occurrence**（读时校验）+ end 坏则夹到下一同级标题 |

⇒ 三个数**不矛盾**，是同一坐标轴上的三档：定义越宽松（允许端修复/消歧）越高。
**但对 R1 falsifier（>50% 变 UNRESOLVED/AMBIGUOUS）而言，三档全部 >50% ⇒ 结论不依赖口径：R1 falsifier 不触发。** D 方的"57.14% 是上界"与我的"98.9% 含修复"应同时保留在 DECISION-PACK 里，标注各自定义。

## 5. 这四组数字对 R7.1 拍板的直接含义（只陈述数字含义，方案留给 A 方）

1. **重切不是"改 id"，是"改单元数"**：KP 身份 357 不变；但单元从 357 → A1 346 / B1 637 / B2 2,623（全库）或 249（教材触达的唯一片）。用户可见变化 = 「一块变几片」，不是「一条变另一条」。
2. **教材是重切的主要对象**：教材 71 条里 **69.0% >1,200 字**，B1 下这些 KP 平均映射 **3 片（p90 12）**；slides 大部分 <1200 字，重切影响小（全库 p50=1）。
3. **孤儿率只有在"限定 KP 覆盖范围"时通过（0–2.6%）**；若视图层要做全库，孤儿率 32–68% ⇒ R2 的 falsifier 会被触发。**R7.1 的通过条件应写死"视图范围 = KP 已覆盖的 section"，否则这条要重设计。**
4. **R1 gate 不需要先重建锚点**（98.9%/100% verified）；但 gate 必须实现 end 夹紧（20.7% 需要），否则 353 条里约 74 条的 end 是坏的。
