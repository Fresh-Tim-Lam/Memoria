## 2. 三选项各自怎么验"没退化"

### 2.0 先定"退化"的可测定义（这是验收的前提）

**"退化"= 以下任一发生：**

```
D1  KP 数量骤减            |Δkp| > 5%                  （语义单元丢失）
D2  锚点变坏               fresh 比例下降 >2pp 或 反转/span=0 增加
D3  引用断裂               任何类别的孤儿率【上升】（相对 §1.4 基线）
D4  端点歧义变多           start/end 候选不唯一比例上升
D5  用户可感知位置变化     同一 kp_id 的 start_line 位移 > 阈值（需定）
```

**⚠️ D5 需要一个阈值——我给出推导方法而非拍数字（见 §3.2）。**

---

### 选项 ① 只重算 end 边界、不动 start

| 项 | 内容 |
|---|---|
| **能验的** | D2（锚点半）、D4（end 侧）、D1（KP 数不变，本就应该 0 变化）|
| **验不了的** | **D2 的 start 侧**（因为没动）、**D3 部分**（见下）|
| **关键风险** | **end 变了 ⇒ 若 slice 用 (start,end) 做身份，则所有切片的 identity 都会变** ⇒ 缓存全失效 |
| **可机检判据** | ① `fresh 比例` 不降（基线 98.60%）② `end 候选不唯一` 比例下降（基线 10.36%）③ KP 数 **必须完全不变**（=357）|
| **额外必查** | **kp_id 不变** ⇒ 图谱 357/357、链接 source 1/1 应保持 100% 可解析 |
| **验证成本** | 单次约 **2.5 秒**（实测本脚本总耗时）|

**⇒ 选项 ① 是**最容易验**的：KP 集合不变 ⇒ 引用完整性理论上零风险。**
**⇒ 唯一要盯的是 D3 里"end 变了但 start 没变"导致的**切片级缓存失效**（如果切片用 start+end 做 key）。**

---

### 选项 ② 全面重切并迁移 kp_id

| 项 | 内容 |
|---|---|
| **能验的** | 全部 D1–D5（但需要**额外的 id 映射表**才能验 D3）|
| **验不了的（没有映射表时）** | **D3 完全无法验** —— 若 kp_id 变了，旧的 FSRS/链接/图谱锚全部指向不存在的 id，看起来全是孤儿，但**分不清"真丢"还是"改名了"** |
| **⚠️ 我的硬要求** | **必须产出 `id_migration_map: {old_id → new_id}`，否则本选项不可验收** |
| **可机检判据** | ① `old_id` 经映射后**全部**能在新 KP 集找到（映射覆盖率 = 100%）② 映射后孤儿率**不高于**基线 ③ 一对多/多对一的情况**必须显式列出**并人工确认 |
| **额外必查** | 迁移后**重新跑一遍 §1.4**，得到"迁移后孤儿率"，与"迁移前孤儿率"对比 |
| **验证成本** | 单次约 2.5 秒 + 映射表生成（工作量在 arch-contract 侧）|

**⇒ 选项 ② 的**验收门槛最高**：没有映射表就**根本不能验收**。这是我要提的最强约束。**

---

### 选项 ③ 不动现有 KP，另建切片视图层

| 项 | 内容 |
|---|---|
| **能验的** | D1（KP 数必须 0 变化）、D3（引用完整性**理论上零风险**，因为 id 全不变）|
| **验不了的** | D2/D4/D5 里的"新切片质量" —— 因为新切片是新概念，没有基线可比 |
| **关键优势** | **对用户数据的风险最低**（kp_id 完全不动）⇒ **D3 自动通过** |
| **关键风险** | 变成"两套体系并存"：新切片和旧 KP 的**映射孤儿率**（草案给的阈值 20%）|
| **可机检判据** | ① KP 数 = 357 不变 ② **切片→kp 映射孤儿率 ≤ 20%**（R2 falsifier）③ 每个 kp 至少映射到 1 个切片（覆盖率 100%）|
| **验证成本** | 单次约 2.5 秒 + 切片构建时间（corpus-analyst 侧）|

**⇒ 选项 ③ 对**我的角度**是最省事的：D3 天然通过，只需要验新切片自己的映射质量。**

## 3. M4/M5 够不够？（Lead 直接问的）

### 3.1 结论：**不够，缺 3 样东西**

| 门禁 | 能验什么 | **验不了什么** |
|---|---|---|
| **M4 锚点健康** | `range_ok` / 反转 / span=0 / snippet 唯一 | **① 引用完整性（FSRS/链接/图谱）② 端点候选歧义 ③ "语义是否正确"** |
| **M5 陈旧** | 源变了但索引没更新（identity 差） | **重切导致的 id 变化**（那是"迁移"，不是"陈旧"）|

### 3.2 我要求新增的 M4b（引用完整性），以及**可执行的校验方法**

```
M4b 引用完整性（三个子项，全部可机检，无需 LLM）：

M4b-1 FSRS 卡可解析率
  判据： cards[].kp_id ∈ current_kp_ids
  命令： 读 <kb>/.memoria/agent/review/cards.json → 比对当前 KP 集
  本库： N/A（无 cards.json）｜AAA_Vocab：可跑（119,767 B）
  阈值： 孤儿率 = 0（严格）；重切后不得上升

M4b-2 链接可解析率
  判据： links[].source_id ∈ KP 集 且 links[].targets[] ⊆ KP 集
  命令： 读 sidecars/*.yaml 的 links[]
  本库基线： source 1/1 = 100%；target 2/3 = 66.67%（1 个既有孤儿）
  阈值： 重切后孤儿率不得高于基线

M4b-3 图谱节点可解析率
  判据： nodes[].kp_id ∈ KP 集
  命令： collect_graph_data(kb)['nodes']
  本库基线： 357/357 = 100%
  阈值： 重切后 = 100%（不得出现孤儿）
```

**⇒ 这三个都是**纯本地计算，2.5 秒内跑完，不需要 LLM，不需要新埋点**。**
**⇒ 换句话说：M4b **现在就能跑**，我已经跑出了基线。**

### 3.3 D5（位置位移）的阈值推导 —— 我不拍数字

**Lead 的纪律要求"不许把算术外推当测量"。所以这里我给**推导方法**而不是一个拍脑袋的阈值：**

```
方法：用"同文件内 KP 的平均长度"作为参照单位
  设 L = median(KP 的 end_line - start_line)，本库可实测
  判据：位移 ≤ 0.5 × L 视为"用户不可感知"（仍在同一知识点范围内）
       位移 > 2 × L 视为"用户可感知"（可能跳到别的知识点）

为什么用 L 而不是绝对行数：
  · 不同文件行密度差异大（教材 vs homework）
  · "位移相对于 KP 自身长度"才是用户体验的尺度

本库待测：L 尚未计算（见 unknowns U-Q1-2）
```

**⇒ 我明确标注：这个方法的阈值系数（0.5L / 2L）是**设计选择**，不是测量结果。真正校准需要用户研究。**
