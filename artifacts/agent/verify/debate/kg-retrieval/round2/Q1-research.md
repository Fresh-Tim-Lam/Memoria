## 0. 一句话结论（给人拍板）

**推荐：C（不动现有 KP，另建切片视图层）+ A1（只做最小 end 修复，作为 R1 前置）；否决 B（全面重切+迁 id；本轮证据下，非"永久"）；否决 A2（把 end 全部改成"下一同级标题"）；"不做"只能当对照基线，不能当选型。**

支撑推荐的成本事实（**以下数字只用于【成本/可行性观测】，不用于设计论证**；推荐依据见 §13.7 的代码事实）：

```
①【语】C 的映射孤儿率 = 0.0%（当前可上线范围 291 切片 / 51 KP；阈值 20%）
   —— 只在"切片只建有 KP 的 section、且只对覆盖达标的章上线"这个口径下成立；
      口径换成整章 41.4%、全库 71.8%（§6）；**仅语料观测，不作 R2 门禁通过证据**
②【语】anchor_verified 覆盖率 = 99.7%（section 档，clamp/A1 修复后投影）/ 63.3%（全文唯一）

③【码】选 C 用户数据改动 = 0；选 B 要换 357 个 kp_id、重映射 720–810 条映射边、
   42 个新单元被 2+ 旧 KP 认领（父子 KP 嵌套），且 B1 会产生 639–720 个新 id（§4/§5）

## 4. 三选项 + "不做" 的代价（① 迁移步骤 / 回滚 / 用户可感知 / 工作量）

> A 按 Lead 定义是"只重算 end、不动 start"。**但实测数据把它劈成两个含义不同的子方案**：
> A1 = 只修 74 条坏/歧义 end（止血）；A2 = 把**所有** end 都改成"下一同级标题"。
> 两者代价差一个量级，必须分开拍。

### 4.A1 只修坏 end（最小修复）

| 维度 | 内容 |
|---|---|
| **迁移步骤** | ① 对 74 条 `end_repair` 的 KP 重算 end（夹到下一同级标题），并**同事务重写 `end.snippet` + `line_hint`**（只改 hint 时 `resolve_range` 仍 ok=False）；② 同事务重算 range 并自检（R1 ④）；③ 不碰 start / kp_id / links |
| **失败回滚** | 每 KP 旧 end 快照（脚本生成）+ **显式走 backup/apply_plan 事务**（`snapshot_pre_images` @ `apply.py:619`、`restore_batch` @ `backup.py:529`）。⚠️ **普通 sidecar 写没有 txid**：只留单代 `.bak`（`document.py:285-298` → `atomic_yaml.py:15-40`），且 `restore_batch` 顺序写、非原子（`backup.py:642-643`）⇒ 迁移必须**先实现为事务写**，不能假设"整批撤销一个 txid" |
| **用户可感知变化** | 74 条 KP 的范围变（教材 17 / slides 57）；ids / 链接 / **图谱节点**不变；**副作用**：被修复的 KP 会变大（repaired p50 479 字，但 13 条 >3000 字，最大 18,335 字）；教材 KP >1200 字占比从 54.9% → **60.6%**；read_kp 单次中位从约 714–722 tok → 约 950 tok（教材，按标定 0.4247）；**v2 补**：图谱**边**会变（边由 range 几何派生，见 §13.5-6 / §13.6-C9；复核员复算 62→56，+8/−14） |
| **工作量估计** | **0.5–1 人日**（纯脚本，74 行；脚本化 + 验证 + 回滚演练） |
| **关键风险** | ⚠️ **R1 ③ 的"夹到下一同级标题"对 33.8% 非标题起点的教材 KP 定义不成立**，会把子题 KP 拉成父节长度：**2 条被放大 14–24×**——`ch2-10-white-noise` 667→**16,056 字**（24×）、`ch2-10-narrowband-random-process` 1,061→**15,387 字**（14.5×）；第 3 条 9,374→9,511（+1.5%）；其余 3 条 1,427/341/219。⇒ A1 必须附一条"非标题起点"规则，否则这 **2 条**会变成巨块（原稿"6 条"是错的，见 §13.5-5） |

### 4.A2 全部 end = "下一同级标题"（全量 end 语义化）

| 维度 | 内容 |
|---|---|
| **迁移步骤** | 357 条 KP 的 end 全部重算并写回（产品口径 **≥349/357 = 97.8% 会变**：end<边界 332 + 越界 17；脚本引擎另得 100%，属引擎伪影不作产品事实）；同事务重算 range |
| **失败回滚** | 需要**全量旧 end 快照**；可脚本恢复（ids 不变，比 B 简单） |
| **用户可感知变化** | **≥97.8%** KP 的范围变；教材 KP 中位 1,714 → **2,985 字（+74%，raw→heading）**；全部 KP 总字数 **+16.3%**（478,069→555,798；clamped→heading 的上限口径另计，不作用户可感值）；read_kp 单次中位 **716–722 → 约 1,268 tok**（0.4247）；图谱边 62→53（复核员复算，+21/−30） |
| **工作量估计** | **1.5–2.5 人日**（含"非标题起点"规则补丁与逐条复核） |
| **关键风险** | ⚠️ **这不是修复，是把 KP 改成"节"**：**否决首要依据 = 定义不成立**——对 33.8% 非标题起点 KP，"下一同级标题"不存在，套用会直接吃下整个父节（如"白噪声"→1.6 万字，§13.6-C4）；用户可感成本 = 多数 KP 变长、图谱边变化。**"69% >1200 字"只是语料观测，不作质量判据**（§13.4；长度判据为 `kg-ontology-v0.md:156` 所禁） |

### 4.B 全面重切 + 迁移 kp_id

B 也有两个子方案（数据差别大，分开报）：

| 维度 | B1（按每个现有 KP 重切） | B2（按文件结构重切） |
|---|---|---|
| **迁移步骤** | 357 个 KP 语义 span 各自切成 ≤1200 字段 → **639–720 个新 KP**；建 old_id→new_id 映射（1 对多：p50 **1** / p90 **4** / max **19**；24.6% 旧 KP 变 ≥2 个新 KP）；迁移 links/edges/cards；旧 id 墓碑表 | 按 section 结构重切整个索引范围 → **1,166 个新 KP**（+809）；其中 **483 个新单元没有旧 KP 对应**（=凭空新增知识点，不是"重切"）；**42 个新单元被 2+ 旧 KP 认领**（父子嵌套，必须人工裁决合并/保留） |
| **失败回滚** | 需 3 份快照（sidecar / links / cards）+ 映射表 + **写锁窗口（产品当前不存在，属新增工程，见 §13.5-7）**；窗口内新复习记录会丢 | 同 B1，且映射行数更多（810 条映射边） |
| **用户可感知变化** | **357 个 kp_id 全换**；外部引用（笔记/历史会话里的 id）全部失效；图谱节点重建；本库 3 links + 26 edges 重映射；跨库（另一路 probe，**本报告未复算**）probe 报 276 links / 22 cards 需迁；42 个"多父认领"单元会让用户看到"一个知识点被并进另一个" | 同 B1，且 483 个新 KP 会让用户的图谱/复习单元**凭空多出一大批** |
| **工作量估计** | **4–6 人日**（arch-contract 估 3–5，我把"嵌套/多父认领裁决"加进去） | **6–8 人日**（≈重建索引 + 迁移，不是"边界重算"） |
| **关键风险** | ① 92 对父子 KP 嵌套 ⇒ 重切会**重复切同一段正文**（639 个唯一 range vs 720 个 naive 单元，说明 81 个是重复）；② 不可逆（最大风险项） | ① 把"重建+扩容"包装成"重切"，成本被低估；② 42 个多父单元必须人工裁决，否则静默错位 |

### 4.C 不动现有 KP，另建切片视图层（与已裁 R2 一致）

| 维度 | 内容 |
|---|---|
| **迁移步骤** | ① 现有 KP（id + range **原样不动**）；② 新增切片视图（`slices[]`：file / section_number / char_range / identity / **source_hash** / kp_ids[] / description / anchor_verified）——放 sidecar 还是 `.memoria` 派生层待裁；③ 切片只建在**已建 KP 的 leaf section** 上；④ 建 anchor gate + description；⑤ 按章设"覆盖门禁"再决定该章是否进"先读索引"路径 |
| **失败回滚** | **删掉 `slices[]`/派生层即可，用户数据零改动、零损失**（唯一"无损回滚"的选项；前提=落位先定、走同一写事务，见 §13.5-7） |
| **用户可感知变化** | **0**（KP 图谱、复习、链接全部照旧）；agent 侧看到更细的切片（当前可上线范围 291 片 / 51 KP，每 KP p50 6 片；全索引范围 301 片 / 72 KP，p50 3.5 片）；新增 schema 字段属 R7.2，需人确认 |
| **工作量估计** | **2–3 人日**（切片层）+ **检索集成另计 1–2 人日（经验估算；结构只做检索前/候选过滤，不进 RRF，R3）** + 建索引时 description 生成（291 片 ≈ 0.19M input tok ≈ 一个 21 轮会话 prompt 的 3.4%，一次性）；**不含**未来按章扩容 |

## 8. 推荐与理由

### 8.1 推荐：**A1（止血）+ C（切片视图层）**；否决 A2 / B / 不做

1. **用户数据风险最小**：C 的改动是 0（ids/range/links/cards 全不动），回滚 = 删派生层（**前提：slices[] 落位先定；普通 sidecar 写无 txid，见 §13.5-7**）；A1 只改 74 条 end（**且必须同事务重写 end.snippet + line_hint，只改 hint 判据①仍拒，见 §13.5b-C2**）。B 要换 357 个 id、720–810 条映射、42 个人工裁决点，且回滚需要**新增**写锁/事务机制。
2. **锚点门禁的"可行性"只是语料观测**（§13.4）：现行产品口径 range_ok 352/357（98.6%），section/context 档 ≈98.3–99.7%（**not** 99.7% 当前值）；A1 修好 end 后这 74 条不再被判 AMBIGUOUS/UNRESOLVED。**这是成本/可行性判断，不是设计依据**；是否"先重建锚点"是人/工程的决策。
3. **C 的依据 = 代码身份耦合 + 可逆性（经验判断），不是"更小单元被证明更好"**（v3 撤回"三源支撑"，见 §13.10-①）：
   - **【码】** 身份 kp_id 已被 4 类消费者绑定（卡/图/会话 anchor/链接），且切片层可删可回滚 ⇒ 改视图层比换身份风险低；
   - **【经验判断】** 291–301 片、每 KP p50 3.5–6 片是**成本/规模观测**，不是"更小更优"的证据；
   - **论文不支撑此主张**：E08 的自变量是**检索返回的 chunk 数 k**（不是索引单元大小），只能支撑"检索预算要有界"（本表 #4）；E09 只证明"语义切分不必"，**未测 heading 结构**；LlamaIndex SentenceWindow 是"小匹配/大阅读"，**与 C"读更小切片"方向相反**，不能当支撑。
   ⇒ **C 的收益必须由 Q3/U3 的 A/B 判定（U3），本材料只主张"低风险、可逆、不动身份"，不主张"已证更优"。**
4. **孤儿门禁可过，但必须带 scope/口径**：按章口径下 ch02 5.7%、ch03 4.3%、notes/平滑 0%；ch01/ch08 不达标就不上先读路径。**v2：这是测量设计建议（经验判断），且改写了 R2 的契约语义，须人裁（§13.8）**。
5. **B 不是"边界重算"，是"换身份 + 扩容"**：B2 会凭空多出 483 个 KP；B1 有 81 个重复 range（父子嵌套）；且 92 对父子嵌套没有裁决规则。花 4–8 人日做不可逆迁移，收益只是"id 更整齐"。**v2 措辞**：本轮证据下**否决** B（依据=代码消费者迁移成本 + 无原子回滚/写锁，见 §13.7），不是"数学上永久不可能"——若将来出现硬理由可重开（§8.2 末）。
