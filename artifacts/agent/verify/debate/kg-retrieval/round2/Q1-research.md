## 0. 一句话结论（给人拍板）

**推荐：C（不动现有 KP，另建切片视图层）+ A1（只做最小 end 修复，作为 R1 前置）；永久否决 B（全面重切+迁 id）；否决 A2（把 end 全部改成"下一同级标题"）；"不做"只能当对照基线，不能当选型。**

支撑它的是三个数（全部我自己算、可复跑）：

```
① C 的映射孤儿率 = 0.0%（当前可上线范围 291 切片 / 51 KP；阈值 20%）
   —— 但只在"切片只建有 KP 的 section、且只对覆盖达标的章上线"这个口径下成立；
      口径换成整章 41.4%、全库 71.8%（§6，口径必须由 Lead 钉死）
② anchor_verified 覆盖率 = 99.7%（R1 原文口径：section 内可消歧）/ 63.3%（收紧到"全文唯一"）
   —— 阈值 50%，两种口径都过；教材 98.6%，不用先重建锚点（§7）
③ 选 C 用户数据改动 = 0；选 B 要换 357 个 kp_id、重映射 720–810 条映射边、
   42 个新单元被 2+ 旧 KP 认领（父子 KP 嵌套），且 B1 会产生 639–720 个新 id（§4/§5）
```

**代价排序（含不可逆风险）：C < A1 < A2 < B1 < B2；"不做"看似 0，实际要背 74 条坏 end（20.7%）+ 粒度问题（教材 KP 中位 1,714 字）不解决。**

## 4. 三选项 + "不做" 的代价（① 迁移步骤 / 回滚 / 用户可感知 / 工作量）

> A 按 Lead 定义是"只重算 end、不动 start"。**但实测数据把它劈成两个含义不同的子方案**：
> A1 = 只修 74 条坏/歧义 end（止血）；A2 = 把**所有** end 都改成"下一同级标题"。
> 两者代价差一个量级，必须分开拍。

### 4.A1 只修坏 end（最小修复）

| 维度 | 内容 |
|---|---|
| **迁移步骤** | ① 对 74 条 `end_repair` 的 KP 重算 end（夹到下一同级标题）；② 同事务重算 range 并自检（R1 ④）；③ 不碰 start / kp_id / links |
| **失败回滚** | 每 KP 旧 end 快照 + 现有 `.memoria/backups/**` 事务：**整批撤销一个 txid**，回滚成本最低 |
| **用户可感知变化** | 74 条 KP 的范围变（教材 17 / slides 57）；ids / 链接 / 图谱节点不变；**副作用**：被修复的 KP 会变大（repaired p50 479 字，但 13 条 >3000 字，最大 18,335 字）；教材 KP >1200 字占比从 54.9% → **60.6%**；read_kp 单次中位从约 726 tok → 约 954 tok（教材，按 0.4237 tok/字） |
| **工作量估计** | **0.5–1 人日**（纯脚本，74 行；脚本化 + 验证 + 回滚演练） |
| **关键风险** | ⚠️ **R1 ③ 的"夹到下一同级标题"对 33.8% 非标题起点的教材 KP 定义不成立**，会把子题 KP 拉成父节长度：实测 3 条病态——`ch2-10-white-noise` 667→**16,056 字**（24×）、`ch2-10-narrowband-random-process` 1,061→**15,387 字**（14.5×）、`ch2-10-cosine-plus-narrowband-gaussian` 9,374→9,511。⇒ A1 必须附一条"非标题起点"规则，否则 6 条 KP 会变成巨块 |

### 4.A2 全部 end = "下一同级标题"（全量 end 语义化）

| 维度 | 内容 |
|---|---|
| **迁移步骤** | 357 条 KP 的 end 全部重算并写回（**336/357 = 94.1% 会变**）；同事务重算 range |
| **失败回滚** | 需要**全量旧 end 快照**；可脚本恢复（ids 不变，比 B 简单） |
| **用户可感知变化** | 94% KP 的范围变；教材 KP 中位 1,714 → **2,985 字（+74%）**，全部 KP 总字数 461,578 → 555,798（**+20.4%**）；read_kp 单次中位 726 → 约 1,265 tok；图谱覆盖范围整体变大 |
| **工作量估计** | **1.5–2.5 人日**（含"非标题起点"规则补丁与逐条复核） |
| **关键风险** | ⚠️ **这不是修复，是把 KP 改成"节"**：对 66.2% 标题起点的 KP 尚可；对 33.8% 非标题起点 KP 会直接吃下整个父节（如"白噪声"→ 1.6 万字）。且**粒度问题更严重了**（>1200 字从 54.9% → 69.0%），与 R2"切片更细"的目标相反 |

### 4.B 全面重切 + 迁移 kp_id

B 也有两个子方案（数据差别大，分开报）：

| 维度 | B1（按每个现有 KP 重切） | B2（按文件结构重切） |
|---|---|---|
| **迁移步骤** | 357 个 KP 语义 span 各自切成 ≤1200 字段 → **639–720 个新 KP**；建 old_id→new_id 映射（1 对多：p50 **1** / p90 **4** / max **19**；24.6% 旧 KP 变 ≥2 个新 KP）；迁移 links/edges/cards；旧 id 墓碑表 | 按 section 结构重切整个索引范围 → **1,166 个新 KP**（+809）；其中 **483 个新单元没有旧 KP 对应**（=凭空新增知识点，不是"重切"）；**42 个新单元被 2+ 旧 KP 认领**（父子嵌套，必须人工裁决合并/保留） |
| **失败回滚** | 需 3 份快照（sidecar / links / cards）+ 映射表 + **写锁窗口**（迁移期间禁写）；窗口内新复习记录会丢 | 同 B1，且映射行数更多（810 条映射边） |
| **用户可感知变化** | **357 个 kp_id 全换**；外部引用（笔记/历史会话里的 id）全部失效；图谱节点重建；本库 3 links + 26 edges 重映射，跨库（另一路 probe）276 links / 22 cards 要迁；42 个"多父认领"单元会让用户看到"一个知识点被并进另一个" | 同 B1，且 483 个新 KP 会让用户的图谱/复习单元**凭空多出一大批** |
| **工作量估计** | **4–6 人日**（arch-contract 估 3–5，我把"嵌套/多父认领裁决"加进去） | **6–8 人日**（≈重建索引 + 迁移，不是"边界重算"） |
| **关键风险** | ① 92 对父子 KP 嵌套 ⇒ 重切会**重复切同一段正文**（639 个唯一 range vs 720 个 naive 单元，说明 81 个是重复）；② 不可逆（最大风险项） | ① 把"重建+扩容"包装成"重切"，成本被低估；② 42 个多父单元必须人工裁决，否则静默错位 |

### 4.C 不动现有 KP，另建切片视图层（与已裁 R2 一致）

| 维度 | 内容 |
|---|---|
| **迁移步骤** | ① 现有 KP（id + range **原样不动**）；② 新增切片视图（`slices[]`：file / section_number / char_range / kp_ids[] / identity / description / anchor_verified）——放 sidecar 还是 `.memoria` 派生层待裁；③ 切片只建在**已建 KP 的 leaf section** 上；④ 建 anchor gate + description；⑤ 按章设"覆盖门禁"再决定该章是否进"先读索引"路径 |
| **失败回滚** | **删掉 `slices[]`/派生层即可，用户数据零改动、零损失**（唯一"无损回滚"的选项） |
| **用户可感知变化** | **0**（KP 图谱、复习、链接全部照旧）；agent 侧看到更细的切片（当前可上线范围 291 片 / 51 KP，每 KP p50 6 片；全索引范围 301 片 / 72 KP，p50 3.5 片）；新增 schema 字段属 R7.2，需人确认 |
| **工作量估计** | **2–3 人日** + 建索引时 description 生成（291 片 ≈ 0.19M input tok ≈ 一个 21 轮会话 prompt 的 3.4%，一次性）；**不含**未来按章扩容 |
| **关键风险** | ① 双轨长期并存（KP 边界 vs slice 边界不一致）；② 孤儿门禁**口径不钉死就不可执行**（同方案 0%/0.7%/41.4%/71.8%）；③ 依赖"section 内可消歧"的 heading path，当前 sidecar **没有存 section_number**，实现时必须新增（见 §10） |

### 4.D 不做（对照）

| 维度 | 内容 |
|---|---|
| **迁移步骤** | 无；**回滚**：N/A |
| **用户可感知变化** | 0 |
| **工作量估计** | 0 |
| **真实代价** | ① 74 条坏/歧义 end 留着（20.7%），其中 5 条 range 已坏（98.6% 可用）；② R1 的 anchor gate 一旦上线，这 74 条只能"不露 id"——R1 的 P0 目标（露 id 前先修锚点）无法达成；③ 粒度问题原样保留：教材 KP 中位 1,714 字 ≈ 726 tok/次 `read_kp`，69% >1200 字；④ R2 的切片视图不存在 ⇒ R6 的"少往返"价值主张无法验证（0.5.x 立项前提悬空）；⑤ 现场事故链已证明 `read_kp` 连 range_ok 都不检查、坏 range 会**静默返回第 1 行内容**（R1 证据，非本报告实测） ⇒ "不做"不是零风险，是把风险留在线上 |

### 5.1 主表

| 方案 | 单元定义 | 单元/切片数 | KP 数变化 | 每 KP 映射片数 p50 / p90 / max | 备注 |
|---|---|---|---|---|---|

| **A2** 全 end 语义化 | KP（end 全改） | **357** | **0** | 1 / 1 / 1 | 94.1% range 变；教材中位 +74% 字 |
| **B1** 按 KP 重切+迁 id | 新 KP 单元 | **639–720**（唯一 range 639 / 不合并 720） | **+282 ~ +363** | **1 / 4 / 19** | 24.6% 旧 KP → ≥2 新 KP；81 个重复 range（父子嵌套） |

| **C** 切片视图（当前全部已建 KP 范围） | slice（+ch01） | **301 片** | **0** | **3.5 / 13.9 / 34** | 72 个 KP；0% 孤儿 |
| **C** 切片视图（含 slides，若纳入） | slice（9 个有 KP 的文件） | **688 片** | **0** | **1 / 5 / 34** | 357 KP；孤儿 0.7%；但 slides 按 C9 不应进"先读索引"路径 |

**切片数对预算的敏感性（同一范围 core+prose）**：800 字 → 451 片；**1200 字 → 301 片**；2000 字 → 201 片。
⇒ 绝对值取决于切分规则（须实现前冻结）；"数百片"的量级稳定，且 C 的片数 ≈ 原 KP 数的 4–6 倍（教材正文），符合"一个 KP 被拆成几片"的预期。

> **映射覆盖率的口径**：C 各行里"每 KP 映射片数"只对**该 scope 内的 KP** 统计（51 / 72 / 357）。
> 对 scope 内 KP：**每个 KP 至少映射 1 片（zero-slice = 0，覆盖率 100%）**；
> 被排除在外的 KP（教材/08 的 `test` 节点；若 slides 不纳入则是 285 个 slide KP）属于"未上线 scope"，不计入 C 的映射分子/分母。
> 若把 slides 纳入（688 片行），357 个 KP 全部有片、0 个 zero-slice。

### 5.2 这组数字推翻/修正了什么

- **修正"KP=标题切分"的适用范围**：对 slides 成立（100%），对教材只有 66.2%。所以"只修 end"无法修到 33.8% 的教材子题 KP（它们的 start 不是标题，end 语义无定义）。
- **修正"重切后 KP 数不变"的直觉**：B1 实测 +282~+363、B2 +809；**"全面重切"必然改 KP 数，因此必然改身份基数**。
- **复现 69.0%**：heading 口径下教材 >1200 字 = 69.0%（49/71），与 corpus-analyst 的 Phase 3 数字一致；resolved 口径是 54.9%。两者不矛盾，是口径差。

## 6. 孤儿率（阈值 20%）：结论完全取决于 scope

### 6.1 多 scope 对照

## 8. 推荐与理由

### 8.1 推荐：**A1（止血）+ C（切片视图层）**；否决 A2 / B / 不做

1. **用户数据风险最小**：C 的改动是 0（ids/range/links/cards 全不动），回滚 = 删派生层；A1 只改 74 条 end、有事务回滚。B 要换 357 个 id、810 条映射、42 个人工裁决点，且回滚需要写锁窗口。
2. **锚点门禁能过，不需要先重建**：99.7%（section 口径）/63.3%（strict 口径）都 >50%；教材 98.6%。A1 修完 74 条 end 后，R1 gate 可以正常上线（否则这 74 条只能被 gate 判 AMBIGUOUS/UNRESOLVED）。
3. **粒度确实被解决，且有数**：教材正文 51–72 个 KP → 291–301 个切片，每个 KP 映射 p50 3.5–6 片；切片 p50 1,006 字 ≈ 426 tok（对比现有 `read_kp` 单次 726 tok 中位）。
4. **孤儿门禁可过，但必须带 scope/口径**：按章口径下 ch02 5.7%、ch03 4.3%、notes/平滑 0%；ch01/ch08 不达标就不上先读路径。这比"全库 71.8% 不可行"更符合 R6 的 lazy 深化路线。
5. **B 不是"边界重算"，是"换身份 + 扩容"**：B2 会凭空多出 483 个 KP；B1 有 81 个重复 range（父子嵌套）；且 92 对父子嵌套没有裁决规则。花 4–8 人日做不可逆迁移，收益只是"id 更整齐"——不解决任何 C 解决不了的问题。
