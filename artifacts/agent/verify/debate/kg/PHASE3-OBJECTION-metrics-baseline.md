## 3. 【自我修正】M-05 的 15% 阈值 —— 我撤回

**按协议 E1（每条证据必须有身份），我无法为"15%"提供任何来源。**

```
  阈值：**无**（首版只建基线）
  判定方式：建立基线后，**下一版本对比自身基线**（趋势 > 绝对值）

  撤回条件：若 Lead 认为"无阈值=空指标"，则我改为「M-05 降级为 data-collection-only，
            不进验收表」，这同样是合法状态
```

### 3.3 M-12（最大分组占比）为什么我还保留 —— 我的原话被误读了

**Lead 问**：「你自己说它是自欺指标，为什么还保留？」

**但 Lead 的解读比我更严，我接受更严的版本：**

```

  用途：**negative gate only**（只用于判"没修好"）
  规则：若 ≥90% ⇒ 判定"分组失效"，阻断发布
        若 <40% ⇒ **不构成任何通过理由**（不写进验收，不写进 release note 的"已修复"）
```

**⇒ 若 Lead 要求彻底删除 M-12，我接受；但我认为"只作 negative gate"是有价值的。**

## 5. 【打 C】token 省了是否等于"更有用"？

**Lead 问**：「省了 token 但答案质量不变算有用吗？M-04/M-05 要的是导航命中率/利用率，C 给的是 token 量 —— 两者能互替吗？」

### 5.1 我的答案：**不能互替。它们测的是两个正交维度。**

| 维度 | 测什么 | C 的 488× 属于哪个 |
|---|---|---|
| **成本（cost）** | 完成同一动作花多少 token | ✅ **C 的 488×** |
| **效果（effect）** | 动作的结果是否更好 | ❌ C 未测 |
| **使用（usage）** | 这个能力被用了吗 | ❌ C 未测（且当前无埋点） |

**⇒ "省 token 488×"是一个**成本改进**，不是一个**价值证明**。**

```bash
import os, re, itertools
```
