## 3. Q3 度数数据归属

**[A]** 度数应提升为 `node.degree`（O(E) 一次，引擎层）
```
现状：2D/3D 各算一份，且缓存键 = links.length
⇒ 边集变了但条数不变时【缓存陈旧】（graph-view-2d.js#L544-L545）—— 隐患
```
**[D]** 同一个建议，但给了契约判据（见 §1）并指出层级：
```
数据层：node.degree
映射层（设置项）：sizeMode: uniform|degree、sizeRange、sizeScale: linear|sqrt|log
渲染层：nodeRadius: 6 常量、3D 的 *0.85
```
**[D] 反对"只做线性映射"的理由（契约可表达性问题）**：
```
只做"大小=度数"的线性映射 ⇒ 实际不可用（长尾让多数节点不可见）
⇒ 映射层必须支持 sizeScale: linear|sqrt|log
⇒ 这是"契约是否可表达"的问题，不是调参问题
```
### 并集结论
```
✅ 三根共识（A、D + C 的隐含支持）：degree 提升为 node.degree，避免前端重算与弱缓存键
✅ [D] 的三层分层（数据/映射/渲染）无人反对
🔴 待裁（V3）：sizeScale 是【v0 必须有】还是【v1】？（D 说是契约可表达性问题，A 用 5 档分位绕开了它）
```

## 4. Q4 3D 特有视觉问题

**[A] 有实测，是本场最硬的一条**：
```
3D 当前成本是 draw calls：真实 133 节点/404 边 = 634 calls / 407 geometries / 116 textures / _render 0.86ms
3D 不需要拆共享几何体：galaxy 分支已是"共享 SphereGeometry + mesh.scale"⇒ 逐节点半径 0 额外几何/0 draw
3D 大小与透视混淆【有实测】：相机到节点距离 1375–2447，同 world 半径屏幕尺寸比 1.78×
  ⇒ "大是因为重要还是因为近"【无法区分】
  ⇒ v0 建议：2D 启用大小、3D 保持等大（度数用颜色）
  ⇒ 若 3D 必须做，需屏幕空间归一（scale∝距离）或雾/描边冗余，否则语义不可解释
```
**[B] 同向但更宽容**：
```
3D 只探索；透视会混淆"大=重要/近"
⇒ 3D size 动态范围收紧 1.0–1.25 + 深度雾/透明度 + 数值 legend
⇒ 决策类任务一律 2D（与 KG 本体辩论 Q6 同结论）
```
**[D]** 提了契约问题：3D 与 2D 共享同一份 nodes/edges；若引入逐节点尺寸，3D 需要拆共享几何体 ⇒ **这是渲染契约变化** ⇒ 尺寸应作为渲染层属性而非数据层属性。

### 并集结论
```
✅ 三根共识（A、B、D）：3D 不承载"大小=重要性"的语义（透视混淆），或用强烈冗余手段
🔴 待裁（V4）：3D 是【保持等大 + 度数用颜色】（A）还是【收紧动态范围 1.0–1.25 + 雾 + legend】（B）还是【v0 不做 3D 大小】（D 的隐含）？
```

## 5. Q5 布局本身

**[B] 指出两个比"节点大小"更严重的问题**：
```
① 布局稳定性是硬伤：
   每次 setGraph 随机初始位置 + alpha=1（graph-layout-2d.js#L37-L51, L244-L246）
   ⇒ 每次打开图都大跳 ⇒ 人无法建立空间记忆
   建议：按 KB path + graph hash 持久化位置 + 只有"重新布局"按钮触发全局 reheat
        + 新节点从 anchor 生长 300ms
② 标签问题比节点大小更严重：
   133 个标签【无条件全画】、固定 10px、【无避让】
   （graph-view-2d.js#L98-L114, L660；graph-label.js 仅 2.2KB 做截断）
   建议 LOD（默认 top20% / zoom 分级）+ 贪心避让 + 毛球提示
```
**[A] 从成本侧独立验证了②**：
```
2D 逐节点半径成本 ≈0（r=4/6/9/12 均 0.56–0.65ms；合成 3000 节点 uniform 1.70 vs varied 1.65ms）
但 2D 真正瓶颈是【每节点标签】：3000 节点 6.70 vs 1.70ms（标签占 ~75%；1500 节点 2.91 vs 0.80）
⇒ 【上大小编码前必须先做标签裁剪】
```
**[D]** 力导向参数存在哪（设置项 vs 常量）未定；毛球态判定他判**零新增字段**（是 `node.group` 的函数），但前端分组无后端字段。

### 并集结论
```
✅ 两根独立（B 从用户体验、A 从绘制成本）指向同一结论：
   【标签是比节点大小更严重的问题，且是大小编码的前置】
🔴 待裁（V5）：标签裁剪是不是 v0 节点大小的【前置依赖】？（A 说必须先做；B 说更严重；C/D 未表态）
🔴 待裁（V6）：布局稳定性（位置持久化）是否进 v0？（B 说是硬伤，A/C/D 未纳入范围）
```
