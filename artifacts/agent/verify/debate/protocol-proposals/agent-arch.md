## 1. 我可能怎样被不公平对待（3 条）

我在本协议中是**提案者**，且我负责的是本轮最重、最难自证的一块（DSH 能力面全量清点 + MCP 工具面 + 扩展点 + 写侧安全 + trace）。这决定了我面临的三种不对称。

### 1.1 举证成本不对称：我只用一个反例就可以被否决，却要被要求证明"全量正确"

- **我的处境**：我的断言形态是"能力面有 N 类、共 M 个点，逐条有 file:line"。
  这种断言的失败模式是**存在一个反例**；而它的成立需要**整批正确**。
  评审者只需找到 1 个反例（例如"Cordis 插件运行时你漏了"、"pin 过期后 skill-filesystem 改了 3 次你没算"），
  就能合理地说"你的清点不可靠"，而我需要重做整批才能自证 —— 一次辩论回合里这不可能完成。
- **具体危险形态**：
  - 用**单个未决点**否定**已决的其余部分**："你连 Cordis 都没说清 ⇒ 全量移植方案不成立"，而不接受"已决 9 条 + 明确标注 1 条 unknown 分期处理"这种答案。
  - **要求缺席证明**："你要全量移植，就得证明你没有漏"—— 在有限时间内这是不可能的，因此这是一种**结构性必败**的提问方式。
  - 反例的**效力不对等**：我可以给出 30 条 `path:line`，反例只需 1 句"我觉得这样太复杂了"。
- **若不受保护，受损的是**：我（劳动无出口），以及**人**（他得到的不是"哪个方案更好"，而是"所有方案都被否"，等于这一轮白做）。

### 1.2 我的独有证据被"一人一票"摊平，同时又被"二次引用"重复计数（两个方向相反的错误都针对我）

- **我的处境**：全仓大概只有我会去读 DSH 源码并把结论落到 `file:line + pin`。这条证据**只有一份**。
- **危险形态 A（稀释）**：裁决按"人头/意见数"计，我的 30 条 `file:line` 与别人 1 句"人说过要省 token，别再加东西"等票。
- **危险形态 B（重复计数）**：别人把我的证据复述进自己的方案，合议时被记成"3 方支持"——
  实际证据根只有 1 个，这就是人担心的**同源伪多数**。
  注意这两个错误方向相反（一个压我，一个"抬高"我），但**同一个原因**：没有"证据根/独立性"的概念。
- **若不受保护，受损的是**：我（唯一证据被票数压掉），以及**决策者**（把 1 份证据误当多份，冻结了没有被真正检验过的前提）。

### 1.3 诚实披露被当缺陷（这条最危险，因为它惩罚的是"说我不知道"）

- **我的处境**：我这个域**必然**有一批"不确定/不做"：
  Cordis 与 Memoria"能力插件"同名不同物；pin 2026-09-15 之后有 5 处上游变更未纳入；
  新增的 skill-office / tool-workspace-dependencies 两个包未移植。
  按人明确的转向（全量移植 + 可扩展 + 自任 MCP server + 省 token），**这些是必须写进方案正文的**。
- **危险形态**：裁决把"写了 unknown"记为"分析不完整/方案不成熟"，把"没写 unknown"记为"设计清晰"。
  于是**理性策略是隐藏不确定性** —— 而人会因此拿到一份"看起来无懈可击"的方案。
  这正好命中人担心的第 2 种失败（**共享假设伪独立**）：没人提出"这里可能是错的"，于是它表现为"共识"，而不是"分歧"。
- **若不受保护，受损的主要不是我是人**：我最多被判负一次；他得到的是一个**不会自我报警的设计**，
  而且在下一个阶段（真的动手移植）才发现，成本高一个数量级。

## 2. 协议必须保证的规则（5 条，每条写"若违反，谁受损"）

> 每条规则都给**可校验信号**（写进合议记录的字段/状态），理由是：本仓已确认"写在文档里靠记住的规范，遵守率等于随机数"，
> 只有让违规**在产物上可见**才稳定生效。

### R1 对称举证义务：任何"否决"必须同时给出 ① 证据、② 最小修补或替代方案的入口

- **规则**：一条否决（vote=reject）必须包含两项，缺一不得成立：
  - `objection.evidence`：具体证据（见 §4 分级），不能是"感觉/太复杂/人不会同意"；
  - `objection.repair_or_alternative`：要么给出能救活该方案的**最小修补路径**，要么写出替代方案的**入口**（可以只是一句"应改为 X 方向，细节由提案者补"）；
    若确实想不出，必须**明确写"我未尝试给出替代"**，此时该否决降级为 `question`（提问，不计否决票）。
- **对称性**：这条规则同样约束我 —— **我否决别人时也必须给替代或降级为提问**。
- **若违反，受损的是**：提案者（劳动被否定且无出口，下一轮只会写"更不容易被挑错"的空方案）；
  以及裁决者（他拿到的是一长串"都不成立"，而不是"选哪个"，无法做决定）。

### R2 证据按"独立来源根"计票，而不是按人头计票

- **规则**：
  - 合议表每票必须带 `evidence_root_id`（同一 `path:line + pin`、同一份测量产物、同一份被引文档 = 同一 root）。
  - 同一 root 的多票**合并为 1 票**，并在记录里保留"被合并"的事实（不丢信息，只是不重复计数）。
  - 引用他人提案/文档里的结论时，必须标 `derived_from=<id>`；`derived_from` 链最终指向同一 root 的，**不得作为独立支持**。
  - 裁决书里出现"多数/一致"字样时，必须附 `independent_roots > 1` 的证明，否则该措辞无效。
- **若违反，受损的是**：持有唯一证据的一方（我，或任何少数派 —— 这正是人担心的**票决压少数**）；
  以及决策者（**同源伪多数**让他以为结论被多方独立验证过）。

### R3 共享假设必须先显式化，并逐条指派"谁负责检验它"

- **规则**：
  - 每份方案（含我的）必须列出 `assumptions[]`：**我的论证在什么前提下成立**。
  - 合并/裁决阶段必须产出 `shared_assumptions[]`：多份方案共同默认、但谁都没检验的前提，**单列**。
  - 每条 shared assumption 必须被指派一个检验者与检验方式（可以是"读 X 即可证伪"）；
    未指派或检验结论为"未检验"的，**不得作为通过或否决的依据**，且冻结产物必须保留这条未决状态。
  - 任何"共识/一致"结论，必须能逐条回指"它依赖哪个 assumption、该 assumption 检验结果如何"。
- **若违反，受损的是**：全队 + 人。理由：**共享假设伪独立是最隐蔽的失败** ——
  三份方案都默认"移植 = 照抄上游"，于是没人发现"Memoria 的运行时/宿主语义与 DSH 不同"，
  它在记录里表现为"共识"，而不是"分歧"，事后才炸。

### R4 裁决必须逐条对照证据，且少数意见原样进入冻结产物

- **规则**：
  - 裁决书必须逐条给出 `claim → 采纳/驳回 → 依据的 evidence id → 理由`；"整体上不同意"不是裁决。
  - 被驳回方对每条驳回有**一次性再回应权**；再回应后不得再引入新要求（见 §3.2）。
  - `dissent-register`：被驳回的证据与理由**不从冻结产物中删除**，标 `dissent` 保留（含"为什么被驳"）。
  - 缺 `ruling-log` 或 `dissent-register` 任一项，产物**不得标记 frozen**。
- **若违反，受损的是**：未来的维护者与决策者（无法回溯"为什么这样定"；当那条被压掉的证据后来被证实，
  没有任何记录显示曾经有人提过 —— 这正是**票决压少数**的长期代价）；当然也损伤少数派本人。

### R5 预算与时序对称；"不做什么/不确定什么"是合法交付物，不计缺陷

- **规则**：
  - **等预算**：每方在每轮获得相等的轮次与字数/token 上限（上限可低，但必须相等且事先公布）。
  - **不判负**：在公布的响应窗口内未回应，**不得**被记为"默认同意/弃权/未参与共识"；窗口关闭前"一致认为"不成立。
  - **诚实豁免**：`unknowns[]` 与 `not_doing[]` 是**评价中立**的交付物 ——
    只按其**是否被论证**（有没有说明范围、影响、后续触发条件）评价，不按"数量多少"扣分。
    反之，"未列出任何不确定"不得被当作"方案更成熟"的证据。
- **若违反，受损的是**：承担重活的成员（我在做全量清点，最可能因为"没时间读别人的 30 页"被判成"未参与共识"）；
  以及所有诚实者（写未知 = 扣分 ⇒ 下一轮没人再写未知，团队从此只产出"听起来没毛病"的方案）。

## 3. 我认为不可接受的裁决方式（2 条）

### 3.1 纯票数裁决：无逐条证据对照，只以"多数同意"冻结

**为什么不可接受**：
- 它把 R2 直接作废 —— N 票可能只有 1 个证据根（同源伪多数）；
- 它把 R4 作废 —— 没有 `claim → 证据 → 理由` 的追溯，冻结物只剩结论；
- 它允许**角色合并**（同一人既定义标准、又提供证据、又投决定票），而这是我的域最容易被压的结构：
  我的证据最"贵"（要去读源码、对 pin），评审最"便宜"（一句直觉）。
  只要便宜的一方人多，贵的一方必输 —— 而输掉的恰好是最难获得的那份证据。

**我要的替代**：票只是**输入**，不是**判决**；判决必须绑定证据 id 与理由（R4），
且"多数"的分子必须是 `independent_roots`（R2），不是人头。

### 3.2 裁决过程"加料"：在最后一轮引入辩论中从未出现的新证据/新要求，据此终局判负，且不给再回应

**为什么不可接受**：
- 它使"准备充分"变成**负收益**：我永远无法满足一个在最后一步才出现的条款 ——
  任何人可以事后构造"你一定没考虑 X"并据此判负，且不可反驳；
- 它破坏 R1 的对称性：我方的举证是**一次性暴露在明处**的，对方的要求却是**可无限追加**的；
- 它是"看起来很严格、实际不可证伪"的裁决，比宽松更危险：它会稳定地淘汰**证据最完整因而暴露面最大**的方案。

**我要的替代**：裁决前必须**冻结问题清单**（`frozen-questions[]`）；
冻结后新出现的要求只能登记为**下一轮议题**（`next-round-topics[]`），不得用于本轮判负。
新增证据若确属重大（能推翻结论），触发**重开一轮**，双方重新获得等量回应权 —— 不得"加料 + 直接判负"。

## 4. 我需要的证据形式（什么样的证据我才认）

我承认这套标准对我自己**最不利**（我的方案要逐条 file:line，别人的方案可以只说方向）。我仍然要求它，因为它是唯一能让"全量移植"这类强主张可被检验的形式。**先写我拒绝什么，再写我接受什么。**

### 4.1 明确不接受为"证据"的（最多只能当背景动机）

| 不接受 | 说明 |
|---|---|
| **"业界惯例 / 大家都这么做 / 某大厂也这样"** | 可以解释"为什么值得做"，**不能**证明"这样做在我们仓库成立"。它不携带本仓的任何约束信息。 |
| **无路径的断言** | "Memoria 的 X 已经支持 Y" 但不给 `path:line`；或给路径但不给"该行如何支撑断言"的推理链。 |
| **"存在某代码"⇒"应当移植"的跳跃** | 上游有 Cordis 插件运行时 ≠ Memoria 需要 Cordis。这一步跳跃必须单独论证，不能夹带。 |
| **不可证伪的主张** | "人手写会更灵活"、"声明式更优雅"、"以后可能要"。没有判据的主张不进裁决，只进 `open-questions`。 |
| **口头结论 / 未落盘结论** | 没产物路径的"我测过了"。本仓已有先例：无证据的 ✅ 不接受。 |
| **单一 benchmark 单次数字** | 无基线、无重复、无口径标注的一个数（见 §4.3）。 |
| **LLM 记忆/体感当唯一依据** | 可作为"去找证据的线索"，不得作为支撑票。 |

### 4.2 我接受的证据分级（A 可支撑结论 / B 只作线索 / 见下）

- **A1 源码断言**：`<repo>/<path>:<line>` + **pin（commit SHA / 版本）** + 一句"该行如何支撑/反驳该断言"的推理链。
  只给目录结构、文件名、包名推语义的，降为 B。
- **A2 可复现测量**：命令 + 输入样本 + 环境 + 产物路径 + **≥3 次重复**（或确定性脚本）；
  数值类必须同时给 `baseline` 与 `delta`；冷/热、首访/复访、headless/realapp 必须标口径。
  依据：`measurement-guidelines.md` 已实测——观察者效应会改变被测系统、重复访问必然失真、单点数据会误导、口径混报不可比。
- **A3 可复现反例**（**否决我的方案所需的最低等级**）：最小复现 = 脚本/输入 + `expected vs actual` + 输出日志 + 产物路径。
  我自愿把门槛抬到这里：**否决我请给 A3，而不是"我觉得"**；同样，我否决别人也要给 A3（见 §4.6）。
- **A4 成本/风险量化**：迁移工作量必须分解（文件数 / 行数 / 依赖 / API 数 / 需改的调用点），
  风险必须含"失败模式 + 可回滚点 + 触发阈值"。"太大了/太复杂了"是无量纲判断，不构成 A4。
- **A5 有口径的负证据**：例如"对 DSH 的 N 个包做了全量清点，口径=全部 `packages/*/`，未发现 X"。
  必须附**清点口径与覆盖范围**，且只能支持"在我声明范围内未发现"，**不声称穷尽**。

### 4.3 我接受的 benchmark 级别（"省 token / 省时"类主张的硬门槛）

我这个域的核心卖点之一就是**接口省 token**，所以我必须把口径钉死，否则我自己会最先造假：

1. **同口径**：同一 tokenizer 或同一预算脚本；同一任务集；同一"任务完成度"定义。
2. **有基线**：`before` 与 `after` 成对出现；只有 `after` 的收益主张无效。
3. **有重复**：≥3 次重复并给区间/中位数，或确定性脚本（可第三方重跑）。只报均值不报样本的，降为 B。
4. **有最坏情况**：token 预算必须按"单次工具调用的**完整往返**（含 schema、错误路径、schema 展开）"计，
   并给 `p50 / 最坏`；只报 happy path 的"省了 40%"不接受。
5. **有产物**：落盘 JSON/日志，路径可访问、可重跑。

### 4.4 我对"全量"这类强主张的特殊要求（因为它是我方案的根基）

- "全量移植"必须表现为**可枚举清单**（每类能力 × 每个点 × file:line × pin），而不是"我清点过了"。
- 清单必须带 `coverage`：我清点了什么范围、用什么口径、什么没清点（`uncovered[]`）。
- **任何一方都不得被要求证明"不存在"**（缺席证明不可能）。反向义务：主张"有遗漏"的一方应给出**A1/A3 级**的定位（"漏了 X，在 `path:line`"）。

### 4.5 我对异议的门槛（保护少数派，也约束少数派）

- 少数派可以用**一条 A1/A3** 顶住多数派的 B 级证据：`evidence_grade` 高于结论所依赖的等级时，该异议**必须**进入 `dissent-register` 且触发重新核对（见 R2/R4）。
- 但少数派**不得**用体感/惯例/记忆否决 A1/A3 —— 这条是对称的，否则"少数派保护"会变成"任何一方都能拖死结论"。

### 4.6 互惠条款（我接受同等甚至更严的约束，以证明本提案非自利）

1. 我的架构提案会**逐条**给 `file:line + pin`，并**单列** `unknowns[]` 与 `not_doing[]`；
2. 我否决他人必须给 A3 或明确写"这是提问不是否决"（R1 降级机制）；
3. 我接受"全量清点永远只是有口径的负证据"，因此我不要求任何人证明不存在（§4.4）；
4. 我接受 R5 的诚实豁免约束我自己：我写出的 `unknowns[]` 多，不因此获得加分，只按"是否被论证"评价。
