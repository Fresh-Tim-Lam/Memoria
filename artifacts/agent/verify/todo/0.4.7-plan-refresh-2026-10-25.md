## 2. 需人裁决（请先审这一节；每项 = 问题 + 选项 + 推荐 + 选错代价）

### D1 skill / plugin / capability 术语统一成什么？
- **问题**：UI/i18n 用「能力插件」（`settings.plugins.caps`），文档混用 capabilities / plugin / skill，用户与 agent 都容易混淆。
- **选项**：
  - **A（推荐）三层区分**：能力=capability（抽象）、技能=skill（规则面）、插件=plugin（分发载体）；出「旧→新」映射表。
  - B 统一叫「能力」，skill/plugin 只作为实现细节不暴露。
  - C 保持现状，只在文档写清区别。
- **推荐 A**：与代码结构（`agent-capabilities.md` / `agent-skills.md` / `agent-plugin-design.md` 三个文件）一一对应，迁移面可枚举（i18n 键 + 3 份设计文档 + 少量注释）。
- **选错代价**：B 会把「技能」这个用户可感知概念藏起来（AG21 验收更难解释）；C 则等于不解决（命名混乱继续）。返工成本 ≈ 30–60 条文案 + 1 轮 i18n 自检（可逆，R2）。

### D2 「上下文占用」怎么显示、压缩怎么观测？
- **问题**：compaction 已实现（`thresholdRatio=0.8` / `retainRatio=0.16`，`/compact` 存在），但 UI 只显示 token 数（`agent-panel.js:745`），从未观测到压缩真的发生。
- **选项**：
  - **A（推荐）百分比 + 阈值提示**：状态区显示「上下文 62% · 80% 时压缩」，压缩发生时插一条系统行（可回放）。
  - B 只显示 token 数（`prompt+completion` 与窗口上限），不做阈值提示。
  - C 详细面板（窗口/剩余/历史压缩记录），占空间更大。
- **推荐 A**：直接回答「压缩从未观测到」——让阈值与压缩事件可见；实现面最小（状态区 + 一条事件渲染）。
- **选错代价**：各模型窗口上限不同，A 需一个上限来源；若映射错 → 百分比误导（代价 = 一次修正 + 用户信任）。B 观测不到压缩，等于没解决原问题。

### D3 排版响应式的联动规则？
- **问题**：原话三条（dock 展开收缩文件树 / 已折叠且分屏则切预览 / 文件树同理），但「收缩」是折叠还是变窄、阈值多少、是否记忆用户选择，均未定。
- **选项**：
  - **A（推荐）按原话自动联动 + 保守阈值**：文档区 < 720px 时才触发；不记忆（每次按窗口状态算）。
  - B 仅做「dock 展开 → 折叠文件树」一条（最小）。
  - C 不做自动，加一个手动「紧凑布局」开关。
- **推荐 A**：最贴近人原话；阈值保守可避免频繁抖动。
- **选错代价**：阈值太激进 → 布局频繁跳（体验差，返工）；记忆策略错 → 用户手动调整被覆盖（不可逆感强，需回滚逻辑）。

### D4 0.4.6 披露的 3 个产品遗留，纳入 0.4.7 还是推后？
- **问题**：0.4.6 release body「Known issues」披露：① 图片块不在选区矩阵；② 多行粘贴后光标像素位置未断言；③ 视图模式偏好重启丢失（`app.js:20` localStorage + `private_mode=True`）。
- **选项**：
  - A 全纳入（①②③，+1 天）
  - **B（推荐）纳入 ①②（验证收尾），③ 推 0.4.8**
  - C 全推 0.4.8（0.4.7 严格只做 agent 收摊）
- **推荐 B**：①② 是 0.4.6「146/146」自证不完整（属上一版半吊子，收摊应补）；③ 是**功能改动**且方案有隐私分支（private_mode），不宜塞进收摊版。
- **选错代价**：A 会拉长 0.4.7 且引入 pywebview 配置风险；C 会让「已披露的验证缺口」继续挂着，下次发版又要解释。

### D5 团队基础设施运维债（findings open / 37 条缺 trailer / 写域重叠 / mode_policy 历史 14 条）进不进 0.4.7？
- **问题**：这些是团队治理线产生的债（见 §3.4），与产品无关，但都「没闭环」。
- **选项**：
  - **A（推荐）不进 0.4.7**：归团队运维，按各自 owner/机制消化（task-110 steward；37 条宽限到 2026-11-07；写域下次建任务收窄；mode_policy 历史项永久不可判定）。
  - B 全进 0.4.7（会污染版本范围，且验收对象是内部工具）。
  - C 只做 0 成本项（写域收窄 + 报告旧路径修正），不占版本。
- **推荐 A + C**：0 成本项本轮顺手做掉（我已收窄 `task-94` 写域、修正本文件旧路径引用），其余不进版本。
- **选错代价**：B 会让「0.4.7 发布说明」变成内部治理清单，且这些项无产品验收标准；A 的风险只是「看板仍显示 WARN」，由 steward 例行处理。
