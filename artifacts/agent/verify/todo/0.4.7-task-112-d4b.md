### 1.3 新发现（本轮最重要）：HEAD 起"量具"在 headless 也假失败
当前 HEAD（`5c6e93cc`）新增了**后端剪贴板 RPC**（`clipboard_get_text` / `clipboard_set_text`，2026-10-24），产品 `writeClipboardText()` 优先走后端。
- **旧驱动的 cut 断言依赖 `navigator.clipboard.writeText` spy** ⇒ 产品不再调它 ⇒ spy 抓不到 ⇒ **HEAD 基线跑出 111/146（35 个 cut 全挂 clipboard）**（本任务实测：`selection-matrix-task112-baseline.md`）。
- 这是**第 3 个"量具盲区"**（前两个：read_only 声明≠沙箱、`assert "xxx" in src` ≠ 代码会执行）。共同形态：**量具假设了被测系统的实现路径；实现变了，量具还在测旧路径。**
- **修法（只改量具，不改产品/不改历史口径）**：
  1. `selection-driver.mjs` 对 cut 使用后端 `clipboard_get_text()` 回读（真实产品写入路径）；
  2. copy 仍走原生 copyEvent/readText（避免后端读到上一次的陈旧剪贴板）；
  3. **每个 copy/cut 用例前写入唯一哨兵** `SEL_MATRIX_SENTINEL_*`，后端回读等于哨兵 ⇒ 视为"产品没写"，绝不把陈旧内容当成功；
  4. `clipboard.source` 明确标注 `backend-clipboard` / `copyEvent/readText` / `clipboard.writeText(spied)` / `pasteEvent`（每条断言自带口径）。
- 修后：headless **9 类 158 用例全 PASS**；等价 8 类 = 146/146（与历史数字同口径，但**测量路径已注明**）。

### 2.4 image cut 的**剪贴板语义**（产品语义待裁决，未改代码）
`edit-handler.js:838 function writeCutToClipboard(text){ if(!text) return; }`、`:1010 cutText = selCut.toString()` —— 只取纯文本：
- **image 组的 cut 仅验证【文档侧移除】**（`imagesGone/imagesKept`）；矩阵中 image 选区都含两侧段落文本，所以剪贴板有文本、断言通过；

- 实测（真机，`image-only-cut-verify.json`）：真实鼠标点图片 + Ctrl+X 为 **no-op**（文档未变、剪贴板未写、无提示）；用产品同源 `beforeinput deleteByCut` + 块级选区则**被拒绝**并回显「已复制到剪贴板，但无法删除该选区…」（文档未改）。
⇒ **结论：图片单独 cut 的语义未定义/不一致，属【产品语义待裁决】**（图片该不该进剪贴板、要不要提示）——**未擅自改 `if (!text) return`**。

## 三、多行粘贴后光标像素核验（source + preview 两条路径）

方法（不靠肉眼）：记录粘贴前光标行/列 → 用真实 Ctrl+V（真实鼠标定位 + 后端剪贴板写入 + 真实按键）粘贴 3 行文本 → 读 `window.getSelection()` 的 caret（容器/偏移 + 相邻字符 Range 的像素 rect），与"插入文本末行末字"的 Range rect 做 **Δx/Δy ≤ 2px** 断言；同时断言源码 3 行都在。

### 3.1 源码区（`applyEditorPaste`）：**PASS**
- 粘贴前：`cursor-test.md` 第 3 行「ALPHA one two three」末尾；
- 粘贴后：光标在第 5 行、偏移 17（= 末行 `PASTE_THREE gamma` 长度）；行内容以末行结尾；`state.doc.body` 三行都在（第 2/3 行为新行）；
- **像素断言：caret rect vs 末行末字 rect —— Δx=0.0px，Δy=0px**；截图 `shots/source_after_multiline_paste.png`。
- 合成 ClipboardEvent 路径同结果（Δ0/0）；真实 Ctrl+V 复现（`real_source_*` 全绿）。

### 3.2 预览区（`pasteTextAtCursor`，折叠光标）：**⚠️ 发现异常，已开问题单（未改产品代码）**
干净真机实验（fresh app、专用 `cursor-test.md`、真实鼠标点击段落末尾 + 后端剪贴板 + 真实 Ctrl+V）观察到：
```
粘贴 3 行：PREVX_ONE aaa / PREVX_TWO bbb / PREVX_THREE ccc
结果 body: 「ALPHA one two threePREVX_ONE aaa」   ← 只保留第 1 行
第 2/3 行丢失；getSelection() 崩塌（caret null，blockText 空）
```
复跑一次则连第 1 行也未插入（paste 事件计数不稳定）⇒ 在当前 harness 下**不能稳定地把它归因为产品缺陷 vs 焦点/按键注入不稳定**，但"至少一次干净实验出现丢行+光标丢失"是**真实观察**。
**未改产品代码**（按纪律）；详见 §五 问题单；建议人工在真实机器上用鼠标点击段落末尾后 Ctrl+V 复现一次以定性。

## 八、方法论：量具盲区与根因判断（本轮教训）

**量具盲区四例**（共同形态：**量具假设了被测系统的实现路径；实现变了/本来就不同，量具还在测旧路径**）：
1. `read_only` 声明被当成沙箱（S4，R-S4-2）
2. `assert "xxx" in src` 被当成"代码会执行"（task-134 死代码）
3. 驱动 spy `navigator.writeText` 被当成"剪贴板写入发生"（本条；当前 HEAD 后端直写）
4. **历史失败 ≠ 当前假失败**（本条）：0.4.5 是**真失败**（后端 RPC 不存在 ⇒ 回退 navigator ⇒ 权限弹窗 ⇒ 未写成）；当前 HEAD 是**假失败**（后端直写 ⇒ spy 抓不到）。**每个结论都要标注适用哪个构建/哪个时期。**

**可操作检查法**：**每个断言都问——它依赖被测系统的哪个实现细节？该细节变了会怎样？**

**根因判断教训**（人指出 + 复核）：当**同一个解释能同时说明"为什么当时失败、为什么现在不失败"**时，才该采信这个根因。
我上一轮的解释只说明了"现在"（后端直写 ⇒ spy 抓不到），**没解释"当时为什么失败"**——直到人点出"当时是权限弹窗"。⇒ 采信根因前必须能覆盖**两个时期**。
