## 一、做了什么（只做 tooltip，没做 toast）

### 1. 三态 tooltip（`app.js:16492` 附近 `_syncSidebarToggleBtn`）
| 状态 | 判定 | zh 文案 | en 文案 |
|---|---|---|---|
| **A 自动折叠**（响应式派生，用户没折叠过） | `_sidebarAutoCollapsed` | **空间不足，已自动收起；点击展开（空间不足时会收起对话栏）** | Auto-collapsed for space; click to expand (the agent dock will be hidden to make room) |
| **B 用户折叠** | `_sidebarCollapsed` | **展开文件树**（原「展开侧栏」按任务要求改） | Expand file tree |
| **C 展开** | 其余 | 收起侧栏（保持原样） | Collapse sidebar |

- 新 i18n 键：`side.autoCollapsedTitle`（zh-CN.js:588 / en.js:590），`i18n_selftest.js` PASS（zh/en 配对）。
- `aria-label` 同步为同一文案（无障碍名称也是解释，不只 hover 才有）。
- **修掉一个真机踩到的坑**：按钮在 `index.html` 上有静态 `data-i18n-attr="title:side.collapseTitle"`，
  它会在启动的 i18n 静态刷新里把"自动折叠态"文案**覆盖回「收起侧栏」**（真机首测就是 title=收起侧栏、
  aria-label 却是自动折叠文案的错位）。修法：`setupSidebarCollapse()` 里
  `btn.removeAttribute("data-i18n-attr")`，标题完全由 `_syncSidebarToggleBtn` 三态接管，
  语言切换仍走 `MemoriaI18n.addRefresh(_syncSidebarToggleBtn)`。

### 2. 视觉区分：采用**方案 i（弱强调）**，理由如下
- **只靠 tooltip 不够**：tooltip 必须 hover 才出现，而困惑发生在"第一眼看到文件树消失"的时刻；
  自动态按钮加一点主题色 = "这不是你刚才点的"，能**提示去 hover 找解释**。
- **只用既有 token**：`#btn-toggle-sidebar.-sidebar-auto-collapsed { color: var(--theme-color); }`
  （app.css:149-151，无硬编码颜色），不改布局/尺寸，不动响应式判据。
- 真机对比（裁剪自 OS 截图）：`shots/auto_1256_tooltip_button_crop.png`（**蓝色主题**）vs
  `shots/user_1600_tooltip_button_crop.png`（默认灰白）；计算色 `rgb(0,122,204)` vs `rgb(204,204,204)`。
  视觉不突兀（仅一个 28×30 图标着色）。

## 三、⚠️ 如实说明：**原生 tooltip 截图在本 harness 环境拍不到**

任务关闭条件 5 要求"hover 显示 tooltip"的截图。实测得到的结论与证据：

1. 用**真实 OS 光标**（`SendInput` 绝对/相对 mouse_event，非 CDP 合成）移到按钮上并等 1.6–2s；
   OS 截图里**没有** tooltip 浮层，枚举所有进程窗口也找不到 tooltip 文本窗口。
2. **对照实验**（`tooltip_probe.py`）：拿顶栏**既有** `title` 的「后退 (Alt+←)」按钮做同样的真实 hover，
   截图同样**没有** tooltip（`memoria_t136_probe/tooltip_probe.png`）。
   ⇒ 不是本次实现的问题；是**本机 WebView2/pywebview 嵌入式窗口对原生 title tooltip 的渲染/截图限制**
   （或原生 tooltip 由 Chromium 自绘、不被 OS 截图捕获）。

**已用可断言的方式替代取证**：`title` / `aria-label` 三态内容在真机 DOM 里逐字断言通过（tooltip 显示的就是它），
按钮弱强调有真机截图像素对比。**但"用户肉眼能否看到浮层"这一点无法在本 harness 断言**。

**需要人/Lead 决策**：
- 若在真人操作的真实机器上 hover 能出现 tooltip ⇒ 本任务即满足 UX 目的（截图请人补一张，或视为已验证）。
- 若真实机器也**不显示** title tooltip ⇒ 本方案对用户无效，需要改**自定义 tooltip 组件**（新增 UI，属更大改动，不在本任务范围，需另行派发）。
