## 五、🔴 本次挖到的**仓库级落点缺陷**（交 Lead 另行立项 task-134，本节只记录，不擅自扩大）

### 5.1 现象
首轮真机验证（修复前）结果：长会话能载入（40 条 DOM 气泡）、后端 `agent_session_load` 返回
`context_usage={chars:31702,max_chars:32000,threshold_chars:25600,compacted_times:0}`，
但 **`#status-agent` 文本为空**、`messages` 里 **`role:"system"` 从未出现** —— task-91 的 UI 部分**在真机上完全没生效**。

### 5.2 根因（实证）
```
agent-panel.js 结构（修复前）：
  L83    window.MemoriaAgentPanel = (function () {      ← IIFE 开始
  L6874    return { ... };                               ← IIFE 的 return（门面）
  L6919    };                                            ← return 对象闭合
  L6921+   function askRecordText / toolDisplayDetail …  ← hoisted，可达
  L6969+   const RES_EXT = {...}                         ← 顶层语句，【永不执行】
  L7126+   task-91 的 4 个 wrapper（const base… = …; fn = function(){}）← 全死
  L7280  })();                                           ← IIFE 结束
```
- **JS 语义**：`return` 之后的**顶层语句**永不执行（只有 `function` 声明 hoist）；task-91 的接线全是赋值语句 ⇒ 死代码。
- **CDP 断点实证**（`deadcode-probe.json`）：对 6874(`return {`) / 7062 / 7252 请求断点，V8 **全部重定位到 6919**
  （IIFE 内最后一个可达位置）；6590（return 之前）正常解析为 6590；paused 栈从未命中 post-return 行。
- **更糟的潜伏风险**：`return` 之后的 `const` 永不初始化；若有 hoisted function 引用它们 ⇒ **TDZ ReferenceError**（不是"没生效"，而是"可能炸"）。

### 5.3 错误约定（已上报 Lead，task-134 统一处理）
`agent-panel.js:6964` 注释写「落点纪律：整块追加在 IIFE 末尾（`})();` 之前）」——**这条纪律是错的**：
IIFE 中间有 `return`，追加在 `})();` 之前 ≠ 追加在 `return` 之前。该约定已误导多个任务的追加块（本任务也是受害者）。
**本次未改这条注释**（按 Lead 裁决：task-134 统一改，避免写域冲突）。
