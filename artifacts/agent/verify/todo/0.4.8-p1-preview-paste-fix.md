## 二、定位（根因证据，非猜测）

用 `debug_probe.py` 给 `MemoriaEditSync.insertText/splitParagraph` 包一层，记录每次调用的返回值 +
`EH.cursorAST` 前后值（`debug-trace.json`）：

```
0 insertText('DBG_ONE aaa')   ret=True   cursor: bi=2/path=[0]/off=19 → off=30
1 splitParagraph()            ret=True   cursor: off=30 → off=30  （未变）
2 insertText('DBG_TWO bbb')   ret=False  ← 静默失败（调用方未检查返回值）
3 splitParagraph()            ret=False
4 insertText('DBG_THREE ccc') ret=False
```

根因链：
1. `pasteTextAtCursor` 逐行 `insertText(lines[0]) → splitParagraph() → insertText(lines[i])`；
2. `splitParagraph()` 的**光标恢复在 `repaintPreview().then(...)` 异步里**（`app.js` splitParagraph 尾部）；
3. 原实现**同步**继续下一行 ⇒ 读到拆段前的旧 `cursorAST`（`bi=2/off=30`，此时块已变/空行尚未恢复）
   ⇒ `insertText(lines[i])` 返回 **false**；
4. 原循环**不检查返回值** ⇒ 后续行静默丢失；最后仍 `setStatus("已粘贴")` ⇒ **用户以为成功**（最坏点）。

## 三、修复（最小改动，未动响应式/tooltip/源码区粘贴）

`src/memoria/ui/static/app/js/app.js`（+≈70/-25）：

1. **新增结构性编辑完成信号** `_pendingStructural`：
   - `splitParagraph()` 里把 `repaintPreview().then(restoreCursor...)` **保存为 `_pendingStructural`**（并 `.catch` 记 console.error，避免未处理 rejection）；
   - `MemoriaEditSync` 导出 `whenStructuralIdle()` 返回该 promise（无 pending 时 `Promise.resolve()`）。
2. **`pasteTextAtCursor` 改为 async 且按序等待**：
   - 每行 `await EditSync.whenStructuralIdle()` 后再插下一行（消除"旧 cursorAST"竞态）；
   - **每步检查返回值**：`insertText`/`splitParagraph` 任一失败即停止；
   - 失败 → `console.error("多行粘贴在第 i/n 行失败…")` + `setStatusError(T("cfg.clip.pasteFail"), "i/n")`
     —— **可见错误**，不再谎报"已粘贴"；成功仍 `setStatus("已粘贴")`。
3. 非折叠选区粘贴路径（`replaceSelectionWithText`）**未改**（矩阵 paste 用例仍全绿）。

> 未新增 i18n 键（复用既有 `cfg.clip.pasteFail`，detail 用 `i/n` 数字，语言无关）；未动 `applyEditorPaste`（源码区对照基线）。

## 六、剩余风险 / 说明

1. `splitParagraph` 的 `_pendingStructural` 只服务"多行粘贴等待"；**快速连续回车后立刻打字**理论上仍有同类竞态窗口（Enter 键路径同步返回、未 await）。本次未改该路径（不在缺陷复现范围；如需要可后续用同一信号统一收口）。
2. 多行粘贴在"非段落块（list/blockquote 等）"的行为沿用原逻辑（逐行 splitParagraph）；本次修复覆盖竞态，不改变这些块类型的既有语义。
3. 真机测试会写系统剪贴板（测试脚本会在每次试验前写入唯一 marker）。
