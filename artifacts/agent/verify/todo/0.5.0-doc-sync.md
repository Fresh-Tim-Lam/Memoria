### 1.1 先读代码确认真实形状（未照抄概要）

| 事实 | 来源 | 实测值 |

| 字段形状 | `history.py::session_context_usage()` | `{chars, max_chars, threshold_chars, compacted_times}` |
| `MAX_HISTORY_CHARS` | 运行时常量 | **32000** |

| `chars` 口径 | `history_chars(build_history(...))` | 先应用 `compaction`/`compaction.prune` 覆盖 |
| `compacted_times` | `compaction` 事件条数 | — |

⇒ 与任务书概要一致，但**每条都经代码与运行时验证**（`python -c` 打印常量，非照抄）。

### 1.2 登记位置与内容

**位置**：`docs/design/dsh-agent-port.md` **§6.8.1**（新增小节，挂在 §6.8「M2 compaction 实施记录」之下 ——
压缩可观测性是该字段的语义归属，而 §6 是会话 RPC 的契约归属地）。

**内容要点**（完整三条语义均写入，非摘要）：
1. **分子分母同域 —— 都是字符，不做 token 换算。** token 是另一套数（`loop/end.usage`，见 §6.15/§13），
   两者不合并、不互相折算；要显示 token 占用应**另立字段**，不许拿本字段换算或反推。
2. **`chars` 口径 = `history_chars(build_history(...))`，与压缩判定同一个函数对象。**
   必须走 `build_history`（先应用 `compaction` / `compaction.prune` 覆盖）；`ask._compact_if_needed()`
   判阈值用的是同一个函数。**禁止**改成原始事件累加 —— 那是压缩前的虚高值，UI 会在已压缩后仍显示 >80%。
3. **缺席含义 = 旧会话/未知，前端必须容忍。** 可缺席或为 `null`；消费方遇缺席不报错、不显示占用行，
   不得当 0% 或 100%。**只增字段**：默认路径逐字节不变。

**另写明归属边界**：该字段属**会话 RPC**契约（§6），**不属于** `agent-service-contract.md`
（该文范围 = 写服务契约：`apply_plan` + `WRITE_CAPABILITY` + 错误码 + `section_index`，不含会话 RPC）。

### 1.3 判定：**不阻塞 0.5.0 发布，但必须补 —— 现已补完**

**为什么本可不阻塞**：代码已交付、docstring 已写、前端已按缺席/null 容忍、`conventions/version.md` 的
0.4.7 行已写口径 ⇒ **功能完整可用**，缺的只是"契约归属"这层。

**为什么必须补**（与 Lead 判断一致）：下次改这个字段的人**不知道它是契约的一部分**，可能随手破坏
（改口径、改语义、或把"字符"换成"token"）。这种"功能能用但没在契约里出现"的坑，事后极难发现。
