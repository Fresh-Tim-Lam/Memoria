## 7. 更正记录：引用了错误来源（2026-10-25，Lead 实测纠正）

**我写错了什么**：本报告初版写「tag `v0.5.0`（annotated `c7c5fb39`）→ 提交 `8067cde6`」，并在 Lead 指出
差异时写成「两者都记、不强行统一」。这是**错误**，不是口径差异。

**实测事实**（Lead 给出、本报告复核）：

| 值 | 实际含义 |
| --- | --- |
| `c7c5fb39` | 2026-10-25 12:17 的**第一次** 0.5.0 发布 commit（**已被撤回**；它是 `8067cde6` 的祖先） |
| `8067cde6` | 2026-10-25 18:52 的**正式** 0.5.0 发布 commit（含更正声明） |
| `b43306e4` | 当前 `v0.5.0` **annotated tag 对象**（指向 `8067cde6`，且既不是 `c7c5fb39`） |

**根因**：我把 `release-0.5.0-record.md`（**撤回记录**）当作当前发版记录引用；该文件当时未标「已撤回」，
但它描述的是第一次发布 `c7c5fb39`。⇒ **引用了错误来源**，属于本轮反复打的那类问题。

**处置**：Lead 已修正 `docs/todo.md §16` 与 `release-0.5.0-record.md`（顶部撤回横幅 + 标题改「已撤回」）；
本报告同步更正 §3① / §4 / 本节，并保留此错误记录（不静默改写）。

**教训（写下来防再犯）**：遇到两个值不一致，先判断「它们指向的是**同一件事**还是**两件事**」——
- 同一事实的不同计量口径（1180 MB vs 1179.5 MB；是否折叠末尾换行）⇒ 用「约」+ 注来源；
- 指向**两次不同发布/不同对象**（`c7c5fb39` vs `8067cde6`；annotated tag 对象 vs commit）⇒ **这是错误，标出来报 Lead，不得折中**。

**核对口径**：`git rev-parse vX.Y.Z` = annotated tag 对象 sha；`git rev-list -n1 vX.Y.Z` = 其指向的 commit sha；
两者在台账里必须分别写、不得混用。
