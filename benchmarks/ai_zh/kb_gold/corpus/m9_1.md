#### 知识点9-1：人工智能基础软硬件框架（对应表格“人工智能算法支撑技术链”）

**1. 智能计算框架的整体结构**
- **位置来源**：第273页，第1页，图9.1。
- 人工智能计算框架可分为**运行系统**（部署和运行模型）和**开发系统**（开发和训练模型）两大部分。

**4. 智能计算结构与计算架构**
- **位置来源**：第274页，第2-3页。
- **智能计算结构**：为实现AI算法而设计的计算框架和架构，包括计算架构和算法优化。
- **计算架构**：为AI算法设计的硬件和软件结构。
  - 从传统CPU到**异构计算**（CPU + GPU + TPU等），充分利用各自优势
  - 专用AI处理器（如TPU）针对深度学习任务优化，提供更高的计算效率和能耗效率
- **算法优化**：
  - 包括算法设计、参数调整、计算优化
  - 使用并行计算、分布式计算、异构计算加速算法执行
  - 通过量化、剪枝等技术减少计算和存储需求
- **智能计算结构与计算架构相互促进**，共同推动AI发展。


#### 知识点9-2：人工智能芯片（对应表格“人工智能芯片（GPU、XPU和类脑芯片等）”）

**位置来源**：第275-276页（9.2节全文），第3-4页

**1. 图形处理器（GPU）**
- **位置来源**：第275页，第3页。
- **基本原理**：最初为图形渲染设计，因并行计算能力被用于AI计算（特别是卷积计算）。
- **架构特点**：大规模并行计算架构，成百上千个计算核心，可同时执行多个计算任务。
- **里程碑事件**：
  - **2006年**：Kumar Chellapilla使用GeForce7800显卡实现CNN，比CPU快4倍——**已知最早将GPU用于深度学习的尝试**
  - **2012年**：AlexNet使用4颗Geforce GTX 580，在1周内完成1400万张图片的训练（262千万亿次浮点运算），引发对GPU的广泛关注
- **英伟达GPU架构命名**：均以著名科学家命名——居里（Curie, 2004）、特斯拉（Tesla, 2006）、费米（Fermi, 2010）、开普勒（Kepler, 2012）、麦克斯韦（Maxwell, 2014）、帕斯卡（Pascal, 2016）、伏特（Volta, 2017）、图灵（Turing, 2018）、安培（Ampere, 2020）、霍珀（Hopper, 2022）、埃达（Ada, 2023）。

**2. 张量处理器（TPU）**
- **位置来源**：第275-276页，第3-4页。
- **提出者**：谷歌公司设计和开发。
- **设计目标**：专门用于加速AI计算，针对深度学习工作负载优化。
- **核心优势**：在高度并行的**矩阵乘法**和**向量运算**上具有显著性能优势。
- **特点**：高内存带宽、低功耗、低延迟；高度可编程和灵活。
- **应用**：谷歌云计算平台、语音识别、图像处理、自然语言处理。

**3. 可扩展处理器（XPU）**
- **位置来源**：第276页，第4页。
- **设计目标**：一颗芯片集成多种类型处理器（CPU、GPU、DSP等）。
- **核心机制**：通过软硬件协同，将不同类型计算任务分配给最适合的处理器。
- **优势**：高效计算、优良能效。

**4. 类脑芯片（Neuromorphic Chip）**
- **位置来源**：第276页，第4页。
- **设计灵感**：受人脑神经元结构和功能启发。
- **架构特点**：采用神经元模型和突触连接的特殊架构。
- **计算模式**：并行计算 + 事件驱动方式。
- **优势**：高能效、低延迟，适用于模式识别、感知和自适应学习。

**5. 特定领域芯片（Domain-Specific Chip）**
- **位置来源**：第276页，第4页。
- **设计目标**：为特定AI应用场景设计（自动驾驶、机器人、物联网等）。
- **特点**：定制化硬件加速器、专用指令集、优化算法。
- **优势**：满足实时性、低功耗、高性能需求。


#### 知识点9-3：分布式神经网络训练算法（对应表格“分布式深度学习优化”）

**位置来源**：第277-279页（9.3.2节前半部分），第5-7页

**1. 分布式训练的背景**
- **位置来源**：第277页，第5页。
- 模型规模不断增大：GPT-1（1.17亿参数，2018）→ GPT-2（15亿参数，2019）→ GPT-3（1750亿参数，2020）。
- 单个GPU V100训练GPT-3需约**288年** → 必须使用分布式训练。
- **三种并行策略**：数据并行、张量并行、流水线并行。

**2. 数据并行（Data Parallelism）**
- **位置来源**：第277-278页，图9.2，第5-6页。
- **核心思想**：训练数据分配到不同计算节点，每个节点有一份完整模型，在本地数据上训练。
- **通信开销**：节点间需高频通信传输梯度或同步模型。
- **局限**：
  - 节点数量增加 → 总数据量增大 → 模型收敛性能下降
  - 数据总量固定 → 每个节点batch size减小 → 计算资源利用率降低

**3. 张量并行（Tensor Parallelism）**
- **位置来源**：第278页，图9.3，第6页。
- **核心思想**：按**神经元**划分模型，每个节点存储一小块模型，达到并行计算目的。
- **通信开销**：每次迭代需共享神经元结果 → 要求**低延时、高带宽**网络。
- **适用场景**：一般仅在**节点内部的多加速器之间**高效完成。

**4. 流水线并行（Pipeline Parallelism）**
- **位置来源**：第279页，图9.4，第7页。
- **核心思想**：按**网络层**划分，每个阶段映射到一个GPU，该阶段的前向、后向传递均在该GPU上完成。
- **关键要求**：每个阶段**计算负载均衡**（减少短板效应）。
- **通信开销**：相邻阶段需传递神经元 → 需**低延时、高带宽**网络。


#### 知识点9-4：分布式训练系统与通信优化（对应表格“分布式深度学习优化”）

**位置来源**：第279-284页（9.3.2节后半部分及9.3.3-9.3.4节），第7-11页

**1. 分布式训练系统的关键要素**
- **位置来源**：第279-280页，第7-8页。
- **通信和同步机制**：
  - **参数服务器（Parameter Server）** （图9.5）：
    - 维护集中的参数存储，计算节点发送梯度更新，参数存储节点更新后广播
    - 优点：同步通信开销较低；缺点：存储节点网络压力大
  - **Ring AllReduce**（图9.6）：
    - 节点组织成环形拓扑，数据沿环形路径传递，每个节点局部归约后传递
    - 优点：网络负载均衡，集群网络利用率高
- **资源管理和调度**：Kubernetes、Apache Mesos等
- **容错和恢复**：自动检测和处理异常

**2. Megatron-LM与DeepSpeed——3D并行**
- **位置来源**：第280-281页，第8-9页。
- **3D并行 = 流水线并行 + 张量并行 + 数据并行**：
  - **机器间**：用流水线并行（减少跨机通信）
  - **机器内部**：数据并行 + 张量并行混合（在内存和计算效率间权衡）
- **ZeRO-Offload / ZeRO-Infinity**（DeepSpeed）：
  - 将参数、梯度、优化器状态卸载到CPU内存或SSD
  - 支持在**少量GPU**上训练TB级别大模型
- **自动化并行系统**：Colossal-AI、Alpa等可自动根据硬件架构和模型结构划分模型。

**3. 网络通信的异构硬件优化——剪刀差问题**
- **位置来源**：第281-282页，图9.7，第9-10页。
- **发展速度剪刀差**：
  - GPU计算能力：每2年增长3.1倍（20年增长约9万倍）
  - DRAM带宽/网络互连带宽：每2年仅增长1.4倍（20年增长约30倍）
- **结论**：神经网络分布式训练越来越成为**网络瓶颈**的负载。

**4. 网内计算（In-Network Computing）**
- **位置来源**：第281-282页，第9-10页。
- **SwitchML**（Sapio等，2021）：
  - 用可编程交换机（如Intel P4）在网络传输同时对梯度进行**规约计算**
  - 优点：只需每个计算节点的上行和下行带宽
  - 结合了参数服务器和Ring AllReduce的优势
- **局限**：智能交换机的网内计算资源仍然有限。

**5. 大规模机器学习系统部署**
- **位置来源**：第282-283页，第10-11页。
- **GPU资源分配**：
  - 静态分配：预先分配（可能导致资源浪费）
  - 动态分配：根据实时需求调整（资源利用效率更高）
- **GPU资源调度**：
  - 公平调度：时间片轮转、公平队列
  - 优先级调度：高优先级任务获得更多资源
- **GPU多租环境挑战**：
  - 训练任务不能充分利用GPU资源
  - 深度学习任务需“组调度”导致等待时间长
- **解决方案**：GPU内存和计算单元的**细粒度动态控制机制**（Xiao等，2020）
- **未来方向**：从云计算和端智能向**端云协同进化计算模式**跨越，充分发挥端侧+云端的各类计算资源。
