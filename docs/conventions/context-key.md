# 上下文维护规范 -v0.1

> **用途**：定义上下文关键句（CTX-KEY）机制，作为检测 Agent 是否完整加载用户指定文件的防火墙。通过在项目文件中嵌入隐式标记，让 Agent 在回答开头自证已读取全部关键内容。
> **目标读者**：项目负责人（用户）与 AI Agent。
> **关联文档**：[meta-rules.md](./meta-rules.md) — 本规范遵循的元规则；[collaboration.md](../guides/collaboration.md) — 具体开发场景规范。

---

## 1. 机制概述

核心思想：用户在要求 Agent 阅读的文件中，随机插入 `[CTX-KEY:xxx]` 标记。Agent 在回答开头必须输出本次扫描到的全部关键句。用户通过对比预期关键句与 Agent 的输出，快速判断 Agent 是否遗漏了文件或文件中的部分内容。

```
用户：请阅读 docs/design/架构设计.md 和 src/config.yaml
      ↓
Agent 扫描这两个文件 → 发现 [CTX-KEY:爸爸] [CTX-KEY:妈妈]
      ↓
Agent 回答开头必须输出：
  [CTX 加载] 关键句: [爸爸] [妈妈]
      ↓
用户在 IDE 全局搜索 "CTX-KEY" → 对比自己的注入列表与 Agent 输出
      ↓
匹配 → 上下文加载正常    |    不匹配 → 上下文遗忘，立即中断
```

## 2. 关键句标记格式

### 2.1 标记规范

- **格式**：`[CTX-KEY:xxx]`
- **要求**：
  - `xxx` 为用户自定义短语，建议简短（1-4 个汉字或字母）
  - 标记必须插入在文件中的**自然位置**（正文段落中、代码注释里、配置项旁边等），不应聚集在同一位置
  - 标记不区分大小写，`[CTX-KEY:abc]` 与 `[ctx-key:ABC]` 视为同一个

### 2.2 标记示例

```
文内：[CTX-KEY:爸爸]
代码注释：# [CTX-KEY:妈妈]
配置：# [CTX-KEY:v0.1]
```

### 2.3 区分度

`[CTX-KEY:xxx]` 格式在全局搜索中具有高区分度。用户在 IDE 中搜索 `CTX-KEY` 即可立即定位项目中所有标记。

## 3. Agent 行为协议

### 3.1 触发条件

当用户明确要求阅读/查看/分析某些文件或目录时，Agent 必须执行 CTX-KEY 检查。

### 3.2 输出格式

Agent 的**每一次回答**必须以以下格式开头：

```
[CTX 加载] 关键句: [短语A] [短语B] [短语C]
```

说明：
- 列出本次扫描范围内**找到的所有关键句**
- 如果范围内没有任何关键句，则输出：`[CTX 加载] 无`

### 3.3 范围界定

Agent 只扫描用户本次对话中**明确指定要阅读的文件**。用户未提到的文件不纳入扫描范围。

### 3.4 约束

- ❌ Agent **不得**在输出关键句后添加任何额外说明（如"请注意以上是上下文关键句"等画蛇添足的内容）
- ❌ Agent **不得**在扫描到关键句后询问用户"是否需要输出关键句"——输出是强制性的
- ❌ Agent **不得**对关键句的含义进行猜测或解释

## 4. 用户协议

### 4.1 标记管理

- 用户通过在项目文件中插入 `[CTX-KEY:xxx]` 来部署关键句
- 建议分散在多个文件中，不要全部塞在一个文件里
- 用户无需维护关键句索引表，通过 IDE 全局搜索 `CTX-KEY` 即可获知完整列表

### 4.2 验证方式

每次 Agent 返回回答后，用户在 IDE 中：
1. 全局搜索 `CTX-KEY`
2. 在搜索结果中筛选出本次对话涉及的文件的标记
3. 与 Agent 输出的 `[CTX 加载]` 行对比
4. 若不一致 → 上下文遗忘发生，**立即中断当前对话**

### 4.3 关键句生命周期

- **复用**：关键句可重复使用。Agent 在后续对话中输出同一关键句不代表其失效。
- **更换建议**：用户可根据自身安全评估决定何时更换。建议在以下情况考虑更换：
  - 项目阶段性里程碑达成
  - 同一关键句已被 Agent 多次输出超过 5 次
  - 怀疑关键句内容已泄露或 Agent 表现出记忆行为
- **删除**：当文件内容发生重大变更时，建议同步检查并更新其中的关键句。

## 5. 遗忘处理流程

当发生上下文遗忘（Agent 输出与预期关键句不匹配）时：

1. **立即中断**：用户停止当前对话，禁止 Agent 继续执行后续操作
2. **原因排查**：确认是 Agent 漏读了文件，还是读错了文件版本
3. **重新加载**：用户重新明确指定需要阅读的文件，要求 Agent 重新扫描并输出关键句
4. **记录**：将遗忘事件记录在项目日志中，供后续改进参考
