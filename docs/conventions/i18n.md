# 语言系统（i18n）维护规范

> **用途**：定义 Memoria 桌面应用的语言系统（语言包 + 界面文案接入）的契约性规则——文案如何抽取成键、语言包结构与存放位置、缺失回退策略、新 UI 如何接入、清单如何维护，使人机在新增/迁移界面文案时无需猜测即可遵守。
> **目标读者**：项目负责人 / AI Agent（所有新增或修改 UI 界面文案、维护语言包的开发者）。
> **关联文档**：[i18n-inventory.md](../reference/i18n-inventory.md)（当前界面文案登记清单，本规范的事实依据）；[readme-i18n.md](./readme-i18n.md)（README 双语与演示截图规范，属**仓库展示文案**，与应用内语言包正交）；[docs-management.md](./docs-management.md)（docs 组织规则）；[meta-rules.md](./meta-rules.md)（规范书写元规则）。
> **状态**：生效中。语言包机制已于 2026-09-03 落地（`app/i18n/zh-CN.js` + `en.js`、`app/js/i18n.js`、设置→显示「界面语言」即时切换、index.html 首批静态文案接入）；同日「检查」功能链路文案接入（检查弹窗/状态栏/角标/设置→检查页，见 `check.*` 键族），并落地后端检查消息的 code+params 本地化机制（见 §5 与 §6.5）。全量界面文案迁移（清单 900 行候选）为进行中事项。
> 制定日期：2026-09-03。

---

## 1. 总则

1. **界面文案禁止硬编码中文**：新增 UI 的用户可见文本一律通过 `t('key')` 取当前语言，语言包缺失时自动回退中文。
2. **中文为源语言**：`zh-CN` 包为完整事实源；新增键必须**同时**补入 `zh-CN` 与 `en`，英文翻译可暂缺（缺键回退中文，见 §5），但中文不可缺。
3. **字符串不拼接**：禁止 `前缀 + 变量 + 后缀` 拼界面文案（中英文语序不同）；用占位符 `{name}` 整体入包。
4. **语言范围**：当前支持 `zh-CN` / `en`；新增语言时只加语言包文件，不改业务代码。

## 2. 文案接入硬规则

- 所有用户可见文本（按钮/菜单/标题/占位符/提示/tooltip/空态/错误提示/对话框/检查报告文案）必须走 `t()`。
- 开发日志、`console.*`、`syncLog`、debug 面板文本**不属于**界面文案，可保留中文，不抽键（清单扫描器已自动剔除）。
- 图谱渲染、Markdown 渲染中的**用户文档内容**不是界面文案，不抽键。
- 文件路径、`id`、标签名、语言代码等标识符不抽键。
- 含参数的文案用 `{参数名}` 占位：`t('toast.fileSaved', { name: 'x.md' })`；包内值如 `文件已保存：{name}` / `File saved: {name}`。

## 3. 键命名与语言包结构（目标布局）

**键命名**：小写点分路径，第一段为区域前缀，逐级语义化；同一区域的键在文档清单里彼此相邻便于审阅。

```
app.status.kbLoaded        → 状态栏「已加载知识库」
toolbar.save               → 工具栏「保存」
menu.tree.rename           → 文件树右键「重命名」
settings.display.lang      → 设置-显示「界面语言」
check.badge.pass           → 检查徽标「检查通过」
toast.fileSaved            → 提示「文件已保存：{name}」
```

**语言包结构（目标路径，落地时建立）**：

```
src/memoria/ui/static/app/
├─ i18n/
│  ├─ zh-CN.js          # 中文包（源语言，必全）
│  └─ en.js             # 英文包
└─ js/
   └─ i18n.js           # 引擎：t(key, params)、getLang/setLang、加载 zh/en、
                        # 缺失回退、切换后派发重新渲染
```

**加载顺序**：`zh-CN.js` → `en.js`（按需）→ `i18n.js`（选择当前语言）。语言偏好持久化于本地设置（`ui-settings`，配置键约定 `ui.lang`），首次启动默认 `zh-CN`。

## 4. 语言包文件格式

每个包导出一个扁平或树状对象（推荐树状便于审阅）：

```js
// i18n/zh-CN.js
window.MEMORIA_LOCALES = window.MEMORIA_LOCALES || {};
window.MEMORIA_LOCALES["zh-CN"] = {
  app: { status: { kbLoaded: "已加载知识库" } },
  toolbar: { save: "保存" },
  toast: { fileSaved: "文件已保存：{name}" },
};
```

引擎取值支持点路径；`en` 包缺键时回退 `zh-CN`，`zh-CN` 缺键回退键名本身（便于发现）。

## 5. 缺失键回退（已确认策略）

- 查找顺序：当前语言 → `zh-CN` → 键名本身。
- 回退行为保证：**英文翻译未完备时界面永远显示中文**，功能文案不会因缺英文而空白/报错。
- 英文包完成度以清单文档「状态」列跟踪（`☐ 未迁移` → `✔ 已迁移`）。

### 5.1 后端检查消息的本地化（方案 1）

后端生成的问题行（如检查报告里的逐条 issue）遵循"中文保留 + code/params 双发"约定，避免中文在前后端两处漂移：

- **后端**：每条 issue 始终携带中文 `message`（zh 界面/CLI/未知 code 的事实源），并附稳定 `code` 与结构化 `params`；`code` 即 en 模板 `check.issue.<code>` 的键后缀，`params` 仅供英文模板占位。
- **语言包**：中文**不**复制进 `zh-CN.js`；英文模板写入 `en.js` 的 `check.issue.<code>`。
- **前端渲染**：当前语言 ≠ zh-CN 且当前语言包含该 code 的模板时用 `t('check.issue.<code>', params)`，否则原样显示后端中文 `message`（未知 code 永不空白）。
- CLI 等不经过前端语言包的直接打印仍使用后端 `message`，零改动。

## 6. 新增 UI / 文案的标准流程

1. 写界面时用 `t('area.key', {…})`，不写中文字面量；
2. 到 `zh-CN.js` / `en.js` 补两个键值；
3. 区域前缀若为新域，按 §3 登记；
4. 运行 `python scripts/scan_ui_strings.py` 刷新 [i18n-inventory.md](../reference/i18n-inventory.md)，并把对应文件状态置「✔ 已迁移」（或在该文件「迁移记录」表登记一行）；
5. 涉及检查报告/导入消息等后端文案时，按 §5.1 约定：后端中文 `message` + 稳定 `code`/`params` 双发；英文模板写入 `en.js` `check.issue.<code>`；前端渲染点走"当前语言有 code 则翻译、否则回退中文 message"的 localize 助手（前端 `localizeCheckIssue`）。

## 7. 语言切换（已确认交互规格，落地项）

- 入口：设置 → 显示 → 「界面语言」（`zh-CN` / `en`）。
- 生效：选择后**即时生效**并重渲染当前界面（不重启），同时持久化到本地设置。
- 实现要点：切换后需对当前可见 DOM 中带 `data-i18n` 的静态节点与动态区域做一次文案刷新；动态 toast/对话框类由渲染时取 `t()` 天然跟随。

## 8. 维护检查清单（自查/评审用）

- [ ] 新增文案没有中文字面量直出到界面（允许出现在 zh-CN 包与注释/日志）；
- [ ] 键已按区域前缀命名且点路径唯一；
- [ ] 中文包已补、英文包尽力补（缺则回退中文可接受）；
- [ ] 含参数文案使用了 `{param}` 占位而非字符串拼接；
- [ ] 清单已刷新、迁移状态已更新；
- [ ] 语言包文件通过 `node --check`，无语法错误。
