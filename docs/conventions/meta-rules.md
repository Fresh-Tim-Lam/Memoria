# AAA 讨论元规范 -v0.1

> **用途**：定义"如何讨论和制定项目规范"的元规则。确保规范讨论有结论、可验证、不空洞。
> **目标读者**：项目负责人（用户）与 AI Agent（执行者）。
> **关联文档**：[collaboration.md](../guides/collaboration.md) — 本规范的下游，定义具体开发场景的规则。

---

## 规则 1：即时落盘，同步认知

**触发条件**：每当一次讨论产生明确结论（采纳/拒绝/暂缓）时。

**约束对象**：双方（用户 + Agent）

**规则内容**：
1. **用户职责**：讨论结束后**立即**更新对应的规范文档，或在对话中明确指示 Agent 更新。
2. **Agent 职责**：在每次响应前，扫描本文件及关联规范文档的最新内容，确保回答基于最新共识。当规范被更新时，Agent 必须输出一条确认信息，格式为：
   ```
   [上下文已同步] 规则 xxx 已更新（yyyy-mm-dd HH:MM）
   ```
3. **时效要求**：任何规范变更必须在 1 次对话轮次内落地到文档。不允许"之后再补"。

**可验证性**：抽查规范文档的更新时间戳，与讨论结论达成的时机对比。超过 1 轮未更新视为违反。

**违反后果**：
- 轻度（1 轮内未更新）：当前讨论暂停，先完成更新。
- 重度（跨对话未更新）：该条结论视为未生效，需重新讨论确认。

## 规则 2：结论必有标记

**触发条件**：任何讨论议题产生初步判断时。

**约束对象**：双方（用户 + Agent）

**规则内容**：
1. 每个议题的最终状态必须显式标记为以下三者之一：
   - `✅ 采纳` — 规则已定稿，写入规范文档
   - `❌ 不采纳` — 明确否决，记录理由
   - `⏳ 暂缓` — 等待前置条件，注明阻塞项
2. 标记必须在当轮对话结束前给出。未标记的议题视为"未关闭"，进入下轮讨论。

**可验证性**：回溯对话记录，检查每个讨论过的议题是否有标记。无标记即违反。

**违反后果**：
- 轻度：Agent 在下一轮开始时主动追问标记。
- 重度：该议题结论视为无效，需要重新讨论。

## 规则 3：规则依附场景

**触发条件**：新增或修改任何规范条目时。

**约束对象**：双方（用户 + Agent）

**规则内容**：
1. 每一条规范必须关联到至少一个**具体的开发场景**（如：模块开发、测试编写、Bug 修复等）。
2. 纯抽象的、不落地到场景的规则不允许写入规范文档。
3. 场景的命名采用 `[场景名]` 前缀标记在规则标题中。

**可验证性**：检查规范文档中的每条规则，其标题或说明中是否包含场景标记。无标记即违反。

**违反后果**：
- 该规则暂不生效，退回补充场景关联。直到场景补充完成之前，不在规范约束范围内。

## 规则 4：文档首行释用途

**触发条件**：创建或修改任何规范文档时。

**约束对象**：双方（用户 + Agent）

**规则内容**：
1. 每份规范文档的第 1-3 行必须直接说明本文档的**用途**、**目标读者**、**与其它规范的关系**。
2. 格式示例：
   ```
   # AAA 讨论元规范
   > 用途：定义"如何讨论和制定规范"的规则。约束对象为项目负责人与 AI Agent。
   > 关联文档：AI 编程协作规范（本规范的下游，定义具体开发场景的规范）
   ```
3. 禁止使用"详见xxx"作为用途说明——用途说明本身必须独立可读。

**可验证性**：打开文档前 3 行，检查是否包含用途、读者、关联三项。缺一项即违反。

**违反后果**：
- 该文档未完成，不得作为正式规范引用，直到用途说明补齐。
