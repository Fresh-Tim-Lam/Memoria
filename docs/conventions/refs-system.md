# 参考资料系统规范 -v0.1

> **用途**：定义项目参考资料库（references/）的使用规范，确保 AI 协作时技术知识的引用准确、可追溯、可验证。
> **目标读者**：项目负责人（用户）与 AI Agent。
> **关联文档**：[meta-rules.md](./meta-rules.md) — 本规范遵循的元规则；[context-key.md](./context-key.md) — CTX-KEY 防火墙机制；[collaboration.md](../guides/collaboration.md) — 具体开发场景规范。

---

## 1. 定位

参考资料系统是独立于开发场景的**知识基础设施**，与上下文规范平级。它的作用是：

- 为 AI 提供可靠的技术知识来源（MuJoCo API、Gymnasium 接口、URDF 格式等）
- 便于用户查证 AI 输出的技术依据
- 作为 CTX-KEY 的散布区域之一

## 2. 规则

### 规则 1：参考资料为辅助，不强制依赖

| 项目 | 内容 |
|------|------|
| 约束对象 | 双方 |
| 说明 | AI 可基于参考资料学习，但与训练数据冲突时需注意版本差异。用户指定的资料优先于 AI 训练数据中的记忆，但 AI 可指出资料版本可能过时并建议更新 |

### 规则 2：AI 必须标注引用出处

| 项目 | 内容 |
|------|------|
| 约束对象 | Agent |
| 说明 | AI 引用参考资料时，必须标注出自哪份资料的第几节/第几页，便于用户定位查证。格式示例：`[引用: references/api_docs/mujoco.html §2.3]` |

### 规则 3：CTX-KEY 可嵌入参考资料

| 项目 | 内容 |
|------|------|
| 约束对象 | 双方 |
| 说明 | 用户可在参考资料中嵌入 `[CTX-KEY:xxx]`。AI 引用相关资料时，若发现 CTX-KEY 则纳入输出范围。工作流程：AI 在回答中标注引用位置 → 用户通过 IDE 搜索 `[CTX-KEY:xxx]` 定位 → 核对 |

### 规则 4：AI 可主动补充资料

| 项目 | 内容 |
|------|------|
| 约束对象 | Agent |
| 说明 | AI 可在用户授权下自行查询官方文档并整理存入 `references/`，或指示用户去查询某份资料。新增资料需注明来源 URL 和获取日期 |

## 3. 目录结构（参考）

```
📁 references/
├── 📁 papers/          # 论文笔记
├── 📁 api_docs/        # 关键库/工具官方文档摘录
├── 📁 design_notes/    # 设计决策记录、架构笔记
├── 📁 tutorials/       # 外部教程本地存档
├── 📁 specs/           # 技术规范
└── README.md           # 索引
```

参考资料无严格格式限制，但推荐每份资料开头注明：来源、日期、版本（如适用）。

## 4. 与其它规范的协作关系

| 规范 | 关系 |
|------|------|
| 上下文规范 | 参考资料可作为 CTX-KEY 的散布区，增加防火墙覆盖密度 |
| AI 编程协作规范 | 在模块开发中，AI 引用资料标注出处；在 Bug 修复中，AI 可查阅官方 API 文档辅助定位 |
