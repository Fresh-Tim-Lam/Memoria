# 显示 + 编辑子系统 · 重构宪章

> **目标（人 2026-10-19 明确）**：**彻底重构，然后「鸠占鹊巢」——新实现接管旧实现的位置，旧代码删除，
> 功能一致（用户界面与交互无感知变化）**。这不是修 bug，也不是加补丁。
> **本文用途**：让人能读懂「痛点是什么、牵涉哪些功能、牵涉哪些交互、验收怎么算过」。
> 内部实施细节见 [render-refactor-battlemap.md](render-refactor-battlemap.md)（阶段/契约编号），本文只管**人话**。

## 1. 现在的痛点（用户视角 + 实测依据）

| # | 痛点 | 用户怎么说 | 技术根因（已取证） |
|---|---|---|---|
| P1 | **打开大文档慢** | 教材打开要等 | 整篇 parse→render 一次做完；一篇教材 ~2,850 个行内公式 ⇒ ~25 万 DOM 节点，首开 1–2 s |
| P2 | **打字卡顿** | 编辑时一顿一顿 | 每次按键都做**整篇**操作：`spliceBlockSource` 全篇 split/join、`logCursorContext` 全篇属性选择器扫描 |
| P3 | **切页签慢 / 切回来重算** | 来回切要重新渲染 | 切回重进 parse/render/MathJax；预览 DOM 池的**判据曾错位**（编辑过的文档永远进不了池，命中率恒 0%） |
| P4 | **编辑与预览对不齐** | 光标位置、跳转落点偏 | 存在**三套坐标口径**（正文行 / 源文件行 / 文件行），互相换算；有序列表列号、表格整块、frontmatter 偏移都在这类边界出错 |
| P5 | **跳转/锚点不准** | 点了没反应或跳错 | 重命名后导航栈不重映射；导航失败不回滚；树内点击会丢掉前进历史 |
| P6 | **预览区能编辑，但没有「块身份」** | —— | 块只有**位置下标**（第几个块），没有稳定 id ⇒ 任何块级增量更新都可能错位 |
| P7 | **新老两套并存** | —— | 显示子系统接口层（`surface/registry.js` + `legacy-surface.js`）已实现并注册，但 `app.js` 明写「不迁移任何调用路径」⇒ **接口空转、无消费者**；新核心 `RenderCore` / `EditSurface` / 高度账本**都不存在** |
| P8 | **内存** | 大库开久了占内存 | 预览池最多 8 条，每条约 25 万节点 |

**为什么必须「重构」而不是修**：P2/P4/P6 是同一个根因——**没有一个稳定的「块」概念**。
只要块没有身份，增量重渲、光标映射、冻结判定、滚动定位都只能靠「位置推算」，修一处漏一处。
所以真正的重构起点是：**给块建立身份，让渲染/编辑/映射都围绕块运行**。

## 2. 牵涉的功能（重构必须保持一致的清单）

### A. 文档打开与视图
- 三视图切换：预览 / 源码 / 分栏
- 首屏渲染 + 加载态（`.-preview-loading`）
- 打开文件后的滚动位置恢复 / 跳转落点

### B. 渲染管线
- Markdown → normalize → 解析 → 渲染 → 块行标记 → Mermaid → MathJax 公式
- 表格、代码块、公式块、图片、引用、列表（有序/无序、嵌套）
- 公式渲染组件（当前 SVG）

### C. 编辑
- **源码区编辑**：行结构、文本输入、选区、Home/End、Tab、回车/退格、撤销重做、粘贴复制、光标与选区恢复
- **预览区块编辑**：双击进入块编辑、块工具栏、图片块单击进编辑、画笔连续涂抹
- **格式工具栏**：加粗/斜体/标题/列表/引用/代码/公式等
- **保存**：自动防抖写盘、写冲突处理（版本令牌 + 覆盖前备份 + 三选一弹窗）

### D. 同步映射（编辑 ↔ 预览）
- 三种坐标互转：正文行 ↔ 源文件行 ↔ 文件行
- 光标位置 ↔ 预览块位置
- 选区 ↔ 预览范围（高亮带）
- 反向：点击预览定位到源码、拖拽选文字建链接

### E. 导航
- 文件树点击切文件、标签页（多开/关闭/切换）
- 前进 / 后退（导航栈 + 文件指针）
- 跳转落点：知识点、指定行号、`[[链接]]`、检查面板错误高亮、搜索命中
- 跳转失败时的降级与可见提示

### F. 知识点（KP）
- KP 列表、hover 高亮
- KP 弹窗五页（范围 / 标识 / 标签 / 边 / 保存删除重命名）
- 范围的两种语义（跳转高亮 vs 静默锚定）
- 待确认（pending）流

### G. 缓存与预加载
- 预览 DOM 池（智能替换：评分/老化/入场闸）
- 后台预加载（可开关）
- 导航预测器
- 设置 → 显示 → 性能（读数、权重、恢复默认）

### H. 其他渲染产物
- 公式导出（`svg.fontCache="local"` 路径）
- 图片（插入/管理/属性/诊断）
- 引用区折叠（刚加）

## 3. 牵涉的交互（重构不得改变的手感）

| 类别 | 具体交互 |

| 鼠标 | 单击切文件 / 双击进块编辑 / 图片单击进编辑 / 右键菜单（树、预览）/ 悬停高亮 |
| 键盘 | 文本输入、方向键、Home/End、Tab、Enter/Shift+Enter、Backspace/Delete、F2 重命名、快捷键（格式/撤销重做/保存） |

| 折叠 | 引用区展开/收起 |

## 4. 「鸠占鹊巢」的具体含义

**现在**（旧实现，要整体替换）：

| 模块 | 行数 | 职责 |
|---|---|---|
| `app.js` | 14,476 | 巨型 IIFE：渲染调度、编辑、导航、缓存、设置……全都在这 |
| `edit-handler.js` | 1,994 | 预览区编辑 |
| `markdown-preview.js` | 2,358 | 侧栏辅助预览（主预览不走它） |
| `mapper.js` / `lexer.js` / `parser.js` / `renderer.js` / `ast.js` | ~3,160 | 解析与坐标映射 |

**重构后**（新核心接管，旧路径删除）：

```
新核心
├── RenderCore      只读渲染核心：文档 → 块树（每块有稳定 id）→ DOM；负责高度账本
├── EditSurface     可编辑面：输入 / 光标 / 选区 / 撤销栈；通过「块 id」与渲染核心通信
└── 挂载点          只保留装配代码；旧的整篇 parse/render、位置推算映射、脏标记判据全部删除
```

**所谓「占巢」**：新核心**取代** `app.js` 里渲染/编辑/映射那一大坨的位置，
外部（文件树、标签页、知识点、对话面板）看到的接口**不变**，内部被整体换掉。

## 5. 验收：功能一致性怎么算过

不是「测试通过就算过」，而是**三件事同时满足**：

1. **§2 的功能清单逐条可用**（人按清单点一遍，行为与现在一致）；
2. **§3 的交互清单逐条手感不变**（尤其：切页签不重算、打字不卡、跳转落点准、光标不错位）；
3. **§1 的痛点 P1–P3 有可测改善**（用 `benchmark-measurement-protocol.md` 的三态判据，大库实测）。

> 反面标准（明确不算过）：
> - 只加了接口、旧路径还在跑（那就是今天的 P7，等于没重构）；
> - 功能少了几项（例如预览区不能编辑了）；
> - 手感变了（例如切页签变慢）——**任何一项手感退化都算失败**。
