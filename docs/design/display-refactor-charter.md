## 1. 现在的痛点（用户视角 + 实测依据）

| # | 痛点 | 用户怎么说 | 技术根因（已取证） |
|---|---|---|---|
| P1 | **打开大文档慢** | 教材打开要等 | 整篇 parse→render 一次做完；一篇教材 ~2,850 个行内公式 ⇒ ~25 万 DOM 节点，首开 1–2 s |
| P2 | **打字卡顿** | 编辑时一顿一顿 | 每次按键都做**整篇**操作：`spliceBlockSource` 全篇 split/join、`logCursorContext` 全篇属性选择器扫描 |
| P3 | **切页签慢 / 切回来重算** | 来回切要重新渲染 | 切回重进 parse/render/MathJax；预览 DOM 池的**判据曾错位**（编辑过的文档永远进不了池，命中率恒 0%） |
| P4 | **编辑与预览对不齐** | 光标位置、跳转落点偏 | 存在**三套坐标口径**（正文行 / 源文件行 / 文件行），互相换算；有序列表列号、表格整块、frontmatter 偏移都在这类边界出错 |
| P5 | **跳转/锚点不准** | 点了没反应或跳错 | 重命名后导航栈不重映射；导航失败不回滚；树内点击会丢掉前进历史 |
| P6 | **预览区能编辑，但没有「块身份」** | —— | 块只有**位置下标**（第几个块），没有稳定 id ⇒ 任何块级增量更新都可能错位 |
| P7 | **新老两套并存** | —— | 显示子系统接口层（`surface/registry.js` + `legacy-surface.js`）已实现并注册，但 `app.js` 明写「不迁移任何调用路径」⇒ **接口空转、无消费者**；新核心 `RenderCore` / `EditSurface` / 高度账本**都不存在** |
| P8 | **内存** | 大库开久了占内存 | 预览池最多 8 条，每条约 25 万节点 |

**为什么必须「重构」而不是修**：P2/P4/P6 是同一个根因——**没有一个稳定的「块」概念**。
只要块没有身份，增量重渲、光标映射、冻结判定、滚动定位都只能靠「位置推算」，修一处漏一处。
所以真正的重构起点是：**给块建立身份，让渲染/编辑/映射都围绕块运行**。

## 2. 牵涉的功能（重构必须保持一致的清单）

### A. 文档打开与视图
- 三视图切换：预览 / 源码 / 分栏
- 首屏渲染 + 加载态（`.-preview-loading`）
- 打开文件后的滚动位置恢复 / 跳转落点

### B. 渲染管线
- Markdown → normalize → 解析 → 渲染 → 块行标记 → Mermaid → MathJax 公式
- 表格、代码块、公式块、图片、引用、列表（有序/无序、嵌套）
- 公式渲染组件（当前 SVG）

### C. 编辑
- **源码区编辑**：行结构、文本输入、选区、Home/End、Tab、回车/退格、撤销重做、粘贴复制、光标与选区恢复
- **预览区块编辑**：双击进入块编辑、块工具栏、图片块单击进编辑、画笔连续涂抹
- **格式工具栏**：加粗/斜体/标题/列表/引用/代码/公式等
- **字体样式应用**：选中后经**右键菜单**（B/I/高亮▾/字色▾）或**工具栏**应用；写入是**块级重生成**（`SourceGen.generateBlock` 整块替换），单块撤销 1 单元、跨块 `beginUndoGroup` 合 1 单元
- **样式 hover 预览**：`.-hl-swatch`/`.-fc-swatch` 的 `mouseenter` 在选区上临时包 `<span>` 预览颜色（**仅颜色有，B/I 无，自定义色也无**）
- **样式画笔**：`_brush{bold,italic,highlight,fontcolor}` 多槽累加 → `body.-brush-active` → 预览区 mouseup 时按固定序 B→I→H→色应用（每步重取实时选区）→ 保持武装可连续涂抹；右键取消点到的槽位、Esc 全退
- **保存**：自动防抖写盘、写冲突处理（版本令牌 + 覆盖前备份 + 三选一弹窗）

### D. 同步映射（编辑 ↔ 预览）
- 三种坐标互转：正文行 ↔ 源文件行 ↔ 文件行
- 光标位置 ↔ 预览块位置
- 选区 ↔ 预览范围（高亮带）
- 反向：点击预览定位到源码、拖拽选文字建链接

### E. 导航
- 文件树点击切文件、标签页（多开/关闭/切换）
- 前进 / 后退（导航栈 + 文件指针）
- 跳转落点：知识点、指定行号、`[[链接]]`、检查面板错误高亮、搜索命中
- 跳转失败时的降级与可见提示

### F. 知识点（KP）
- KP 列表、hover 高亮
- KP 弹窗五页（范围 / 标识 / 标签 / 边 / 保存删除重命名）
- 范围的两种语义（跳转高亮 vs 静默锚定）
- 待确认（pending）流

### G. 缓存与预加载
- 预览 DOM 池（智能替换：评分/老化/入场闸）
- 后台预加载（可开关）
- 导航预测器
- 设置 → 显示 → 性能（读数、权重、恢复默认）

### H. 其他渲染产物
- 公式导出（`svg.fontCache="local"` 路径）
- 图片（插入/管理/属性/诊断）
- 引用区折叠（刚加）

## 4. 「鸠占鹊巢」的具体含义

> **范围已由人确认（2026-10-20）：只换「文件显示区域」** ——
> 即**渲染 + 预览 + 编辑 + 同步映射 + 与之绑定的缓存/预加载**这一块。
> **文件树 / 标签页 / 知识点面板 / 图谱面板 本体不动**。
> **但跨域接口必须保持**：知识点面板与图谱的「悬停高亮」依赖渲染层给出的块/范围定位，
> 新核心必须继续提供同等的「按范围/按块定位 + 高亮」能力（接口可换，行为不可变）。

**现在**（旧实现，要整体替换）：

| 模块 | 行数 | 职责 |
|---|---|---|
| `app.js` | 14,476 | 巨型 IIFE：渲染调度、编辑、导航、缓存、设置……全都在这 |
| `edit-handler.js` | 1,994 | 预览区编辑 |
| `markdown-preview.js` | 2,358 | 侧栏辅助预览（主预览不走它） |
| `mapper.js` / `lexer.js` / `parser.js` / `renderer.js` / `ast.js` | ~3,160 | 解析与坐标映射 |

**重构后**（新核心接管，旧路径删除）：

```
新核心（只接管「文件显示区域」）
├── RenderCore      只读渲染核心：文档 → 块树（每块有稳定 id）→ DOM；负责高度账本
├── EditSurface     可编辑面：输入 / 光标 / 选区 / 撤销栈；通过「块 id」与渲染核心通信
└── 挂载点          只保留装配代码；旧的整篇 parse/render、位置推算映射、脏标记判据全部删除
```

**所谓「占巢」**：新核心**取代** `app.js` 里渲染/编辑/映射那一大坨的位置，
外部（文件树、标签页、知识点、对话面板、图谱）看到的接口**不变**，内部被整体换掉。

**切换策略（人已定 2026-10-20）**：重构期间**允许新老并存、可切换**（对照验证）；
**直到确定落地才 commit，然后删除旧代码**——不搞「先删后补」。

## 5. 验收：功能一致性怎么算过

不是「测试通过就算过」，而是**三件事同时满足**：

1. **§2 的功能清单逐条可用**（人按清单点一遍，行为与现在一致）；
2. **§3 的交互清单逐条手感不变**（尤其：切页签不重算、打字不卡、跳转落点准、光标不错位）；
3. **§1 的痛点 P1–P3 有可测改善**（用 `benchmark-measurement-protocol.md` 的三态判据，大库实测）。

> 反面标准（明确不算过）：
> - 只加了接口、旧路径还在跑（那就是今天的 P7，等于没重构）；
> - 功能少了几项（例如预览区不能编辑了）；
> - 手感变了（例如切页签变慢）——**任何一项手感退化都算失败**。

## 5.1 交互怎么测：自动化覆盖什么、人工兜底什么（2026-10-20 定）

**结论：不需要任何插件。** 现有 `scripts/benchmark/surface/cdp.mjs` 走的是 CDP `Input` 域，
浏览器把它当**真实输入**处理（`isTrusted=true`，与我们现在的 `typeText` 同一条路）。

### 已有能力（可直接用）
- `Input.dispatchKeyEvent`（keyDown + keyUp，带 `text`）⇒ 真实 `keydown` / `beforeinput`
- `typeText(text)`：逐字符受信任输入；`pressKey(key)`：命名键（Enter/Esc/方向键等）
- `realClick(selector)`、`Page.captureScreenshot`（可做视觉回归）

### 需要补的三块（都在 cdp.mjs 里加，不加依赖）
| 缺口 | 加什么 | 用来测 |
|---|---|---|
| **鼠标拖拽** | `Input.dispatchMouseEvent`：`mousePressed` → 多次 `mouseMoved` → `mouseReleased` | 拖拽选区（跨行/跨块）、拖选建链接 |
| **双击选词** | 同上，`clickCount: 2` | 双击选英文单词 |
| **修饰键** | 按键/鼠标事件加 `modifiers` 位掩码（Alt=1 Ctrl=2 Meta=4 **Shift=8**） | Shift+方向扩选、Shift+Home/End、Ctrl+A |
| **中文输入** | `Input.imeSetComposition` + `Input.insertText` | IME 组合输入（纯键事件的盲区，必须专门加） |

### 断言层（测「有没有做到」）
1. **选区状态**：`window.getSelection()` 的 `anchorNode/anchorOffset/focusNode/focusOffset/toString()`
   —— 精确断言「选中的是哪个字到哪个字」；
2. **选区可视状态**：选区高亮类/样式是否出现、范围是否正确；
3. **金标准快照**：同一操作序列，对**新老两套实现**分别抓「可见 DOM 结构 + 选区 + 焦点」并 diff。
   —— 这正是「重构期间允许新老并存」的直接用途：**同一剧本跑两条路，结果必须一致**。

### CDP 做不到的（必须人工验收，写清别假装覆盖）
- 操作系统级 **IME 候选窗 / 真实输入法行为**（只能模拟 composition 序列，不是真输入法）；
- 从资源管理器**拖文件进窗口**（OS 级拖放）；
- 触控板**惯性滚动**、真实触摸；
- **真实剪贴板**（除非授 `Browser.grantPermissions`，且仍受系统剪贴板影响）。

⇒ **策略**：自动化覆盖「可模拟的交互」（点击/双击/拖拽选区/键盘扩选/输入/滚动/切页签），
**人工兜底不可模拟项**（IME、OS 拖拽、惯性滚动）。两者的结果都记进验收记录。

**已落地（2026-10-20）**：三件套 `scripts/benchmark/surface/{interaction.mjs, run_interaction.py, scenarios/interactions.json}`，
11 个剧本覆盖 §3 的选区与样式交互；**已在旧实现上产出金标准**（连跑两次 11/11 快照完全一致 ⇒ 可重现）。
用法见 `scripts/benchmark/surface/README.md`「交互契约测试」一节。
实测三个坑（已写进代码）：`mouseMoved` 必须带 `button:'left'`；跨块两点须同时在视口内；应用启动会异步自动开默认文件，须先等 `currentPath` 稳定。

## 5.2 必保接口（跨域契约，重构不得弄丢）
