**A. 编辑器输入（格式 / 光标 / 空白）**

- **E24 · 表格内无法应用字体颜色 / 加粗 / 斜体** —— 建议 **P2**
  - **现象（用户原话）**：「格式编辑不完善，表格内字体颜色 - 内加粗斜体」。
  - **客观描述**：预览区表格单元格内的文字无法通过工具栏（或选区样式命令）应用字色/加粗/斜体；表格属不可编辑块，样式选区提取路径也不认识表格结构。
  - **影响面**：预览区（富文本）→ 表格块；样式工具条对该选区不生效；是否可用源码区手写 `[[\c:…|…]]` 绕过待验证。
  - **验收判据**：预览表格单元格内选中文字 → 应用字色/加粗/斜体 → 对应单元格源码出现 `[[\c:…|…]]` / `[[\b|…]]` / `[[\i|…]]`，预览立即生效，保存后重开仍在；同格可叠加与取消。
  - **定位线索**：表格在不可编辑块集合内 —— `app.js:9732`（`NON_EDITABLE` 含 `table`）、`edit-handler.js:570`（同）；样式选区提取 `_extractSelectionMiddle()` 只对 `list` / `blockquote` 下钻、无 `table` 分支 `app.js:11318-11360`；表格编辑入口仅有 i18n 键 `edit.block.editTable`（`edit-handler.js:1215`，事件未接）。**结论：被 E02 阻塞，E02 不落地则本条无法闭环。**

- **E26 · 换行后光标不跟随滚动** —— 建议 **P1**
  - **现象（用户原话）**：「bug: 换行不会自动跟随光标移动 滚条」。
  - **客观描述**：回车产生新行后，滚动条/视口不跟随光标下移，光标可停在视口外，需手动滚动才能继续输入（长文档尤甚）。
  - **影响面**：源码区逐行 contenteditable 的 Enter 路径与预览区富文本编辑的 Enter 路径（两处是否都缺需真机确认）。
  - **验收判据**：把光标置于可见区最后一行 → 按 Enter（源码区 / 预览区 / 分栏各一次）→ 新行进入视口、光标可见、滚动条随之下移；连续 Enter 10 次不出现「光标跑出视口需手滚」。
  - **定位线索**：全仓无「编辑后保持光标可见」实现 —— `scrollIntoView` 只用于预览跳转/文件树定位（`app.js:13549`、`app.js:13576`、`file-tree.js:543`）；源码区 `input` 仅同步+标脏（`app.js:7429-7452`），Enter 插行后只 `setStart` 选区不滚（`app.js:7800-7810`）；预览 `commitRange` 只在 `repaintPreview().then` 里 `restoreCursor`（`app.js:10579-10581`）。**具体缺失点未定位**（需真机确认是源码区、预览区还是两处都缺）。

- **E27 · 样式文字末尾无法输入空格** —— 建议 **P1**
  - **现象（用户原话）**：「样式文字末尾无法输入空格」。
  - **客观描述**：在带样式的文字（字色/加粗/斜体等 `[[\…|…]]`）末尾输入空格时，空格不进入内容；疑似被内联边界或行尾空白处理吞掉。
  - **影响面**：预览区富文本编辑中的样式节点尾部；行内公式/链接等内联原子边界可能同症（待验）。
  - **验收判据**：在 `[[\b|abc]]` 末尾（`]]` 之前）连续输入两个空格 → 源码保存为 `[[\b|abc  ]]`（或样式节点外的等价尾随空格）且重开仍在；空格后再打字不丢空格。
  - **定位线索**：**parser / source-gen 往返已排除** —— 探针 `artifacts/agent/verify/probe-parser-roundtrip-2026-10-22.js` 显示 `[[\c:#f00|abc ]]` 解析→回写结果 SAME、AST 文本保留尾随空格。剩余怀疑点 = 预览 DOM 编辑态「光标停在样式节点末尾」的偏移换算（`mapper.js` 的 `domToAst` / `renderedToSrcCol`）与 `commit → restoreCursor` 边界；需真机配合 `keys-debug`（`localStorage["-keys-debug"]="1"`）定位是 beforeinput 未收到、`insertText` 返回 false，还是进了源码又被重渲吃掉。

- **E29 · 预览区英文单词后无法输入空格** —— 建议 **P1**
  - **现象（用户原话）**：「预览区域英文单词后面没办法输入空格」。
  - **客观描述**：在预览区英文/ASCII 词后输入空格无效（中文词后是否同样，用户未报）。
  - **影响面**：预览区富文本编辑；英文写作/中英混排场景。
  - **验收判据**：预览区英文单词后输入空格 → 空格进入源码（保存可见 `word `）、光标前进一格；连续两次空格不吞；中文词后同测通过。
  - **定位线索**：**未定位**。parser 往返保真已排除（同上探针 `hello ` 往返 SAME）；疑与 E27 同根因（内联边界/行尾空白的 DOM↔AST 偏移），建议**两条一起定位**，但**分别验收**（现象与影响面不同）。

**B. 预览渲染（Markdown 前缀往返）**

- **E28 · 预览区 `>` 后无法按空格** —— 建议 **P1**
  - **现象（用户原话）**：「预览区域 `>` 后面没有办法按空格」。
  - **客观描述**：在行首输入 `>` 后再按空格，空格被当作引用块标记的一部分吸收，内容里得不到该空格（后续文字会被渲染进引用块）。
  - **影响面**：预览区富文本编辑 → 段落行首（`>` 在行中/行尾不受影响）。
  - **验收判据**：在预览区空段落行首输入 `>` 再输入空格 → 空格可见且保存后源码为 `> `（`>` 与正文之间恰一个空格），不出现「空引用块」；继续输入文字得到 `> 文字`；引用块内再输入空格正常。**若产品期望「`> ` 立即转为引用块」，需用户先确认语义**（当前无此自动转换）。
  - **定位线索（探针已复现）**：`lexer.js:99-109` 的前缀正则 `^(\s*)(>\s?)` 把 `>` 后的**至多一个空格**吞进 `blockquote_prefix`；`parser.js:482-494` 只要有 `blockquote_prefix` 就整行转 blockquote、正文只剩前缀之后；`source-gen.js:70-73` 回写引用块恒为 `"> " + 正文`；而 `detectStructuralMarker()`（`app.js:10449-10458`）**不含 `>`** ⇒ 输入 `>` 时不会立刻转换，等下一次重解析才被吸收。探针输出：`">" → 回写 "> "`，AST 变成 `blockquote > paragraph(空)`（见 `probe-parser-roundtrip-2026-10-22.js` 输出）。

**C. 复制粘贴**

- **E25 · Ctrl+V 粘贴图片无效** —— 建议 **P1**
  - **现象（用户原话）**：「没有办法直接 ctrl+v 复制图片到文本编辑区域，复制会被浏览器拦截提示是否复制」。
  - **客观描述**：剪贴板只有图片（截图/图片文件）时，在文本编辑区 Ctrl+V 不会插入图片，粘贴被静默吞掉；用户另提到会出现「浏览器拦截/询问」提示（**该提示的确切触发点原话存疑，待用户确认是 Ctrl+V 还是右键「粘贴」时出现**）。
  - **影响面**：源码区 / 预览区粘贴路径；图片入库链路（注册表/去重）。
  - **验收判据**：剪贴板为截图或图片文件时，在源码区与预览区分别 Ctrl+V → 图片按既有图片资产链路入库（去重、注册表）并插入 `![](...)`；纯文本粘贴行为与现在一致；不出现需要用户额外授权的剪贴板弹窗（若平台强制授权，须有可读提示与一次授权后不再询问）。
  - **定位线索**：两处 paste 处理器只读 `text/plain` 且命中即 `preventDefault` —— 源码区 `app.js:7821-7831`（→ `applyEditorPaste` `7839+`）、预览区 `app.js:11936-11948`（→ `pasteTextAtCursor` `11892-11913`）；全仓**无** `clipboardData.files/items` 的图片分支（对话栏已有图片粘贴可作参照：`agent-panel.js:6248`、`agent-panel.js:6537`）。「浏览器询问」疑与右键粘贴走 `navigator.clipboard.readText()`（`app.js:7927`、`app.js:11919`；WebView2 会弹剪贴板权限询问）有关 —— **原话存疑，需用户确认操作路径**。

- **E30 · Ctrl+X 后再粘贴，剪切内容重现** —— 建议 **P0（数据正确性）**
  - **现象（用户原话）**：「bug: crtl+x 之后再粘贴，剪切的内容会重现」。
  - **客观描述**：在预览区选中文字按 Ctrl+X 后文字从画面消失，但随后 Ctrl+V（或任何触发重渲染的操作）会让被剪切内容重新出现，可能与粘贴内容并存 ⇒ **重复/残留正文**（静默数据污染）。
  - **影响面**：预览区富文本编辑的剪贴板路径（源码区是否同样待真机确认）；任何触发重渲染的动作（编辑、切视图、切文件、保存重开）。
  - **验收判据**：预览区选中一段 → Ctrl+X（文字消失）→ 别处 Ctrl+V → 被剪切文字**只**出现在粘贴处、原处不再出现；随后重渲染/切视图/保存重开都不「回魂」；撤销/重做序列正确（撤销粘贴→撤销剪切可逐步还原）。
  - **优先级前置条件（Lead 2026-10-22 要求）**：本条的 **P0 依赖下述机制，而机制目前是代码推断** ⇒ **必须先真机复现确认**（预览区选中一段 → Ctrl+X → 别处 Ctrl+V → 触发重渲染）。**若真机不复现，则降级为 P1/P2 并注明「仅代码推断，未复现」**，不得用未复现的机制支撑 P0。
  - **定位线索（静态推断，需真机复验）**：`beforeinput` 只拦截 `insertText` / `deleteContentBackward` / `deleteContentForward` / `insertParagraph`，其余（含 `deleteByCut`）直接 `return` 交还原生（`edit-handler.js:834-855`）；`#preview` 上**没有** `input` 监听做「DOM 原生改动 → AST」兜底同步（该文件只有 beforeinput/keydown/composition/mouseup 绑定）；而粘贴走 AST 管线（`app.js:11936-11949` → `insertText` → `repaintPreview()`），重绘源是 **AST/源码** ⇒ 剪切从未写回源码，重画时原内容复现并与粘贴内容并存。**建议真机复验后再定性为「静默数据污染」。**
