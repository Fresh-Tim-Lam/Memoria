## 2. MVP（人明确）

```
粒度：① 单文件导出  ② 多选导出  ③ 全选导出
产物：一个 .html 单文件  或  一个「网页文件夹」（含 index.html + 资源）
用途：用户用浏览器看（省电 / 免启动 app）、方便转发给别人
```

### 导出粒度与产物形态是**两个维度**（不要混为一谈）
| 维度 | 取值 | 说明 |
|---|---|---|
| **选择范围** | 单文件 / 多选 / 全选 | 由 UI 决定 |
| **产物形态** | 单 `.html` / 网页文件夹 | 由导出选项决定 |

⇒ 允许组合：单文件 → 单 html；全选 → 文件夹；多选 → 两者皆可。

## 3. 已裁决（人 2026-10-26 拍板，**不再开放**）

### Q1 导出页面的视觉形态 —— **都要（两种都做）**
```
人原话：「都要，其他按你推荐的写」
⇒ 采用两档：
   (a) **Memoria 样式（默认）**：只读版，含同款主题/排版/代码块/公式，
       【不含侧栏 / 知识图谱 / 搜索】—— 这三项是运行时能力，静态化的代价与收益不匹配
   (b) **纯文本区域**：干净、轻量、无交互（保留标题层级与代码块，不做主题皮肤）
⇒ 导出时可选；默认 (a)
⇒ 两种都必须是【单 html 与网页文件夹】都能产出（形态 × 皮肤 = 正交，不做组合限制）
```
**为什么默认只读 Memoria 样式而不含侧栏/图谱/搜索**：
```
静态 HTML 里这三项要么需预渲染成独立页（工作量与收益不匹配），
要么需在浏览器内建索引（体积 + 复杂度）。
而导出的核心用途是「浏览器里读 + 转发」⇒ 阅读体验优先，交互能力不是 P0。
【若将来要做图谱/搜索的静态版，属后续版本，不在 0.5.x MVP】
```

## 4. 必须提前想清的技术约束（Lead 预判，非排期）

```
① 静态化边界：Memoria 的预览依赖 render-core + MathJax + 主题变量：
   · MathJax 是本地 vendor（可随包/内联）—— 但要考虑体积与许可
   · 图谱/搜索/链接解引用是【运行时能力】⇒ 静态 HTML 里要么降级为死链，要么预先渲染成静态页
   · 图床/附件（images/attachments）要一起打包，否则导出物在别人机器上全是裂图
② 体积：全选导出可能几十 MB（图片 + vendor）
③ 隐私：导出物会离开用户机器 ⇒ 必须问清楚"是否包含 agent 会话历史/配置（含 API key）"
   ⇒ 默认【绝不包含】config/agent.json 与会话；这条要写进契约
④ 链接语义：导出后，内部 wikilink 指向的文档若不在导出范围内 ⇒ 降级策略（死链/提示/自动纳入）
```

## 8. 批次拆分与依赖（皮肤×形态重算后：4 批 + v1.1 延后项）

> 批次是**实现顺序**，不是默认值或组合限制；四组组合都在 v1 交付范围内（"都要"的最小满足）。
> 延后到 **v1.1** 的是各组合的**高级体验**（打印精修/深色跟随/TOC 定制/更多皮肤），**不是**组合本身。

| 批次 | 交付 | 依赖 | 验收组合 |
| --- | --- | --- | --- |
| **B1（内核 + 文件夹 + a 皮肤）** | 渲染内核（marked + 公式/图预渲染 SVG）+ `F` 打包层（`index.html`+`assets/`）+ 皮肤 a 模板 + 单文件选择 + `export_scan` 预览/结果反馈 | 无（复用现有 marked/MathJax/mermaid；新增导出编排层） | **a×F**（单文件 → 文件夹） |
| **B2（单 html + 多选/全选 + 体积保护）** | `S` 打包层（CSS/图片/SVG 内联、图片 base64）+ 多选/全选 UI + 体积预估/警告 + 性能 | B1 的渲染内核与资产管线 | **a×S**、多选/全选 × F |
| **B3（纯文本皮肤 b，独立项）** | 皮肤 b 模板（无主题变量、无 vendor、CSS ≤20KB、系统字体）+ 两形态复用 B1/B2 打包层 + `b` 体积对比 | B1+B2 内核/打包层 | **b×F**、**b×S** |
| **B4（矩阵回归 + 收口）** | 四组组合矩阵回归（同一文档四组产物文本等价）+ Chrome/Edge 离线矩阵 + 打印 + 文档/i18n/隐私说明 + 空态/边界 | B1–B3 | **四组全绿**（§9） |
| **v1.1（延后，不阻塞 v1）** | 各组合高级体验：打印精修、深色模式跟随（若做）、TOC 自定义、第二皮肤微调、更细的大库保护 | v1 发布后 | 另立任务 |
| **v2+（另立）** | HTML 导入、可达闭包、搜索静态化、bundle 对 | 格式冻结 + 安全评审 | — |

**顺序理由**：① 先 `F + a` 打通"渲染→打包→皮肤"三段式（文件夹最接近开发调试形态，资产问题早暴露）；② 再做 `S` 内联（体积/编码/图片 base64 是独立风险）；③ 皮肤 b 放在内核与打包都稳定后做，避免皮肤逻辑混进内核；④ 矩阵回归最后做，避免每组组合都跑全矩阵导致返工。

## 9. 每批验收判据（按皮肤分组 + 四组矩阵）

### 9.1 通用自动检查（每批、每组组合都跑）

断网（DevTools offline / 拔网线）`file://` 打开产物：

| # | 判据 | 通过标准 | 测法 |
| --- | --- | --- | --- |
| A1 | 外部请求 | **0 个**（除 `file://`） | DevTools Network 记录 |
| A2 | 控制台 | **0 error**（warning 允许） | Console 记录 |
| A3 | 公式 | 内联 `<svg>` 数 == 源公式块数；无未渲染 `$` | DOM 计数 + 文本 grep |
| A4 | 图（mermaid） | 每块 == 内联 SVG（或显式降级提示，计数一致） | DOM 计数 |
| A5 | 图片 | 所有 `<img>` `naturalWidth > 0`；无 404 | DOM + 网络 |
| A6 | 内部链接 | 集内可达；集外有降级标记、不 404 | 点击 + `href` 解析 |
| A7 | 隐私 | grep 不到 `api_key` / `agent.json` / `sessions/` / provider 配置 | 文本 grep（四组都跑） |
| A8 | 体积 | 记录单文件/文件夹总字节；与预估偏差 ≤30% | 文件系统统计 |
| A9 | 打开速度 | 单文档首屏 ≤2s（基线机）；全选 index ≤5s | Performance 计时 |
| A10 | 可读性 | 正文 16px 左右、行宽 60–80 字符、代码块/表格不溢出、打印不预览截断 | 目视 + DOM 样式断言 |

### 9.2 皮肤 a（Memoria 只读）专项
- 主题变量与 `markdown-body` CSS **已内联**（无外部 CSS/字体请求）；代码块/表格/引用块样式生效；
- **无侧栏 / 无图谱 / 无搜索入口**（DOM 中不存在对应容器/按钮）；
- 与 App 内 preview 观感一致（字体/行宽/代码块/表格对比截图或 DOM 样式断言）。

### 9.3 皮肤 b（纯文本）专项
- **无主题皮肤**：产物 CSS 中 grep 不到 `--memoria` 主题变量定义/`markdown-body` 皮肤规则；无 `vendor/`/JS 依赖（允许 0 个 `<script>`）；系统字体栈；
- **轻量可验证**：同内容 `b` 产物体积 ≤ `a` 产物的 **60%**（单文件与文件夹各测一次）；CSS 内联 ≤20KB；
- 保留标题层级（h1–h3 可辨）、代码块 `<pre><code>`、公式内联 SVG；打印预览不截断；
- 允许无可点击目录/无侧栏（"干净"即目标）；内部链接仍按 A6 工作。

### 9.4 四组矩阵一致性（B4）
- 同一文档产出 4 组产物：抽取纯文本（`innerText`）后**四组文本等价**（差异仅允许空白归一化）；
- 四组各过 A1–A10 + 对应皮肤专项；**不允许**某组合缺公式/缺图/多脚本；
- 记录四组体积矩阵（`a×S`/`a×F`/`b×S`/`b×F`）用于 P0-10 与 v1.1 决策。

### 9.5 禁止的验收方式
- ❌ "看起来更好看"；❌ 只测一种皮肤/一种形态；❌ 联网打开；❌ 只截图不点链接；❌ 用 `a` 的产物冒充 `b`（grep 主题变量即可识破）。

## 10. 已裁决与实现约束（原开放问题 → 已定，见 §3）

### 10.1 Q1 皮肤（已裁：都要；默认 a；两形态正交）
- 实现约束：**渲染层与皮肤模板解耦**（一份内容 HTML 套两皮肤）；**打包层与皮肤解耦**（两皮肤 × 两形态由 packer 决定，不写死组合）。
- 默认值：皮肤 `a` + 形态 `S`（单文件，最便于转发）；用户在导出对话框可改。
- **不做**：组合限制、皮肤=某形态的隐式绑定、"纯文本=只能单文件"。

### 10.2 Q2 省电（已裁：待测，未测不得作卖点）
- 归为**验证项**：浏览器打开静态产物 vs 启动 Memoria，比较 CPU/内存/电池（实验方案见本文件原 §10.2 记录，已并入本节）。
- 未测前 release notes/宣传**不得**写"省电"；可写"无需启动应用、浏览器直接看"（事实）。

### 10.3 Q3 导入（已裁：v1 只导出，导入延后）
- 0.5.x v1 只交付导出；导入（入口/格式/与既有 markdown 导入的关系）→ v2 或后续。
- 导出格式 `schema_version` 先冻结，导入以之为目标格式。

### 10.4 三条硬约束（Lead 特别关注，写进实现）
1. **皮肤×形态正交**：禁止"a 只能 F / b 只能 S"的隐式限制（用户要"纯文本+单 html 发微信"必须可行）。
2. **纯文本要真的纯文本**：不含主题变量、不含 vendor 大依赖；否则"轻量"理由不成立且体积优势消失（§9.3 用 grep+体积双判据）。
3. **隐私禁止**：两皮肤、两形态都不得包含 `config/agent.json`、会话历史、API key（§9.1 A7 四组都跑）。

### 10.5 延后项（v1.1+，防止"都要=都要完美"导致无限延期）
打印精修、深色模式跟随、TOC 定制、更多皮肤、搜索/图谱静态化、可达闭包、HTML 导入、bundle 对。
