## 0. 设计目标与明确的"不做"

### v0 要解决的用户问题（按优先级）

```
Q1 图上"哪个节点更重要"看不出来 —— 现状所有节点半径恒为 6px
Q2 每次打开布局都大变 —— 现状随机初始化 + alpha=1
Q3 134 个标签全画、无避让 —— 标签淹没图形本身
```

### v0 明确不做（每一条都有裁决理由）

```
✗ 3D 里用大小编码重要性  → D-KGV-04：透视 1.78×，叠加人范围最坏表观 3.92×，信号 < 噪声
✗ 内容体量作为 size 模式 → D-KGV-05：node 无 chars 字段；行数判据被 D-KG-07 禁用
✗ 跨会话位置持久化        → D-KGV-07：v1 候选，需先做实验
✗ 12–13 档 / 5 档 / 4 档 → D-KGV-01：均超出人给定范围，物理上不成立
✗ 埋点 node_radius_px     → D-KGV-08：映射产出不是数据，改映射后历史值不可比
✗ labelHover 逐事件埋点   → D-KGV-08：per-frame 写入是性能反模式
```

## 1. 节点大小（D-KGV-01 / 02 / 03）

### 1.1 范围（人裁决，最高效力）

```
视觉尺寸 = 基准 × [75%, 165%]（线性：半径/直径等比）
基准     = 现状 nodeRadius 常量（当前 6.0px）
⇒ 半径 4.50 ~ 9.90px，跨度 5.40px（直径 9.00 ~ 19.80px）
```

⚠️ **未决（U-KGV-2）**：用户把 `nodeRadius` 设置调到非 6 时（可调范围 4–12），
75%~165% 是随基准缩放，还是仍以 6.0px 为基准？v0 实现按**随基准缩放**，
但此点在 v0 验收时须记录实际行为。

### 1.2 档数与判据归属

```
档数 = 3 档，相邻半径差 2.70px
判据 = 【≥2px 绝对判据】（源自 A 的工程先验，非人类实测）
⚠️ 不要把本条写成"C 的 3px 判据" —— 同一范围下 3px 判据只给 2 档
```

**降级条件**：若 DS-1 人类判读实验证明真实可辨阈值 ≥3px ⇒ 降为 2 档。
DS-1 是"做 >3 档"的必要前提。

**反锯齿偏移**：渲染层对所有半径有 **+1.0px 常量溢出**（`ev:bench:kgviz-v2-discriminability`）。
差分类判据不受影响（常量差分抵消），但**绝对直径断言必须加上该偏移**，否则系统性偏 1px。

### 1.3 映射契约

```jsonc
{
  "kind": "quantile",          // 冻结：不用 sizeScale 术语
  "relative": true,            // 必须同时在 UI 显示绝对值
  "thresholds": [ /* 由 degree 分位点生成 */ ],
  "tiePolicy": "lower",        // tie 归入较低档；阈值取 ≥ 分位点向上取整
  "radiusRange": { "min": 4.50, "max": 9.90 }   // 由 基准×[0.75,1.65] 派生
}
```

**为什么不用 sizeScale**：分位（rank / 经验 CDF）与参数值变换（linear/sqrt/log）**不可互换** ——
同一 `degree=5` 在 live 语料映射到 r8、在均匀语料映射到 r4；
5 档人口 quantile `[41,17,25,24,26]` vs linear `[41,66,20,4,2]`。分位在结构上消除长尾、自带上下界。

### 1.4 tie 策略是必需项，不是细节

```
问题：degree 大量并列 ⇒ 按分位切 3 档时人口 = 59 / 35 / 40（44% 挤最小档）
⇒ 不定义 tiePolicy，"分位 = 人口均衡"就是假的
⇒ v0 验收必须报告实际三档人口，不得只报"3 档"
```

### 1.5 必须显示绝对原值（否则凭空创造语义）

本体已定 `reference` 是**无断言跳转** ⇒ 图谱本身没有"重要性"语义。
用分位大小会把"排名"读成"重要" ⇒ **节点 tooltip 必须显示 degree 原值**。

## 2. 3D 视图（D-KGV-04）

```
v0：3D 节点【等大】；重要性/度数用【颜色】编码，不用大小
```

依据：透视造成屏幕尺寸比 **1.78×**（相机距离 1374.88–2447.01，fov 50）；
叠加人给定 2.2× 范围 ⇒ 最坏表观比 **3.92×**；信噪比 ≈ 0.32（信号 < 噪声）。

**成本澄清**：3D 不做大小的理由**不是性能** —— galaxy 已用共享 `SphereGeometry` + `mesh.scale`，
逐节点半径 0 额外几何、0 额外 draw calls。拒绝理由是**语义不可解释**（深度与重要性通道重叠）。

**falsifier**：若 3D 深度判读任务正确率 ≥80% 且归一组显著优于等大组 ⇒ 可撤回。

## 3. 标签（D-KGV-06）

### 3.1 优先级：可读性前置成立，性能前置不成立

```
✅ 保留：134 个标签无条件全画、无避让 ⇒ 标签淹没大小差 ⇒ 标签必须先做 LOD/避让
✗ 撤回：「标签是 size 的性能前置」
   实测：134 节点下标签开销仅 0.4→0.5–0.6ms（20–33%），占 60fps 预算 3–4%
   "75%" 只在合成 N=3000 时成立
```

### 3.2 v0 取值

```
· 标签避让（碰撞检测 + 优先级：度数高 > 度数低）
· 密度阈值以上隐藏次要标签（悬停显示）
· 不做：逐帧重算布局（会与 §4 的稳定性冲突）
```

## 4. 布局稳定性（D-KGV-07）

### 4.1 v0 承诺（零存储成本）

```
① 确定性种子：同一语料 + 同一种子 ⇒ 每次打开节点坐标【字节级一致】
② 会话内保位：hover / zoom / select 不触发全局 reheat
③ 新节点锚点生长：增量加入的节点在已有邻居附近生长，不重排全局
```

**实测依据**（`ev:obj:D` 真机 5 次）：reset 平均位移 mean **185.6–219.2px**（中位 199.4），
p90 ≈ **398px**，**92.5–97.8% 节点移动** ⇒ 现状确实是"每次都大变"。

### 4.2 v1 候选（不在 v0）

```
跨会话位置持久化。前提实验：重开定位指标 ≤1.5× 首次（C 的 V-07）
⇒ v1 若要做，必须先证明"空间记忆"是真实用户行为，而非推理
```

## 6. 毛球态判定（D-KGV-09）

```
机制：前端 Union-Find（零新增字段，groups 已在 graph-groups.js#L83-L121，O(N+E)）
```

⚠️ **v0 必须修正阈值组合**：原组合在当前语料**自相矛盾** ——

| 条件 | 当前值 | 原阈值 | 结果 |
|---|---|---|---|
| labels | 134 | >60 | ✅ 命中 |
| edges/nodes | 3.02 | <4 | ❌ 不命中 |
| avgdeg | 6.03 | <8 | ❌ 不命中 |

⇒ 结果**开局永远判为毛球态**（任一命中即触发）
⇒ v0 改为**单条件 + 实测校准**：以最大分组占比为主判据（配合 §8 残差 B 的实测值 81.97% / 89.55%）

## 7. 语料身份（D-KGV-12，**必须遵守**）

```
语料身份 = 三元组 ( HEAD sha, manifest_sha256, 测量时间 )
冻结值：HEAD d9341bd1（dirty=true）/ manifest_sha256 a6866c46cab71c43… / 2026-10-26
规模：294 文件（158 md + 136 yaml）；节点 134 / 边 404
build 状态：post_build=true（.memoria/build 产物存在）
```

### 三条硬约束

```
① 禁止再用单一"语料 sha"（旧值 051deb78 无法对应任何可复现状态）
② 该语料【不可从 git 复现】：
   git archive HEAD docs/example ⇒ 61 节点 / 154 边
   当前工作区 AAA_Vocab         ⇒ 134 节点 / 404 边
   方案 1（构造可复现语料）实测不可行（需重建 73 sidecar + 24 md = 重新造数据）
   ⇒ manifest_sha256 是唯一身份；一旦工作区改变，该 manifest 永久失效且无法回滚
③ 判"语料是否一致"看 manifest_sha256，不看 artifact_sha256（后者含时间戳）
```

### 新增事实（修正既有表述）

```
158 个语料 md 中只有 134 个产生 KP，24 个不产生
（Writing 课程笔记 / plan / prompts / reading / question-bank，其中 L9-Part1Summary.md 为 0 字节）
⇒ 「1 文件 1 KP」应表述为：「134 个 KP 文件各占一个 md，另有 24 个无 KP 的库内 md」
```

### build 副作用（残差 A）

```
kb_build 是【破坏性迁移】：kb_build.py#L293-298 strip hints 后 open(full,"w") 写回源 md；
#L312 写回 sidecar。同一副本：build 前 collector 404 边 → build 后 454 边
⇒ 任何边/degree 测量【必须记录 build 状态（pre/post + build sha）】
```

## 8. 验收（可测）

| 项 | 判据 | 失败处理 |
|---|---|---|
| **T-size** | 3 个不同 quintile 节点，用户挑"最大" ⇒ ≥90% 正确 | <80% ⇒ 降为 2 档 |
| **T-label** | 标签避让后，随机 20 节点中用户读出 ≥16 个标签（80%） | 未达标 ⇒ 加强避让 |
| **T-depth** | 3D：两个深度不同但同 degree 的节点，用户判断"哪个更重要" ⇒ 若 ≥80% 判对 ⇒ 说明用户在把深度误读为重要性 ⇒ 强化"3D 不用大小" | — |
| **T-double** | 同一节点同时用颜色+大小编码 degree ⇒ 检查双重编码冲突 | 有冲突 ⇒ 二选一 |
| **T-stable** | 同一语料打开两次，确定性种子下节点坐标【字节级一致】 | 不一致 ⇒ 种子未生效 |
| **T-census** | 节点/边数 = 134/404（按 manifest_sha256 校验） | 偏差 ⇒ 失败并报 U-C2 |

**T-size / T-label / T-depth 需要真人参与**（U-KGV-5）⇒ 发布前是否必须完成，待人与 Lead 确认。
