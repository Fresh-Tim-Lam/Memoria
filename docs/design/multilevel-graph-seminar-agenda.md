## 2. 待裁决的核心概念（假设，不是结论）

- **层次（level）**：同一知识范围的展示粒度。L0 全库概览（簇节点）→ 逐层深入；最小粒度为**知识点**（U-28，已定）；
  更深（句/断言/概念）是否作为新层，由 S1/S10 研讨。
- **维度（dimension）**：同一层次下另一套取景规则。已定两维：**层次维度**、**关联维度**（定义待 S1）；其余留开放槽位（U-25）。
- **簇节点**：语义内聚小群（非严格连通分量），外部只有零星桥（U-13/U-14）。
- **选择性渲染**：按当前层/维 + 语义关系 + 跳数预算决定渲染集合；边是否"存在"本身是语义（U-27），不是数据有边就画。
- **多归属**：KP/簇可属于多个子图/层次/维度；规则待 S2/S6，可能不设上限（U-31）。
- **渲染接口**：2D/3D 是同一渲染契约的两个实现后端（U-33），只设计接口与视图模型，不拆两条线。

## 3. 研讨会场次与章程

> 每场独立章程；会前 24h 发议程+预读；每场产出冻结稿+覆盖矩阵更新。
> 流程：独立提案（≥2 份）→ Lead 并集 → 交叉异议 → 裁决 → 冻结。证据分级 A/B/C；不足 2 源标"本项目假设"。
> **逐议项**：每场按议项编号（Sx-1、Sx-2…）逐条讨论、逐条裁决，禁止整场打包一次过（U-34）。

### S0 · 术语、边界与不做什么

- 必答：层次/维度/簇/一跳/选择性渲染/边"存无"的精确含义；"语义"判据；与旧全展开的关系（默认替代+开关）。
- 交付：`docs/design/multilevel-graph/S0-terms.md`（术语表 + 反例 + 与现有产品术语映射 + U 覆盖）。

### S1 · 维度体系（层次维度 + 关联维度 + 开放槽位）

- 必答：维度清单；每维度取景规则/边源/默认跳数/终止条件；维度组合方式；关联维度的**具体定义**（U-30）；开放槽位的登记方式（U-25）。
- 交付：`S1-dimensions.md`（维度矩阵：维度×取景×边源×跳数×终止×优先级 + 开放槽位表）。

### S2 · 簇与子图划分（语义内聚 + 桥 + 多归属定义）

- 必答：内聚度/桥判定；划分算法候选与可复算性；稳定性；多归属定义（先定义，再决定是否设上限或"不设上限"，U-31）。
- 交付：`S2-clustering.md`（判据 + 算法对比 + 稳定性 + 多归属规则 + 复算脚本方案）。

### S3 · 节点模型与渲染接口（视觉 + 2D/3D 统一契约）

- 必答：簇节点视觉（大小/徽标/计数/展开提示）；层次感知（面包屑/层级条）；**单一渲染接口契约**（视图模型输入、渲染输出、事件回传；2D/3D 为实现后端，U-33）；性能预算。
- 交付：`S3-node-render-contract.md`（节点类型×视觉 token + 渲染接口 schema + 事件契约 + 可访问性）。

### S4 · 选择性渲染、一跳语义边界与「边存无/类型」

- 必答：渲染算法（层/维/簇/一跳预算 → 节点边集合）；一跳挂接语义判据与去重；"背后图不带入"形式化（U-17）；
  **同一对节点在不同层/维/上下文中边的"存无"与类型差异**的判定规则（U-27）；关联维度跳数策略（U-11）；
  全展开开关的兼容渲染路径（U-26）。
- 交付：`S4-rendering.md`（伪代码 + 边界条件 + 反例集 + 存无/类型决策表）。

### S5 · 导航状态机（下钻/返回/跨图/更深跳）

- 必答：状态=(层次,维度,当前簇/节点,历史栈)；下钻/返回/面包屑；点 KP → 编辑器跳转（U-20）；点簇 → 进入子图（U-7）；
  点一跳节点 → 进入"所在"子图（U-21）或"新一跳/更深"（U-22）；多归属的"从哪来回哪去"。
- 交付：`S5-navigation.md`（状态机图 + 转换表全覆盖 + 边界用例）。
- **S5a（SE 专家）**：状态图（statechart）细化的工程图（状态/事件/动作/守卫/副作用），与 S5 同步冻结。

### S6 · 数据模型与契约

- 必答：多层图数据结构（层/维/簇/成员/桥/多归属/边存无）；簇结果持久化（缓存 vs 事实源）；与现有 KP/edges[]/contain_kind/provenance 的兼容；版本与回滚；后端取景查询接口。
- 交付：`S6-data-contract.md`（schema + 读写路径 + 兼容/迁移/回滚 + 查询接口）。
- **S6a（SE 专家）**：ER 图（实体/关系/基数/主键/生命周期）+ DFD（数据流/存储/外部实体），与 S6 同步冻结。

### S7 · agent 消费（多层级如何真正增效）

- 必答：agent 检索/选节/写作如何使用层次/维度；与现有检索评测接入；降级路径。
- 交付：`S7-agent-usage.md`（接口 + 调用策略 + 评测方案）。

### S8 · 度量、验收与发版门槛

- 必答：用户可用性（任务完成时间/迷失率/点击深度）；性能（首屏/帧率/规模）；语义正确性（簇/一跳人工抽检协议）；agent 指标；发版门槛与回滚。
- 交付：`S8-metrics.md`（指标×阈值×方法×产物）。

### S9 · 后端检索 / 取景算法（关键，U-32）

- 必答：给定(层,维,焦点,预算)，如何从全库选择要显示的节点/簇/边；候选算法（层次聚类+语义检索+社区发现+图游走+embedding 近邻）；
  复杂度与可复算；与 agent 检索共用哪些索引；失败/退化时的回退。
- 交付：`S9-retrieval.md`（算法候选对比 + 接口 + 复杂度 + 复算脚本 + 退化策略）。
- **S9a（SE 专家）**：检索/取景数据流图（DFD，含存储与外部接口），与 S9 同步冻结。

### S10 · agent 如何设计知识点（U-29，关键）

- 必答：memoria agent 产生 KP 的机制（从正文/选区/对话生成；边界、命名、粒度、去重、多归属）；人如何监督/纠错；
  与"最小节点粒度=知识点"的关系（U-28）；agent 设计 KP 的审计与回滚。
- 交付：`S10-agent-kp-design.md`（流程 + 触发 + 质量判据 + 审计/回滚 + 人机分工）。
