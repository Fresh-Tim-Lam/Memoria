## 2. 待研讨会裁决的核心概念（**全部是假设，不是结论**）

> 以下仅为议程用语，避免开会时口径漂移；每一条都要在对应场次被独立提案/异议/裁决。

- **层次（level）**：同一"知识范围"的展示粒度。L0 = 全库概览（簇节点），L1 = 某簇内部（子簇/知识点），
  L2 = 某知识点内部/更细语义单元……层数不预设上限（U-8），但要有"何时不再深入"的终止规则。
- **维度（dimension）**：同一层次下的**另一套取景规则**。已知至少两维：**层次维度**、**关联维度**；
  其他维度在 S1 枚举（候选：证据/来源维度、时间维度、任务/问答维度、正反/争议维度——待裁决）。
- **簇节点（代表连通子图的节点）**：不是严格连通分量，而是"内聚度高 + 外部只有零星桥"的语义小群（U-13/U-14）。
- **一跳挂接**：当前视图只把与当前层次节点"有语义关联"的邻居挂接一跳（U-15/U-18）；
  挂接的邻居**不自动把它背后的图带进来**（U-16/U-17）。
- **选择性渲染**：渲染决策基于"当前层次/维度 + 语义关系强度 + 跳数预算"，而不是图数据里有边就画（U-16）。
- **多归属**：一个 KP/簇可同时属于多个子图、多个层次、多个维度（U-21），必须解决"从哪来、回哪去"。

## 3. 研讨会场次与章程

> 每场独立章程；每场前 24h 发议程 + 预读材料；每场产出冻结稿 + 覆盖矩阵更新。
> 流程：独立提案（≥2 份）→ Lead 并集 → 交叉异议 → 裁决 → 冻结。证据分级 A/B/C，不足 2 源标"本项目假设"。

### S0 · 术语、边界与不做什么

- **必答**：层次/维度/簇/一跳/选择性渲染的精确定义；"语义"在本设计的判据；与旧"全展开图谱"的关系（替代还是并存）。
- **不在范围**：具体算法、具体视觉实现。
- **交付**：`docs/design/multilevel-graph/S0-terms.md`（术语表 + 边界 + U 覆盖）。
- **冻结标准**：术语表每条有定义、反例、与现有产品术语的映射。

### S1 · 维度体系（层次维度 + 关联维度 + 其他）

- **必答**：维度清单与每个维度的"取景规则/边源/默认跳数/终止条件"；维度之间如何组合（互斥切换？叠加？）；
  哪些维度是 v1 必须、哪些留槽位。
- **交付**：`S1-dimensions.md`（维度矩阵：维度 × 取景 × 边源 × 跳数 × 终止 × 优先级）。
- **冻结标准**：每个维度可被机检描述（给定图与参数能算出视图）；U-8/U-9/U-10/U-11/U-12 全部有裁决。

### S2 · 簇与子图划分（语义内聚 + 桥）

- **必答**：内聚度度量；桥的判定（边数/语义强度/跨簇比例）；划分算法候选（社区发现/层次聚类/语义嵌入聚类/混合）
  与可复算性；簇的稳定性（更新/增删知识点后是否漂移）；多归属允许到什么程度（U-21）。
- **交付**：`S2-clustering.md`（判据 + 算法候选对比 + 稳定性/多归属规则 + 复算脚本方案）。
- **冻结标准**：在 frozen 语料上给出可复跑划分结果与质量指标（内聚/桥比例/簇数量）。

### S3 · 节点模型与视觉层级

- **必答**：簇节点长什么样（大小、徽标、聚合计数、展开提示）；层次如何被用户感知（面包屑/层级条/缩略图）；
  簇节点与 KP 节点的视觉区分；性能预算（节点/边上限、帧率）。
- **交付**：`S3-node-visual.md`（节点类型×视觉 token + 可访问性 + 性能预算）。
- **冻结标准**：U-5/U-6/U-19 逐条对应；视觉规范可被 UI 机检（CSS/组件契约）。

### S4 · 选择性渲染与一跳语义边界

- **必答**：渲染算法（输入：当前层/维、簇、一跳候选、跳数预算；输出：节点/边集合）；
  一跳挂接的语义判据与去重；"背后图不带入"的形式化规则（U-17）；关联维度的跳数上限与可调策略（U-11）。
- **交付**：`S4-rendering.md`（伪代码 + 边界条件 + 反例集）。
- **冻结标准**：给定视图参数，两名实现者能得出同一渲染集合（可机检）。

### S5 · 导航状态机（下钻/返回/跨图/更深跳）

- **必答**：状态 = (层次, 维度, 当前簇/节点, 历史栈)；下钻、返回、面包屑跳层、点 KP → 编辑器跳转（U-20）、
  点簇 → 进入其子图（U-7）、点一跳节点 → 进入其"所在"子图（U-21）或"新一跳/更深"（U-22）的判定规则；
  多归属时的"从哪来回哪去"。
- **交付**：`S5-navigation.md`（状态机图 + 转换表 + 边界用例）。
- **冻结标准**：状态机可被机检（转换表全覆盖，无死状态）；U-7/U-15/U-19/U-20/U-21/U-22 有裁决。

### S6 · 数据模型与契约

- **必答**：多层图的数据结构（层/维度/簇/成员/桥/多归属）；簇结果是否持久化（缓存 vs 事实源）；
  与现有 `KP`/`edges[]`/`contain_kind`/provenance 契约的兼容（v0.3 是否够用，是否需要 v0.4）；
  版本与回滚；agent 读取接口（按层/维查询）。
- **交付**：`S6-data-contract.md`（schema + 读写路径 + 兼容/迁移/回滚）。
- **冻结标准**：schema 可校验；旧库零数据改动可打开；回滚方案 ≤ 1 步。

### S7 · agent 消费（多层级如何真正增效）

- **必答**：agent 检索/选节/写作如何使用"层次/维度"（例如先选簇→再入簇检索、或按维度扩展关联）；
  与现有检索评测（BEIR/内部集）的接入；不达标时的降级路径。
- **交付**：`S7-agent-usage.md`（接口 + 调用策略 + 评测方案）。
- **冻结标准**：至少 1 个可复跑 A/B（有/无多层级）证明改善或明确证伪。

### S8 · 度量、验收与发版门槛

- **必答**：用户可用性（"想用"怎么测：任务完成时间/迷失率/点击深度分布）；性能（节点/边规模、帧率、首屏）；
  语义正确性（簇/一跳的人工抽检协议）；agent 指标；发版门槛与回滚。
- **交付**：`S8-metrics.md`（指标 × 阈值 × 测量方法 × 产物路径）。
- **冻结标准**：每条指标可机检或有人工协议；U-2 双层价值分别有验收。

## 5. 会议纪律

1. 每场**独立提案 ≥2 份**（研究者独立写，不许互看草稿），Lead 做并集，验证者提异议；
2. 每场只裁决本场问题，跨场问题登记到"悬置清单"，不夹带；
3. 每场产出必须能被**机检或人工协议**复现；无证据的主张标"本项目假设"；
4. 原话覆盖矩阵不全 ⇒ 本场不得冻结，重开；
5. 任何产品代码在 S0–S6 冻结前**不写**（避免再次"边语义做了一堆、主体架构没动"）。

## 6. 需人先确认的问题（本议程批准前）

- Q1 维度清单：除"层次/关联"，你心里还有哪些维度？（时间/证据/任务/争议…？还是先留开放槽位）
- Q2 默认视图：是否彻底替代旧的"全展开"模式，还是保留切换？
- Q3 层次上限：是否允许无限深入（到句/词级），还是到"知识点"为最深层？
- Q4 关联维度默认跳数：1 跳够不够？是否允许用户调 2 跳？
- Q5 多归属上限：一个 KP 最多属于几个子图/层次/维度？
- Q6 性能预算：全库规模上限（节点数/边数）与首屏目标（秒/帧率）？
- Q7 是否要 3D/动画（旧版有 2D/3D），还是先做 2D 交互闭环？
- Q8 开会形式：逐场向你汇报（异步批）还是关键场次你到场？
