# 背景栈视图设计（Background Stack）

> 状态：**待多人研讨**（人提出，2026-11-06）；0.5 HOLD；未实现、未发布。
> 替代：点击子图节点后“硬切换视图 + 返回按钮”的交互（task-389）。
> 目标：消除视图割裂感，把导航栈直接画成同一画布上的背景层。
> **本文 §1 之后是 Lead 的初步整理，不是定稿；不得当成人意图的最终解释。所有语义以 §0 原话为准，经多人独立解读后由 Lead 汇总。**

## 0. 人原话草稿（逐字，不得改写）

> 我有一个绝妙的样式设计，之前我不是说：”本图谱视图点击子图谱节点进入该子图谱视图“吗，  我觉得直接切换视图，可能会造成割裂感，不妨这样，  上层的对应节点， 连接本层的对应节点（如果没有对应节点，两种视觉方案：1连接本视图最大的节点；2连接本视图图谱最外的虚线包围框， 这是连接的效果，  然后，上一层（不一定是上一层吧，更准确应该讲跳转关系，也就是我们的上一站，用户可能点击各种各样的关系跳转到新的图谱视图）的图谱视图是以一种背景的表示形式显示在当前图谱的，（以下效果的程度我称之为背景程度）可以调低透明度、节点大小整体调小亮度调低、不显示文字除了节点A(后面讲到节点A是什么），然后我们在上一站点击的那个节点，称之为 节点A,   这个节点A在本图谱视图正常样式，但是要换一个颜色，表示点击它可以返回上一站； 假设用户的层次深入链路是   X->Y->Z,  现在显示Z的视图，  X  和 Y都是正常作为“背景”显示， 而且每次步进，上一级的背景程度在下一次累加（log(原来+增量)），上一级背景的”节点A"就不再特殊处理（颜色，文字显示）；补充，背景节点和当前视图节点一样是有相互作用力而不重叠的，只不过作用力也会因为“背景程度”按照那个log机制削弱；补充：每次点击进入到子视图，窗口都要进行一次居中定位（设置带开关），定位到当前显示的图谱视图的中心；为了防止背景节点太多干扰主视图，限制到达一定数量，就裁切过去的链路最早的视图所属的节点，假如步进一次导致节点数量超出，但是裁切到”上一站“仍然超，不裁，保留“上一站”作为背景

## 1. 视图栈（Lead 初步整理，待研讨）

导航栈按访问顺序保存每一站：

```text
stack = [X, Y, Z]
Z = 当前（foreground）
Y = 上一站（immediate previous）
X = 更早
```

每站保存：

- `view_id` / `title` / `breadcrumb`
- `focus`、当前节点集、边集、布局种子/坐标、相机（pan/zoom）
- `clicked_node_id`：用户在该站点击进入下一站的节点
- `selection`

点击 group 进入子图 = `push(view)`；点击节点 A 或 Back = `pop()`。
返回后恢复上一站的节点集、坐标、相机、选中与 focus，不重新随机布局。

## 2. 背景层

当前站正常渲染；更早站作为背景渲染：

- 不显示文字（节点 A 例外）；
- 降低整体透明度、节点尺寸与亮度；
- 保留边，但更淡；
- 背景节点仍参与同一力导向模拟，和当前节点一样不重叠；作用力按背景程度削弱。

背景程度（示例参数，原型可调）：

```text
age(i) = stack.length - 1 - i        # 0 = 当前
level  = log(1 + age)                # 人要求的 log 累加
opacity = 0.55 / (1 + level)
size    = 1.0 / (1 + 0.35 * level)
force   = 1.0 / (1 + 0.75 * level)
```

当前层 `age=0, level=0`，完整样式；越早越淡、越小、力越弱。
“背景程度”逐层累加，但按 log 衰减，避免第二层突然消失。

## 3. 节点 A 与返回

- 只有**上一站**被点击的节点称为 **节点 A**；
- 节点 A 在当前视图以正常尺寸/正常样式显示，但使用 accent 色（区别于普通节点与选中态）；
- 节点 A 显示文字；点击它 = 返回上一站；
- 更早层的 A 不再特殊处理（无 accent、无文字），仅作为普通背景节点；
- 每个非根站同时保留 Back 按钮与面包屑作为无障碍/显式入口。

## 4. 连接线

从上一站的节点 A 连到当前站的“对应节点”：

- 优先按同一 id / `parent_id` / `mapped_from` 映射；
- 无映射时两种方案（原型先实现方案 1，方案 2 留开关）：
  1. 连到当前视图度数最高/最中心的节点；
  2. 连到当前视图最外的虚线包围框（表示“从子图边界进入”）；
- 连接线样式独立于普通边（更粗/带箭头/低饱和），不遮挡主图；
- 更早层的连接线可选保留，但随背景程度变淡。

## 5. 居中

每次进入子视图，对当前视图做一次 `fit/center`（带 `autoCenter` 开关）。
返回上一站时恢复保存的相机，不重新居中。

## 6. 裁切

背景节点过多会干扰主视图：

- 上限 `maxBackgroundNodes`（默认建议 120，可配置）；
- 超限时从**最早**的站开始整站裁掉；
- **上一站永不裁**；若裁到上一站仍超限，保留上一站，允许超限；
- 显示背景节点计数/裁切 badge，日志记录裁掉了哪些 view。

## 7. 交互与可访问性

- 点击背景非 A 节点：不触发跳转（避免误触）；可 hover 显示提示“背景视图：X”；
- 点击 A / Back / 面包屑：逐层返回；
- 键盘：Back 按钮可 Tab/Enter；Esc 可返回上一层（可选）；
- 过渡：进/出栈用 150–250ms 透明度/尺寸过渡，不要瞬移。

## 8. 验收

1. X→Y→Z 三层截图：Z 前景、Y 背景、X 更淡；节点 A 特殊且可点击返回；
2. 连接线：有映射 / 无映射（最大节点/包围框）两种；
3. 背景参与力且不重叠；前景不被背景抖动/瞬移；
4. 裁切：超限从最早站裁，上一站保留；
5. 居中开关生效；
6. 根视图无背景、无返回按钮；返回恢复原坐标/相机/选中；
7. 0.5 HOLD，不改冻结 S0–S10/C0。

## 10. 人的裁决（2026-11-06，逐条记录）

> 以下为人在研讨后给出的明确裁决，优先于 §1–§9 中与它们冲突的 Lead 初步整理。

1. **不是两层画布**：背景准确说也在本层画布上，只是背景节点**参与相互作用、但不能点击**。
2. **节点 A 要画第二个实例**：即使当前视图已有同 id 的真实节点，也要另画一个 A；这是为了**区分“点击 A 返回”与“点击真实节点”**的语义。
3. **上一站 = 访问顺序**：不按层次定义，因为点击节点“进入到”的新视图不一定是层次关系，也可能是别的关系；所有访问都按站序入栈。
4. **允许背景力推动前景**：力作用之后会慢慢稳定；不要求前景在背景力下零位移。
5. **不是切换画布，而是同一画布上的不同视图**：进入子图时不清空画布；父层的 A 以背景幽灵节点留在同一画布上，并以跨层连接线连到子图的入口节点（入口锚点可命名为 L0_1）。返回时移除前景层，A 恢复前台。

仍待裁决/原型确认：A 第二个实例的落点与偏移、A 与真实同 id 节点的命中优先级、无映射时连接线连最大节点还是子图整体、裁切口径与上限、返回是否恢复选中、UI 过渡与物理 settle 的时限。
