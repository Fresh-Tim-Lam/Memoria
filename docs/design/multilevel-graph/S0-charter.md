# S0 章程：术语、边界与不做什么（多层次 / 多维度图谱）

> **依据**：`docs/design/multilevel-graph-vision.md`（U-1..U-35，两轮原话逐字存档）；
> `docs/design/multilevel-graph-seminar-agenda.md` V0.2。
> **状态**：S0 章程 V1，Lead 起草；**逐议项**推进（U-34）。本场 S0–S6 冻结前不写产品代码。
> **日期**：2026-11-02（Asia/Shanghai）。

## 1. 目的

把"多层次 / 多维度 / 选择性渲染"这套设计的**最小术语集**钉死，并明确**不做什么**，供后续
S1–S10 与 DFD/ER/状态图共用同一套口径；防止后续各场各自发明术语（此前的返工主因之一）。

## 2. 不在范围

- 具体聚类/检索算法（S2/S9）；
- 节点视觉与布局实现（S3）；
- 性能数值与发版门槛（S8）；
- 2D/3D 渲染引擎实现（只定义接口边界，U-33）。

## 3. 议项清单（逐项裁决；一项未裁决不得跳下一项）

每项产出：**定义（一句话 + 形式化）**、**反例**、**边界用例**、**与 U 编号映射**、**裁决记录**。

| 编号 | 议项 | 必须回答 |
|---|---|---|
| S0-1 | 「语义」 | 图谱语境下"语义"是什么、不是什么；用什么判据说"这条边有语义/没有" |
| S0-2 | 层次（level）与最小粒度 | 层次的定义；「最小节点粒度=知识点」如何形式化；更深层（句/概念）是否算层次（只定位置，不定内容） |
| S0-3 | 维度（dimension） | 维度的定义；与层次的区别；开放槽位（U-25）如何登记而不会被误实现 |
| S0-4 | 簇 / 代表连通子图 | 簇的定义（内聚高+零星桥）；"代表子图"与"严格连通分量"的区别；簇节点与 KP 节点关系 |
| S0-5 | 一跳挂接 | "一跳"的计法（沿什么边算一跳？跨维度算不算？）；挂接节点集合的定义 |
| S0-6 | 选择性渲染 + 边「存无/类型」 | 选择性渲染的定义；边的"存在/不存在"在什么条件下是语义（U-27）；类型差异如何表达 |
| S0-7 | 多归属 | "属于"的定义（成员关系 vs 视图出现）；允许一 KP 同时属于多个层次/维度/子图的含义（上限 S2/S6 决定） |
| S0-8 | 默认视图 vs 全展开 | 默认视图（替代旧全展开）与开关后全展开的边界；两者数据源是否同一份（U-26） |
| S0-9 | 渲染接口边界 | 视图模型（输入）与渲染后端（2D/3D 实现）的边界；事件回传契约的最小集（U-33） |
| S0-10 | agent 的角色边界 | agent 在这套图谱中"设计知识点/决定语义/决定取景"分别到哪一层（细谈 S9/S10） |
| S0-11 | 不做什么 | 明确本板块 v1 不做：自动改写用户正文？跨库图？时间轴？词级节点？——逐条列出 |
| S0-12 | 术语映射 | 新术语 ↔ 现有产品术语（KP、edge、link、graph view、contain_kind、provenance）一一映射；冲突处标红 |

## 4. 预注册判据（会前写死，会后不得改口）

1. 每个术语必须有：定义、至少 1 个反例、至少 1 个边界用例、U 编号映射；
2. 两份独立提案（研究 A / 复核 B）的**差异必须逐条列出**并裁决，不许静默合并；
3. 术语映射若与现有契约冲突（如"边"的含义变化），必须写明**兼容/迁移/回滚**方案；
4. 每个议项裁决必须有证据等级（A/B/C 或"本项目假设"）；
5. 覆盖矩阵中与 S0 相关的 U 编号必须全部出现，否则本场不得冻结。
