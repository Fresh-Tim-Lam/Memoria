# S8 章程：度量与验收（正确性、确定性、性能、可解释性、agent 指标、回归门禁）

> **依据（不可改写）**：`multilevel-graph-vision.md`（U-1..U-35）。
> **上游冻结**：S0–S7 八份 v1（+ S3-ADDENDUM-1、S6-ADDENDUM-1），**不得违反**；逐议项（U-34）。
> **状态**：S8 章程 V1（Lead 起草）。本场冻结前不写产品代码。
> **日期**：2026-11-04（Asia/Shanghai）。

## 1. 目的

把 S0–S7 冻结的语义/契约转成**可执行的度量与验收**：G6 快照冻结、正确性/确定性/性能阈值、可解释性与 UX 验收、G7 agent 指标、数据质量度量、故障注入/回放、回归门禁与 CI 接入、0.5 退出标准。
S8 不发明新图谱语义，只定义「怎么算达标」。

## 2. 不在范围

- 后端检索质量指标（S9）；
- agent 设计知识点质量（S10）；
- 图谱 UI 视觉设计（S3/S4/S5 已冻结）；
- 0.5 实现本身。

## 3. 议项清单（逐项裁决；一项未裁决不得跳下一项）

每项产出：定义/规则、机检条件、反例、边界用例、U 映射、建议裁决、证据等级。

| 编号 | 议项 | 必须回答 |
|---|---|---|
| S8-1 | 指标框架与优先级 | 指标分类（正确性/确定性/性能/可解释/agent/数据质量/回归）；主指标 vs 诊断指标；不得用单一指标掩盖失败；P0 硬门禁 vs 软指标 |
| S8-2 | G6 快照冻结 | 字段/命令/产物路径/sha/复跑；快照不可变；与 S6 G6 字段一致；基线如何建立/更新 |
| S8-3 | 正确性/确定性 | HAC 确定性、registry 校验、presence/rule_id、subset、closure/behind=0、tie-break；阈值（100% 确定性等） |
| S8-4 | 性能/预算 | 60fps/≤180ms、max_nodes/max_edges、后端延迟、冷/热、首开/切页签；预算不可满足的可见失败；S3/S4 数值来源 |
| S8-5 | 可解释性/UX 验收 | rule_id 解释率、suppressed 解释、unknown≠无关系、无静默、可见降级；如何机测（DOM/事件/快照） |

## 4. 预注册判据（会前写死）

1. 每个指标有定义/公式/阈值/证据路径/失败语义；不得只写"好/快"；
2. P0 硬门禁必须机器可判（命令/exit code/快照 sha）；软指标有趋势与门槛；
3. G6 快照字段与 S6 一致、可复跑、sha 稳定；快照不可变；
4. 性能数值有来源与测量条件（冷/热、硬件、样本数）；不得拍脑袋；
5. 可解释性/降级可机测（DOM/事件/快照），不能只靠人工观感；
6. G7 指标与 S7 契约一致，写尝试=0 硬约束；
7. 数据质量指标明确「semantic only」，结构/引用边不得计入；
8. 故障注入覆盖预算/空语义/stale/缺失/非法/审计失败；
9. 回归门禁明确本地/CI 差异与 flaky 处理；
10. 0.5 DoD 与 I-01..I-13 对齐；两份独立提案差异逐条裁决；
11. 不写产品代码、不改契约、不 commit。
