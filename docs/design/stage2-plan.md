## 2.1 现状盘点：性能指标**同样未覆盖所有操作**（第二个系统性缺口）

现有性能指标只有 **3 个操作 + 2 个计数**：

| 已有 | 值 |
|---|---|
| A 按键 → 真源（打字时延） | 11.15ms（预算 16） |
| B 首开 → 块+公式可读 | 1434ms（预算 2000） |
| C 页签 A→B→A | 1292ms（预算 500 且 <B/2） |
| M1/M2 每键 DOM 写 | 19 / 5 |
| JS heap / DOM 节点 | 129.8MB / 103,490（单点采样） |

**未覆盖的操作（用户真会做、且重构最容易打坏的）**：

| # | 操作 | 现状 | 为什么危险 |
|---|---|---|---|
| 1 | **滚动**（大文档、窗口化边界跨越） | ❌ 无 | 窗口化/增量重渲激进时首当其冲；卡顿最容易被用户感知 |
| 2 | **框选 / 拖拽选择**（长距离、跨块） | ❌ 无 | 选区三态是阶段 2 重写重点 |
| 3 | **复制 / 剪切 / 粘贴**（大段、含公式） | ❌ 无 | 剪贴板协商 + 结构重渲，易超时 |
| 4 | **撤销 / 重做**（含结构编辑） | ❌ 无 | 新 EditCore 必须保证 O(1)~O(k)，不能退回整篇重渲 |
| 5 | **查找 / 替换**（文档内） | ❌ 无 | 遍历全部块，与 BlockIndex 查询效率直接相关 |
| 6 | **保存**（写盘 + 缓存失效） | ❌ 无 | 保存路径会清 `preview_body` 缓存，易触发整篇重渲 |
| 7 | **视图模式切换**（源码/预览/双栏） | ❌ 无 | 会重建 DOM |
| 8 | **设置变更**（字号/主题/字体） | ❌ 无 | `display.fonts` 全量刷新，是 §5.3 必保项 |
| 9 | **语言切换**（i18n 重渲染） | ❌ 无 | S6/S7 病灶所在；新实现必须提供刷新钩子 |
| 10 | **IME 中文输入**（组合串 + 上屏） | ⚠️ 仅计入打字时延 | 与纯 ASCII 按键路径不同 |
| 11 | **结构编辑**（回车拆段/合并/跨块删除） | ❌ 无 | 局部 upsert 正确性已测，**性能未测** |
| 12 | **样式应用**（工具栏/右键/样式画笔） | ❌ 无 | 阶段 2 新增能力，必须有预算 |
| 13 | **KP 悬停/跳转** | ✅ 功能已测 | **无时延指标**（hover 应在帧内） |
| 14 | **agent 面板流式渲染** | ❌ 无 | 独立渲染链，token 流下的重渲成本未测 |
| 15 | **导出 / 打印** | ❌ 无 | SVG 字体缓存高风险区 |
| 16 | **长会话内存增长**（泄漏） | ❌ 仅单点 heap | 切页签/重渲频繁时可能累积 |
| 17 | **应用冷启动 → 可交互** | ❌ 无 | B 是"首开文档"，不含 boot |

**结论**：现有性能闸只能保证"**打字/首开/切页签**没退化"。**滚动、粘贴、撤销、查找、保存、视图切换、语言切换、画笔、流式渲染、内存增长**全部无指标 ⇒ 阶段 2 换管线后，这些操作退化了我们也看不见。

⇒ **P0 = 双覆盖面补齐**：渲染保真覆盖（§2）+ 性能操作覆盖（§2.1）。两者都遵循同一纪律：
**先在当前 HEAD 取全绿基线（`S_old` / `P_old`），再允许切换；任何操作退化 >1.15× 或超预算 ⇒ 不得切换。**

### 性能指标的分级与预算口径

| 级 | 操作 | 判据 |
|---|---|---|
| **A 硬门槛**（用户直接感知） | 打字、滚动、框选、粘贴、撤销、查找、保存、视图切换、结构编辑、画笔、KP 悬停/跳转、首开、切页签 | ①绝对预算（16ms 帧内 / 100ms 反馈 / 1000ms 导航）②不退化 >1.15× |
| **B 记录** | 设置变更、语言切换、agent 流式、导出、内存增长 | 报 p50/p95 + 相对变化；超 1.5× 需解释 |
| **C 不测** | 工具栏/菜单等非内容渲染、图谱（阶段 2 范围外） | 说明理由 |

> **预算不得凭空发明**：先测当前 HEAD 的 `P_old`，绝对预算取 `min(用户可感知阈值, P_old × 1.15)`；无用户阈值的操作取 `P_old × 1.15`。

## 3. 架构（双插头 + 双跑 + 切换门禁）

```
                ┌──────────────── SurfaceHost（契约 C1–C12）────────────────┐
                │                                                          │
   legacy ◄─────┤  SurfaceRegistry.switchTo('legacy' | 'new')               ├────► new
   (现有路径)     │                                                          │
                └──────────────────────────────────────────────────────────┘
                       │                                   │
              ┌────────▼────────┐                 ┌────────▼────────┐
              │ legacy 管线      │                 │ RenderCore       │
              │ app.js+renderer  │                 │ (新：AST→块树→DOM)│
              └─────────────────┘                 └─────────────────┘
                                                          │
                                                  ┌───────▼────────┐
                                                  │ EditCore（新）  │
                                                  │ 选区/IME/结构编辑│
                                                  └────────────────┘
```

**关键约束**
1. **同一契约**：legacy 与 new 都实现 `SurfaceHost` 接口；`C10 双消费者一致`、`C11 新旧等价`、`C12 无损切换` 由契约强制。
2. **双跑对比**：同一文档同时（离屏）喂给两条管线，用 `fidelitySignature` + 交互回放比对；**diff 必须为 0 或每项显式归类**（bug / 有意变更）。
3. **`data--src-line` 仍唯一写点**：新管线必须复用 `BlockIndex.upsert()`（门禁不放松）。
4. **切换可逆**：`switchTo('legacy')` 必须随时可用，直到删除旧路径的切片。
