# Memoria 知识系统设计说明

## 一、核心概念

### 1.1 知识点 (Knowledge Point) —— 最小单元

过去文件是组织信息的单位，现在**知识点**是最小单元。一个知识点对应正文中一段连续的论述区域，由 Markdown 标题（`#`/`##`/`###`）界定。

```
## 注意力机制          ← 知识点 A（depth=2）
...
[[Transformer]]       ← 落入 A 区域的链接
...
### 自注意力           ← 知识点 A-1（depth=3, 被 A 包含）
...
## 损失函数            ← 知识点 B（depth=2, A 的兄弟）
```

**关键属性**：
| 字段 | 说明 |
|------|------|
| `id` | 唯一标识（有 id=知识点节点，无 id=标签/关键词） |
| `name` | 名称（与标题文字一致可自动定位区域） |
| `depth` | 标题层级（#=1, ##=2, ###=3），自动计算 |
| `line` | 在正文中的行号，自动计算 |
| `tags` | 标签列表 |
| `weight` | 权重（0~1），影响图谱中的引力强度 |

### 1.2 包含关系 (Containment)

标题层级天然产生包含关系：`## A` 下所有 `###` 标题的知识点都是 A 的子知识点。

**知识点树**：由 `_buildConceptTree()` 将扁平数组按 `line` 排序、`depth` 入栈出栈构造。

```
root
 ├── 注意力机制 (depth=2)
 │    ├── 自注意力 (depth=3)
 │    └── 多头注意力 (depth=3)
 ├── 损失函数 (depth=2)
 └── [orphans: line=0 的未匹配知识点]
```

保存时自动从树结构推导"包含"边，无需手动配置。

### 1.3 边 (Edge) —— 知识点之间的关系

#### 当前支持的边类型

| 类型 | 含义 | 图谱表现 |
|------|------|----------|
| `reference` | 引用（正文 `[[链接]]` 自动生成） | 默认连线 |
| `prerequisite` | 前置知识 | 箭头指向 |
| `extend` | 扩展延伸 | 虚线 |
| `analogy` | 类比关系 | 点线 |
| `包含` | 层级嵌套（自动推导） | 透明/弱化 |

#### 边的强度

| 强度 | 符号 | 图谱表现 | 弹力系数 |
|------|------|----------|----------|
| **强边** (strong) | `-` 实线 | 节点间距近，连线吸引强 | `strength: 0.8` |
| **弱边** (weak) | `- -` 短虚线 | 节点间距远，连线吸引弱 | `strength: 0.2` |

边属性在配置页面中编辑，用户可以为每条边选择强弱。

### 1.4 文件 —— 容器角色

文件不再是组织单元，而变成**知识点的容器**（一个文件包含多个知识点）。点击图谱中的节点 → 打开该知识点所在文件 → 自动滚动锚定到知识点对应标题行。

## 二、图谱可视化设计

### 2.1 2D 模式（D3.js，现有）

基于力导向布局，支持缩放/拖拽/群组过滤。

### 2.2 3D 模式（Three.js）

| 特性 | 实现 |
|------|------|
| 节点 | 球体（SphereGeometry），显示 `abbreviation`（自动缩写） |
| 连线 | 贝塞尔曲线，强边实线/弱边虚线（或颜色区分） |
| 视角 | 鼠标左键拖拽旋转，滚轮缩放 |
| 悬停 | 显示节点 id、description |
| 切换 | 工具栏按钮 **2D/3D** 一键切换 |

### 2.3 布局模式

| 模式 | 说明 |
|------|------|
| **Radial** | 以根节点为中心，子节点向外辐射 |
| **Top-down** | 以根节点为顶部，子节点向下层叠 |
| **Free-force** | 自由力导向布局，用户可拖拽调整 |

### 2.4 吸引/排斥模式

- **吸引**：边不是万有引力，而是弹性"绳子"拉近两端节点
- **排斥**：节点之间恒定排斥力，防止重叠
- 后续可引入相关性权重作为影响因子

## 三、示例：一个完整的知识文件

```markdown
---
description: "深度学习基础概念"
concepts:
  - id: "attention"
    name: "注意力机制"
    weight: 0.9
  - id: "self-attn"
    name: "自注意力"
    weight: 0.7
  - id: "loss"
    name: "损失函数"
    weight: 0.6
edges:
  - type: "prerequisite"
    targets: ["self-attn"]
    strength: "strong"
  - type: "extend"
    targets: ["loss"]
    strength: "weak"
---

# 深度学习笔记

## 注意力机制

注意力机制是 Transformer 的核心，详见 [[Transformer]]。

### 自注意力

自注意力是注意力机制的特例，Q=K=V。

## 损失函数

交叉熵损失是分类任务中最常用的损失函数。
```

**解析结果**：
1. 三个知识点：「注意力机制」(depth=2, line=17)、「自注意力」(depth=3, line=21, 被包含)、「损失函数」(depth=2, line=25)
2. 两条边：`prerequisite(strong)` → self-attn，`extend(weak)` → loss
3. 一条自动推导的包含边：注意力机制 → 自注意力
4. 一个引用链接：`[[Transformer]]` → 落入「注意力机制」区域

## 五、完整工作流示例

### 场景：用户撰写一份 AI 调研笔记

#### 步骤 1：原始 Markdown

```markdown
---
description: "AI Agent 调研笔记"
---

# AI Agent 综述

## 规划能力 (Planning)

规划是 Agent 最核心的能力之一。

### 任务分解

任务分解通过 [[Chain-of-Thought]] 实现。

### 自我反思

自我反思机制允许 Agent [[ReAct|ReAct 模式]] 修正错误。

## 记忆系统 (Memory)

记忆系统分为工作记忆和长期记忆，请参考 [[RAG]]。
```

#### 步骤 2：系统解析后（前端配置页所见）

**知识点树**：
```
AI Agent 综述 (depth=1)
├── 规划能力 (Planning) (depth=2)
│   ├── 任务分解 (depth=3)
│   └── 自我反思 (depth=3)
└── 记忆系统 (Memory) (depth=2)
```

**自动推导的包含边**：
| 源 | 目标 | 类型 |
|----|------|------|
| AI Agent 综述 | 规划能力 (Planning) | 包含 |
| AI Agent 综述 | 记忆系统 (Memory) | 包含 |
| 规划能力 (Planning) | 任务分解 | 包含 |
| 规划能力 (Planning) | 自我反思 | 包含 |

**用户定义的边**（在配置页编辑区域添加）：

| 源知识点 | 目标知识点 | 关系类型 | 强度 |
|----------|-----------|---------|------|
| 任务分解 | Chain-of-Thought | 引用 | 强 |
| 自我反思 | ReAct 模式 | 引用 | 强 |
| 记忆系统 | RAG | 引用 | 弱 |

**链接归属**（按行号范围自动分配）：
- 「任务分解」知识点 → `[[Chain-of-Thought]]`
- 「自我反思」知识点 → `[[ReAct|ReAct 模式]]`
- 「记忆系统」知识点 → `[[RAG]]`

#### 步骤 3：图谱可视化

- **2D 模式**（D3.js Force）：树形展开，强边（实线粗）吸引更大，弱边（虚线细）
- **3D 模式**（Three.js）：球体节点 + 缩写标签 + 贝塞尔弧线 + 鼠标拖拽旋转
- **布局切换**：Free-force / Radial / Top-down
- **节点点击**：跳转到知识点所在文件并定位到对应标题行

#### 步骤 4：配置页全貌

```
┌─────────────┬──────────────────────────────┬──────────┐
│  文件树      │  编辑区                      │  候选列表 │
│             │                              │          │
│ 📁 notes     │  ▸ 知识点配置 (▼)           │  + 添加   │
│  ├ 📄 ai.md  │    ├ AI Agent 综述          │           │
│  ├ 📄 rl.md  │    ├ 规划能力 (Planning)     │          │
│  └ 📄 cv.md  │    │  ├ 任务分解            │          │
│             │    │  ├ 自我反思            │          │
│             │    │  └ 记忆系统            │          │
│             │    │                        │          │
│             │    ▸ 边配置 (2条用户边)      │          │
│             │    │  引用 → [CoT, ReAct] 强 │          │
│             │    │  引用 → [RAG]        弱 │          │
│             │    │                        │          │
│             │    [自动解析] [🧠 AI 分析]  │          │
└─────────────┴──────────────────────────────┴──────────┘
```

## 六、前端架构

### 6.1 模块划分

| 文件 | 职责 |
|------|------|
| `index.html` | 布局骨架：侧边栏（图谱） + 内容区（标签） + 配置面板 |
| `css/memoria.css` | UI 样式，含图谱边强度 CSS 类 |
| `js/app.js` | 主流程：标签管理、文件加载、知识点跳转 |
| `js/graph.js` | D3.js 2D 图谱：力导向、缩放拖拽、布局模式 |
| `js/graph-3d.js` | Three.js 3D 图谱：球体节点、弧线、缩写、悬停 |
| `js/config.js` | 配置窗口：文件树、知识点树、边配置、候选管理 |
| `js/search.js` | 搜索：语义 + 模糊 + 正文搜索 |

### 6.2 数据流

```
.md 文件 → 后端解析 (Python)
  → index.json (nodes, concepts, edges, concept_locations)
    → app.js 加载 index
      → graph.js / graph-3d.js 渲染图谱
      → config.js 读取并编辑
        → 保存时写回 frontmatter
          → 后端重建索引
```

### 6.3 边强度模型

| 属性 | 强边 (strong) | 弱边 (weak) |
|------|---------------|-------------|
| 图谱样式 | 实线，width=2 | 虚线 (dasharray 4,4)，width=1 |
| 力导向吸引 | `distance=80`, `strength=0.9` | `distance=160`, `strength=0.2` |
| 适用场景 | 直接引用、前置知识 | 扩展延伸、类比 |
