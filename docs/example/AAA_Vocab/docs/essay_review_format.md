# Essay Review Format（作文批改知识点文件格式 · 次生规范）

> **文档性质**：**次生规范（secondary spec）**。本文件不由 Memoria 分发，属本知识库自行约定的补充规则。
> **上游权威（冲突时以它们为准）**：`docs/writing_evaluator.md`（批改口径与评分标尺）、`docs/ielts_band_descriptors.md`（官方四项描述语 + 各题型 TA/TR 判定点）、`.memoria/agent/kb-spec.zh-CN.md`（KP 与 sidecar）、`docs/format.md`（渲染语法）。
> **适用范围**：仅限本知识库 `AAA_Vocab`。
> **状态**：生效中，2026-09-18。

---

## 1. 目的

把 `writing_evaluator.md` 的 **S4 评价批改**结果**落库**：写进被批改作文**对应的知识点文件**，成为可检索、可回看、可复习的知识内容。

- 一篇作文 = 一个知识点文件 = 一个 KP。
- 批改写在**同一文件**内（不另建文件），保证"原文 ↔ 批改"始终在一起。

## 2. 与 `writing_evaluator.md` 的唯一偏差：标注语法

`writing_evaluator.md` 原定用 HTML 标注（`<del style="color:red">` / `<ins style="color:green">` / `<mark>`）。
**但 Memoria 主预览不支持 HTML 直通**——原始 HTML 标签会**按字面文本显示**（见 `docs/format.md` §2），即渲染出裸标签，不可用。

因此**映射为 Memoria 原生语法**：

| 语义 | `writing_evaluator.md` 原设计 | 本库写法 | 渲染效果 |
|---|---|---|---|
| 待删 / 待改原词 | `<del style="color:red">原词</del>` | `~~原词~~` | 删除线 |
| 建议的替换 | `<ins style="color:green">新词</ins>` | `[[\h:green\|新词]]` | 绿底高亮 |
| 亮点词句 | `<mark style="background:#cce5ff">亮点</mark>` | `[[\h\|亮点]]` | 黄底高亮 |
| 语法批改中被引用的词 | `<u>词</u>` | `**词**` | 加粗 |

**硬约束**：字样式命令内**不得嵌套** `[[kp-id]]`——行内首个 `]]` 会提前收尾，导致断链（见 `docs/format.md` §4.2）。要叠加效果用 Markdown，如 `[[\h:green|**加粗**]]`。

## 3. 文件结构（区块顺序固定，不得增删换序）

```
# <作文标题>                      ← 唯一 KP，与 sidecar 的 name 逐字一致

> 来源 / 用时 / 词数 / 备注

## 📋 题目 / Task                  ← 题干原文

## 📊 图表 / Charts                ← 仅 Task 1 有图时；图片入 .memoria/images/

## ✍️ 我的作答 / My answer         ← 学员原文，逐字保留（含错误）

## 📝 批改 / Review

### 🎨 标注稿 / Annotated          ← 按 §2 语法、粒度最小化（不整句整段标注）

### ✨ 亮点 ≥3 条

### ❌ 错误纠正 ≥8 条               ← 每条：原词 + 建议改写 + 原因（语法/搭配/拼写/时态/一致/冠词）

### 🔗 连接词分析 ≥3 条

### 🔁 重复词分析 ≥3 条             ← 只给真实可用的替换，不给炫技式生造

### 📊 分项评价 / Criteria          ← 四项，各含：分（整数 0–9）+ 理由 + 文内例子 + 升 8 分动作

### 🏛️ 官方锚点对照                ← 每项对照官方样卷档位：本项分 | 最接近的官方样卷 | 考官原话 | 差距动作

### 🗣️ 总体评语                   ← 2–4 句，不机械列点

### 🏅 整体得分                    ← 四项算术平均，按 0.5 步进；须列出算式
```

## 4. 评分口径

完全沿用 `docs/writing_evaluator.md` 的**评分标尺**与**阅卷人内部校准**（首段定调、机械模板扣分、任务回应底线、overview 缺失、立场明确度、衔接隐性标准、0.5 步进取舍等）。

- 四项**分别**评估后**算术平均**，按 0.5 步进。
- 单项只允许**整数** 0–9。
- 字数：Task 1 < 150 / Task 2 < 250 → TA/TR ≤ 5。**字数以脚本统计为准**，不凭目测。
- **官方描述语与各题型的 TA/TR 判定点见 `docs/ielts_band_descriptors.md`**：先按题型（Task 1 图型 / Task 2 题型）定该题的硬性要求，再对照官方档位描述语打分。

## 5. 机读副本（学习状态隔离）

同一次批改的 **JSON**（`writing_evaluator.md` §JSON 输出 schema 的结构）另存：

```
.memoria/agent/review/evaluations/<源图名>.json
```

- 依据：主规范 `kb-spec.zh-CN.md` §1 要求**学习状态只放 `.memoria/agent/review/**`**。
- md 面向**人读**（批改报告），JSON 面向**机读**（可统计、可对比历次分数）。
- 两者内容同源，但**不得**用 JSON 的字段名去改 md 的结构。
- **JSON 由脚本从 md 抽取生成**（单一事实源 = md），避免两处漂移；JSON 转义交给 `json.dump`，不手写。
- 字段 `annotatedEssayHtml` 内**存 Memoria 标注语法**（§2 映射后的文本），不是 HTML —— 字段名沿用 `writing_evaluator.md` 的 schema，未改名以免破坏机读兼容。
- Task 1 的第一项官方名称为 **Task Achievement**，写入 JSON 时统一归入 schema 的 `taskResponse` 字段。

## 6. 改写示范格式（5.5 → 7）

用于把某篇已批改、**低于目标分**的作文，**以学员原稿为骨架**逐段升级为达标示范。
**与 `writing_evaluator.md` 的 S5 范文不同**：S5 直接给一篇 8 分范例；本格式保留**原稿的论证走位**，让学员看清"我这段差在哪、改成什么样"，因此**可迁移性更强**。

落点：`writing/part<N>/<序号>.md`（批改稿为 `1.md`，改写示范顺延为 `2.md`）。

### 6.1 固定区块

```
# <作文标题> · 改写示范          ← 唯一 KP，与 sidecar 的 name 逐字一致

> 来源（指向对应批改稿）/ 当前分 → 目标分 / 依据的官方锚点 / 改写稿词数

## 🎯 差距诊断：<当前分> → <目标分> 只差几件事
   ← 3–5 条；每条必须对应官方描述语或硬门限，不得凭感觉列

## 🧱 段落结构：原稿 vs 目标分版
   ← 表格：段号 | 原稿功能 | 目标分版功能 | 为什么这样调整

## ✍️ 逐段改写
   ### 第 N 段：<该段功能>
   - **原稿**（逐字引用，含错误）
   - **问题**（钉到官方哪条描述语 / 哪条硬门限）
   - **改写（目标分版）**（英文，可直接背诵）
   - **为什么这样改**（逐点对应官方描述语）
   - **更好的表达**（≥3 条：原表达 → 升级表达，注明语体与适用场景）

## 📖 全文改写版（连读）
   ← 英文完整篇，可直接当范文背；标注词数

## 🧰 可背词块表
   ← 表格：功能 | 词块 | 例句

## ✅ 自检：改写稿对照官方描述语
   ← 逐条核对目标分档位的官方描述语是否**全部满足**，未满足不得交付
```

### 6.2 硬要求

1. **数据准确**：Task 1 改写**必须带真实数值**；数值若取自图表的机器识别，须在文首标注**识别来源与核对要求**。
2. **不得编造事实**：Task 2 例证优先用**假设性例证**（`Consider someone who…`），**不得**编造统计数据、研究结论或新闻事件。
3. **立场与结构须真正达标**：改写稿必须**实际满足**目标分档位的硬门限（如 Part 2 的明确立场 + 每段例证），而不是"看起来更漂亮"。
4. **原稿逐字保留**：引用原稿时不得改字。

## 7. 自检

1. 区块顺序与 §3 完全一致，数量不缺失（亮点 ≥3、错误 ≥8、连接词 ≥3、重复词 ≥3）。
2. 标注语法仅使用 §2 的白名单（无裸 HTML 标签、无 `[[kp-id]]` 嵌在字样式命令内）。
3. `## ✍️ 我的作答` 段与学员原文**逐字一致**（不改语法、不改拼写、不改断行）。
4. **`### 🏛️ 官方锚点对照` 的 4 行必须各自指向一个真实存在的官方样卷档位**，考官原话须能在 `docs/ref/ielts/ielts-academic-writing-sample-tasks-2023.extracted.md` 中检得（不得自造引语）。
5. KP `name` 与 H1 逐字一致；`range` 可精确重定位、`end` 非空行。
6. 整体得分 = 四项算术平均，且列出算式。
7. 交付前提示用户在 Memoria 执行「构建」「检查」。
