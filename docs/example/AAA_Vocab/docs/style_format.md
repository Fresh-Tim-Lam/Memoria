# Style Format（正文样式标注规范 · 次生规范）

> **文档性质**：**次生规范（secondary spec）**。本文件不由 Memoria 分发，属本知识库自行约定的补充规则。
> **上游权威（冲突时以它们为准）**：`docs/format.md`（可用样式命令与渲染行为）、`.memoria/agent/kb-spec.zh-CN.md`（KP / sidecar、§7.1 来源可溯）、`docs/vocab_format.md`（词条怎么写）、`docs/essay_review_format.md`（作文批改的标注语义）。
> **适用范围**：本知识库 `AAA_Vocab` 的**全部正文 md**（词条、短语、句式、口语与写作笔记、批改稿）。
> **状态**：生效中，2026-09-23。

---

## 1. 目的

记笔记时**应当自觉给正文加一些样式**（加粗 / 斜体 / 高亮 / 颜色），让重点一眼可见；但**用量必须克制**——样式是"分层级的信号"，不是装饰。本规范固定"用哪些写法、各表示什么、最多用多少"，避免同一语义在不同文件里各写各的（也便于日后按写法检索）。

## 2. 可用的样式写法

（摘自 `docs/format.md` §3 / §4.2，渲染行为以那份为准）

| 写法 | 渲染 | 本库用途 |
|---|---|---|
| `**加粗**` | 加粗 | 字段标签、要点提示、关键词 |
| `*斜体*` | 斜体 | 变体、语气等次级信息 |
| `` `行内代码` `` | 代码体 | 单词、词块、命令的**字面文本** |
| `[[\h\|文本]]` | 高亮（默认黄底 `#fff3cd`） | 最值得回看的重点、亮点句 |
| `[[\h:bg\|文本]]` / `[[\h:bg:fg\|文本]]` | 指定底色 / 底色＋字色 | 需要区分语义的颜色（见 §3） |
| `[[\c:color\|文本]]` | 字色 | 例句焦点、待办 / 待核实标记 |
| `[[\b\|…]]` `[[\i\|…]]` `[[\u\|…]]` `[[\s:size\|…]]` | 粗 / 斜 / 下划线 / 字号 | 与 Markdown 等价者**优先用 Markdown**（更好读、可嵌套） |
| `~~删除~~` | 删除线 | 批改标注稿里的"原写法 / 待删" |

颜色取值：命名色 `yellow` `green` `red` `blue` `orange` `purple` `gray`，或 `#RRGGBB`。

## 3. 语义 → 写法（同一语义，全库同一写法）

| 语义 | 本库写法 | 现有落点 |
|---|---|---|
| 重点 / 该回看 | `[[\h\|…]]` | `speaking/part2/1.md:68-71`、`writing/part2/1.md:47-50` |
| 建议替换 / 正确写法 | `[[\h:#14532d:#a7f3d0\|…]]` | `writing/part2/1.md:35` 起（旧写法 `[[\h:green\|…]]` 只给底色、字色继承主题，深色主题下读不清） |
| 例句焦点表达 | `[[\c:blue\|…]]` | `expressions/phrases/queue-for-ages.md:16`、`:53` |
| 待核实 / 待办 / 未确认 | `[[\c:red\|…]]` | `vocab/heritage.md:73` |
| 原词 / 旧写法 | `~~…~~` | 各批改稿的标注区 |
| 字段标签、提示语 | `**…**` | 全库词条的 `**英式音标 (British IPA)**` 等 |

- **配色优先级**：`essay_review_format.md` §2 登记的 `\h:green` 只约束**语义**（"建议替换"用绿系）；**具体色号以本表为准**（深色主题写两段式）。两处若不一致，以本文件 §3 为准。
- **深色主题**：需要"底色＋字色"时必须**两段式写全**（`\h:bg:fg`），不要让字色继承主题。

## 4. 用量（"自觉加一些，但不要多"）

1. **每屏 ≤ 3 处**：约 20–30 行内的高亮 / 着色合计 ≤ 3 处；超了改用加粗或列表分层。
2. **一行 ≤ 1 处**：同一行不叠两处以上高亮（**批改标注稿除外**——`~~旧~~` ＋ `[[\h:…\|新]]` 成对出现是语义要求，且必须**逐词最小粒度**）。
3. **只圈词 / 短语**：整句、整段不上色。
4. **同级不混色**：同一层级信息只用一种颜色，不出现"三色齐上"。
5. **标题与表头不上色**：`##` / `###` 标题、表格表头自带层级，不用样式命令。
6. **不叠楼**：已是 `**加粗**` 的字段标签不再加高亮；表格单元格默认不上色。
7. **一处一义**：同一处文本只承担一个语义（要么"重点"，要么"建议替换"）。

## 5. 语法硬约束（踩了就坏）

1. **样式命令不嵌套**：`[[\…]]` 内不再写 `[[\…]]`；叠加效果用 Markdown，如 `[[\h:green\|**加粗**]]`。
2. **命令内不得嵌 `[[kp-id]]`**：`]]` 按**行内第一个** `]]` 收尾，嵌链接会被提前截断 → 断链。链接写在命令**外面**。
3. **单行内闭合**：样式命令不跨行；参数区不要出现多余的 `|`。
4. **颜色写全**：只写 `\h:bg` 时字色继承主题——深色主题下必须两段式。
5. **与链接区分**：`[[id]]` / `[[id\|文本]]`（无 `\` 前缀）是**知识点链接**；样式命令一律 `[[\` 开头。
6. **别为消警告而删样式**：样式命令会被产品登记为 sidecar `links[]` 条目，`validate_kb` 里常伴随 **`link_no_targets`（未绑定跳转目标）警告**——那是**已知噪声、不是错误**（例：`vocab/heritage.md:73` 的 `\c:red`、`writing/part1/1.md:38` / `:40` 的 `\h:green`），不要为它删样式。

## 6. 各类笔记的落点建议

| 笔记类型 | 建议 |
|---|---|
| `vocab/`、`expressions/` 词条 | 字段标签 `**…**`；词条与音标、命令用 `` `…` ``；例句焦点 `[[\c:blue\|…]]`；易错点 / 听力陷阱挑 ≤ 1 处 `[[\h\|…]]` |
| `speaking/` 素材笔记 | `### ✨ 亮点` 的句子用 `[[\h\|…]]`；交付提示里的关键词用 `**…**` |
| `writing/` 批改稿 | 按 `essay_review_format.md` §2 的语义 ＋ 本规范 §3 的色号；`~~旧~~` 与 `[[\h:#14532d:#a7f3d0\|新]]` 逐词成对 |
| `docs/` 规范与说明文 | 一般**不上色**；用加粗与代码体即可（说明文上色反而干扰阅读） |

## 7. 自检

1. 样式是否只落在词 / 短语级，且每屏 ≤ 3 处（§4）？
2. 是否都用 §3 的既有写法（同义同写法），没有自造新的颜色语义？
3. 有没有嵌套的样式命令、命令内嵌 `[[kp-id]]`、跨行的样式命令（§5）？
4. 深色主题下"底色＋字色"是否两段式写全（§5 第 4 条）？
5. `validate_kb` 的 `link_no_targets` 是否只是样式命令的已知噪声（不是真断链）？
6. 交付后提示用户在 Memoria 执行「构建」「检查」。
