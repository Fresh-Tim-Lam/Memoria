# Style Format（正文样式标注规范 · 次生规范）

> **文档性质**：**次生规范（secondary spec）**。本文件不由 Memoria 分发，属本知识库自行约定的补充规则。
> **上游权威（冲突时以它们为准）**：`docs/format.md`（可用样式命令与渲染行为）、`.memoria/agent/kb-spec.zh-CN.md`（KP / sidecar、§7.1 来源可溯）、`docs/vocab_format.md`（词条怎么写）、`docs/essay_review_format.md`（作文批改的标注语义）。
> **适用范围**：本知识库 `AAA_Vocab` 的**全部正文 md**（词条、短语、句式、口语与写作笔记、批改稿）。
> **状态**：生效中，2026-10-13（§7 划关键词 / §8 配色成对立规）。

---

## 1. 目的

记笔记时**应当自觉给正文加一些样式**（加粗 / 斜体 / 高亮 / 颜色），让重点一眼可见；但**用量必须克制**——样式是"分层级的信号"，不是装饰。本规范固定"用哪些写法、各表示什么、最多用多少"，避免同一语义在不同文件里各写各的（也便于日后按写法检索）。

## 2. 可用的样式写法

（摘自 `docs/format.md` §3 / §4.2，渲染行为以那份为准）

| 写法 | 渲染 | 本库用途 |
|---|---|---|
| `**加粗**` | 加粗 | 字段标签、要点提示、关键词 |
| `*斜体*` | 斜体 | 变体、语气等次级信息 |
| `` `行内代码` `` | 代码体 | 单词、词块、命令的**字面文本** |
| `[[\h\|文本]]` | 高亮（默认黄底 `#fff3cd`；**本库一律按 §8.1 写全两段**） | 最值得回看的重点、亮点句 |
| `[[\h:bg\|文本]]` / `[[\h:bg:fg\|文本]]` | 指定底色 / 底色＋字色 | 需要区分语义的颜色（照 §8.1 的四组，不自造） |
| `[[\c:color\|文本]]` | 字色 | **停止新增**（§8.2 第 3 条）；改用成对高亮或 `**加粗**` |
| `[[\b\|…]]` `[[\i\|…]]` `[[\u\|…]]` `[[\s:size\|…]]` | 粗 / 斜 / 下划线 / 字号 | 与 Markdown 等价者**优先用 Markdown**（更好读、可嵌套） |
| `~~删除~~` | 删除线 | 批改标注稿里的"原写法 / 待删" |

颜色取值：命名色 `yellow` `green` `red` `blue` `orange` `purple` `gray`，或 `#RRGGBB`。

## 3. 语义 → 写法（同一语义，全库同一写法）

| 语义 | 本库写法 | 现有落点 |
|---|---|---|
| 重点 / 该回看 | `[[\h\|…]]` | `speaking/part2/experience_1.md:68-71`、`writing/part2/income-equality-impact.md` 批改亮点区 |
| 建议替换 / 正确写法 | `[[\h:#14532d:#a7f3d0\|…]]` | `writing/part2/income-equality-impact.md` 批改标注稿起（旧写法 `[[\h:green\|…]]` 只给底色、字色继承主题，深色主题下读不清） |
| 例句焦点表达 | `[[\c:blue\|…]]` | `expressions/phrases/queue-for-ages.md:16`、`:53` |
| 待核实 / 待办 / 未确认 | `[[\c:red\|…]]` | `vocab/heritage.md:73` |
| 原词 / 旧写法 | `~~…~~` | 各批改稿的标注区 |
| 字段标签、提示语 | `**…**` | 全库词条的 `**英式音标 (British IPA)**` 等 |

- **配色优先级**：`essay_review_format.md` §2 登记的 `\h:green` 只约束**语义**（"建议替换"用绿系）；**具体色号以本表为准**（深色主题写两段式）。两处若不一致，以本文件 §3 为准。
- **深色主题**：需要"底色＋字色"时必须**两段式写全**（`\h:bg:fg`），不要让字色继承主题。

## 4. 用量（"自觉加一些，但不要多"）

1. **每屏 ≤ 3 处**：约 20–30 行内的高亮 / 着色合计 ≤ 3 处；超了改用加粗或列表分层。
2. **一行 ≤ 1 处**：同一行不叠两处以上高亮（**批改标注稿除外**——`~~旧~~` ＋ `[[\h:…\|新]]` 成对出现是语义要求，且必须**逐词最小粒度**）。
3. **只圈词 / 短语**：整句、整段不上色。
4. **同级不混色**：同一层级信息只用一种颜色，不出现"三色齐上"。
5. **标题与表头不上色**：`##` / `###` 标题、表格表头自带层级，不用样式命令。
6. **不叠楼**：已是 `**加粗**` 的字段标签不再加高亮；表格单元格默认不上色。
7. **一处一义**：同一处文本只承担一个语义（要么"重点"，要么"建议替换"）。

## 5. 语法硬约束（踩了就坏）

1. **样式命令不嵌套**：`[[\…]]` 内不再写 `[[\…]]`；叠加效果用 Markdown，如 `[[\h:green\|**加粗**]]`。
2. **命令内不得嵌 `[[kp-id]]`**：`]]` 按**行内第一个** `]]` 收尾，嵌链接会被提前截断 → 断链。链接写在命令**外面**。
3. **单行内闭合**：样式命令不跨行；参数区不要出现多余的 `|`。
4. **颜色写全**：只写 `\h:bg` 时字色继承主题——深色主题下必须两段式。
5. **与链接区分**：`[[id]]` / `[[id\|文本]]`（无 `\` 前缀）是**知识点链接**；样式命令一律 `[[\` 开头。
6. **别为消警告而删样式**：样式命令会被产品登记为 sidecar `links[]` 条目，`validate_kb` 里常伴随 **`link_no_targets`（未绑定跳转目标）警告**——那是**已知噪声、不是错误**（例：`vocab/heritage.md:73` 的 `\c:red`、`writing/part1/1.md:38` / `:40` 的 `\h:green`），不要为它删样式。

## 6. 各类笔记的落点建议

| 笔记类型 | 建议 |
|---|---|
| `vocab/`、`expressions/` 词条 | 字段标签 `**…**`；词条与音标、命令用 `` `…` ``；例句焦点 `[[\c:blue\|…]]`；易错点 / 听力陷阱挑 ≤ 1 处 `[[\h\|…]]` |
| `speaking/` 素材笔记 | `### ✨ 亮点` 的句子用 `[[\h\|…]]`；交付提示里的关键词用 `**…**` |
| `writing/` 批改稿 | 按 `essay_review_format.md` §2 的语义 ＋ 本规范 §3 的色号；`~~旧~~` 与 `[[\h:#14532d:#a7f3d0\|新]]` 逐词成对 |
| `docs/` 规范与说明文 | 一般**不上色**；用加粗与代码体即可（说明文上色反而干扰阅读） |
## 7. 划关键词（选什么、划多大、划在哪儿）

> 「划关键词」＝把正文里**将来能直接搬进答案的最小可复用单位**标出来。没有这条规范，笔记就会「整段一样重要」＝没有重点。

### 7.1 什么算关键词（三类，按优先级取舍）

| 优先级 | 类型 | 例 | 划它的理由 |
|---|---|---|---|
| ① | **搭配骨架**（动词＋介词、形容词＋名词、名词＋引导词等「槽位」） | `embrace exotic culture`、`put pressure on`、`coexist with`、`the authorities concerned` | 决定「这话能不能说对」——错一个介词就失分 |
| ② | **易错 / 易混点**（拼写、前后置、冠词、单复数、近义分界） | `humanitarian`（human-i-tarian）；前后置相反的 `concerned` | 复习时要第一眼被抓住的东西 |
| ③ | **可直接输出的高分句式 / 词块** | `Perilous though that half an hour was`、`there is no guarantee that …` | 句型比难词值钱，可整块迁移 |

- **不划**：题干原词（照抄题干本就要避免）、专有名词 / 数字、已加粗的字段标签、表格表头（§4）。
- 一段里**只挑 1–2 处**；同一句既想划搭配又想划句式时**只划搭配**，句式放到 `## 🔍 高分句` 里单独处理。
- 已经挂 `[[kp-id]]` 跳转的词块**不叠高亮**（链接自带颜色＋下划线，再叠一层会花；§4.6）。要强调就到别的落点强调。

### 7.2 划多大（粒度）

- **词 / 短语级**：2–5 个词，或一个「槽位」（介词、冠词、单复数标记）。
- **句式级**：只圈**骨架部分**（引导词 ＋ 主语 ＋ 谓语），后头的事实细节不圈。
- **唯一例外**：`## 🔍 高分句` 一节可**整句高亮**（那一节要背的单位就是「句」），每篇 ≤ 4 处。
- **不划整段**：一段里非划不可的超过 3 处时，改用列表分层或加粗（§4.1）。

### 7.3 划在哪儿（各类笔记的落点）

| 笔记类型 | 关键词的落点 |
|---|---|
| `vocab/` 词条 | ① Core Definitions 里最该记住那条释义的关键名词 ② Collocation Matrix 里 2 个最高频搭配 ③ 听力陷阱的连读 / 弱读片段（≤ 1 处） ④ 「常见误用」里的错写形式 |
| `expressions/` 词条 | ① 核心搭配本身 ② 介词 / 冠词这类槽位 ③ 与近义条目的分界词 |
| `speaking/` 素材 | ① `## 🔍 高分句` 的句子（整句，≤ 4 处） ② 平实版「难词替换速查表」里的难词（用加粗，不上色） |
| `writing/` 批改稿 | 按 `docs/essay_review_format.md` §2 的语义表；`~~旧~~` 与「建议替换」成对出现 |
| `docs/**` 说明文 | 不上色（§6） |
### 7.4 写作正文：report point 加粗，好表述上色

> 用户口径（2026-10-21）：「对于 report point，你加粗，对于好的表述，你用颜色划关键词。」

- **report point（事实）→ 加粗**：数据、年份、国名、排序结论、趋势幅度本身。例：`**83 million**`、`**2012**`、`**Spain and China**`、`**fifth**`、`**$139.6 billion**`。加粗的是「说了什么」。
- **好的表述（说法）→ 上色**：能整块搬进别的答案的搭配与句式骨架，用 §8.1 的「关键词块」蓝底 `\h:#1e3a8a:#bfdbfe`。例：`second most visited`、`just under`、`a rise of`、`with the exception of`、`earned by far`、`followed by`、`despite falling numbers of tourists`。上色的是「怎么说」。
- **两者互斥**：同一个词块不同时加粗又上色；拿不准时问「换成别的数字，这个词还用不用」——还用的上色，不用的加粗。
- **适用范围**：`writing/` 下的**成文正文**（Introduction 改写句、Overview、Details）。Introduction 段的四色标注是「原题 → 改写」的功能演示，属讲解层，不与本条的「好表述」混用。
- **不受 §4.2 单行限量约束**：写作正文按「每个可背表述各标一处」执行（与批改稿同理），但仍遵守 §5 的语法硬约束（不嵌套、单行闭合、两段式配色）。

### 7.5 课程截图：该插图的插图，该转写的转写

> 用户口径（2026-10-21）：「纯文字图不需要插图」「自己区分插图」。判定由 Agent **逐张自行完成、不询问用户**；也不要因为图多，就把两张图合并成一条处理。

- **图里只有文字**（词汇表、句子对照、要点列表、纯文字幻灯片）⇒ **不插图**：把文字转写成列表或 `>` 讲解，正文里不写「见下图」。
- **图里有文字之外的信息**（流程图、地图与图例、箭头或红标签指向、图表的坐标轴与刻度、版式本身承载含义）⇒ **插图**：入库 `.memoria/images/`，用一行 `![alt](<.memoria/images/x.png> "width=560,align=center")` 引用，图下再用 `>` 写讲解。
- **文字与图示并存**（如分步截图只换了一个红色标签）⇒ 按「含图示」处理：插图，且 `>` 只补图里读不出的要点，不逐条复述图上文字。
- **判错都算笔记缺陷**：该插的没插 ⇒ 版式 / 指向信息丢失；纯文字图也插 ⇒ 正文被截图挤占。修正时删引用**不删磁盘文件**。
- 已按本条执行的落点：`writing/SimonClass/L7-ProcessDiagram.md` 的题目流程图、城市地图、分步截图 → 插图；Vocabulary 两张条目幻灯片 → 只转写、不插图。

## 8. 配色：底色与字色必须成对

> **硬口径**：高亮**一律两段式写全** `[[\h:bg:fg|文本]]`。
> 只写底色的写法（`[[\h|…]]`、`[[\h:green|…]]`）会让字色**继承主题色**——深色主题下浅字压浅底，正是「看不清字」的根源；自本条起**不再新增**，存量维护时遇到即改。

### 8.1 四组标准配色（照抄，不要自造）

| 语义 | 写法（逐字照抄） | 底色 / 字色 | 对比度 |
|---|---|---|---|
| 重点 / 该回看 / 亮点 | `[[\h:#fff3cd:#5c4a00\|…]]` | 浅黄底 ＋ 深棕字 | ≈ 7.8:1 |
| 关键词块（新学、待背的搭配） | `[[\h:#1e3a8a:#bfdbfe\|…]]` | 深蓝底 ＋ 浅蓝字 | ≈ 7.0:1 |
| 建议替换 / 订正 / 正确写法 | `[[\h:#14532d:#a7f3d0\|…]]` | 深绿底 ＋ 浅绿字 | ≈ 7.1:1 |
| 待核实 / 待办 / 未确认 | `[[\h:#7f1d1d:#fecaca\|…]]` | 深红底 ＋ 浅红字 | ≈ 6.9:1 |

（对比度按 WCAG 相对亮度估算，四组均 ≥ 4.5:1，大小字号都够用。）

### 8.2 配对原则

1. **深浅相反**：浅底配深字（黄底＋棕字）或深底配浅字（蓝 / 绿 / 红底＋同色系浅字）；同侧深浅（深底＋深字、浅底＋浅字）一律禁用。
2. **同色系内取对比**：底色与字色同色系最稳（绿底配浅绿字）；跨色系既花又难保对比——旧写法 `[[\h:green:blue|…]]`（绿底蓝字）即反例。
3. **停止单用字色**：`[[\c:color|…]]` 只给字色、没有底色，同一个色在深 / 浅主题下必有一边读不清——**不再新增**；要标焦点就改用 8.1 的「关键词块」成对高亮，或 `**加粗**`。
4. **一组色对一个语义**：8.1 的四组各自绑定一种语义，不得为了好看另发明配色（§3 同理）。
5. **两种主题都要能读**：写完全行扫一眼——「把主题切成浅色，这一行的字还看得见吗？」（§9 自检）

### 8.3 例外：Simon 课程笔记的四色对齐（合法，不是自造色）

> 用户口径（2026-10-21）：「Simon 课程里面我使用的样式颜色组合是合法的。」

`writing/SimonClass/**` 的 Introduction 段用**四色成分对齐**标注原题与改写句，这组写法**不受 §8.1 四组色号约束**，也不要按 §8.2 第 3、4 条去「修正」：

| 颜色 | 标注的成分 | 写法 |
|---|---|---|
| 红 | 题干动词框架（shows / compares） | `[[\h:red:red\|…]]` |
| 黄 | 数据对象（谁、什么指标） | `[[\h:yellow:#b37b02\|…]]` |
| 蓝 | 限定方式（范围、单位、对象） | `[[\h:blue:blue\|…]]` |
| 绿 | 时间 | `[[\h:green:green\|…]]` |

- 用途是**教学演示**（哪块原样搬、哪块被换掉），与 8.1 的「重点／关键词／订正」语义不通用，两套色系别互相套。
- 同色相接 = 这块原样搬过来；跨色相对 = 这块被换掉了。**颜色按替换关系对齐，不按位置对齐**。
- 仅限 `writing/SimonClass/**` 的 Introduction 段；该目录之外的 `writing/` 正文仍按 §7.4 执行。

## 9. 自检

1. 样式是否只落在词 / 短语级，且每屏 ≤ 3 处（§4）？
2. 是否都用 §3 的既有写法（同义同写法），没有自造新的颜色语义？
3. 有没有嵌套的样式命令、命令内嵌 `[[kp-id]]`、跨行的样式命令（§5）？
4. 深色主题下"底色＋字色"是否两段式写全（§5 第 4 条）？
5. `validate_kb` 的 `link_no_targets` 是否只是样式命令的已知噪声（不是真断链）？
6. 交付后提示用户在 Memoria 执行「构建」「检查」。
7. **每个高亮是否都写了 `bg:fg` 两段**？有没有残留 `[[\h|…]]`、`[[\h:green|…]]` 这种只给底色的写法（§8）？
8. 划的是不是「能搬进答案的最小可复用单位」，而不是整句 / 整段（§7）？
