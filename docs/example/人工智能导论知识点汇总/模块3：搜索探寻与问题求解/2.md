#### 知识点3-4：最小最大搜索（Minimax Search）（对应表格“Minimax搜索”）

**位置来源**：第71-74页（3.4节全文），第92-95页

**1. 对抗搜索（Adversarial Search）的引入**
- **位置来源**：第71页，第92页。
- 现实中的智能体不是孤立存在的，需要与其他智能体打交道。
- **适用场景**：信息确定、全局可观察、竞争对手轮流行动、输赢收益**零和（zero-sum）** 假设下的**二人博弈**问题。
- **零和博弈**：一方获得收益必然意味着另一方遭受损失，双方收益和损失相加的总和永远为“零”。

**2. 对抗搜索的形式化要素**
- **位置来源**：第71-72页，第92页。

| 要素 | 定义 |
| :--- | :--- |
| **状态 \(s\)** | 包含当前游戏局面和当前行动的智能体。初始状态 \(s_0\) 含初始局面和初始玩家。 |
| **动作 \(a\)** | 给定状态 \(s\)，\(player(s)\) 在当前局面下可以采取的操作。集合记为 \(actions(s)\)。 |
| **状态转移** | 给定状态 \(s\) 和动作 \(a\)，\(result(s,a)\) 决定后继状态。 |
| **终局检测** | \(terminal\_test(s)\) 判断游戏是否在状态 \(s\) 结束。 |
| **终局得分** | \(utility(s,p)\) 表示在终局状态 \(s\) 时玩家 \(p\) 的得分。零和博弈中只需记录一方的 \(utility(s)\)，另一方按零和原则计算。 |

**3. 最小最大搜索的核心思想**
- **位置来源**：第72页，第92-93页。
- 算法交替探索两名玩家的决策，假设两名玩家都**理性地倾向于最大化自己的得分**（在零和博弈中等价于最小化对手的得分）。
- **玩家MAX**：以最大化得分为目标的玩家。
- **玩家MIN**：以最小化得分为目标的玩家。
- 对于搜索树的每个结点，计算一个**分数**（终局得分或中间结点的最优策略得分）。
- **MIN层**：取所有子结点分数中的**最小值**（因为MIN会选择对MAX最不利的走法）。
- **MAX层**：取所有子结点分数中的**最大值**（因为MAX会选择对自身最有利的走法）。

**4. 教材示例：井字棋（Tic-Tac-Toe）**
- **位置来源**：第72页，第93页，图3.7。
- 井字棋是 \(3 \times 3\) 棋盘，双方各执“○”和“×”，轮流落子，三子连成一线获胜。
- 从玩家MAX（如执“×”）角度，终局得分定义为：MAX胜为+1，平局为0，MAX负为-1。
- 图3.8展示了一棵井字棋搜索树的一部分。

**5. Minimax算法递归定义（教材第94页核心公式）**
- **位置来源**：第73页，第94页。
- 搜索树中每个结点的分数递归计算如下：

\[
\operatorname{Minimax}(s) =
\begin{cases}
utility(s), & \text{若 } terminal\_test(s) \text{ 为真} \\
\max_{a \in actions(s)} \operatorname{Minimax}(result(s,a)), & \text{若 } player(s) = MAX \\
\min_{a \in actions(s)} \operatorname{Minimax}(result(s,a)), & \text{若 } player(s) = MIN
\end{cases}
\]

**6. Minimax算法的流程（算法3.2）**
- **位置来源**：第73-74页，第94-95页。
- `MinimaxDecision(s)`：在状态 \(s\) 下求最优动作 \(a^* = \arg\max_{a} MinValue(result(s,a))\)
- `MaxValue(s)`：返回MAX行动下状态s的得分（初始化 \(v=-\infty\)，取所有子结点MinValue的最大值）
- `MinValue(s)`：返回MIN行动下状态s的得分（初始化 \(v=+\infty\)，取所有子结点MaxValue的最小值）

**7. Minimax算法的性能分析**
- **位置来源**：第74页，第95页。
- **完备性**：如果搜索树有限，则算法必然在有限时间内终止。
- **最优性**：如果对手总是理性地按照最优策略行动，则算法得到的解是最优的。
- **时间复杂度**：\(O(b^m)\)（\(b\)：有效走法数，\(m\)：游戏树最大深度）
- **空间复杂度**：\(O(bm)\)（深度优先搜索）
- **局限性**：对于复杂游戏（如国际象棋、围棋），搜索树巨大，无法在合理时间内完全探索。


#### 知识点3-5：Alpha-Beta剪枝搜索（对应表格“Alpha-Beta剪枝搜索”）

**位置来源**：第75-80页（3.5节全文），第96-101页

**1. Alpha-Beta剪枝的核心思想**
- **位置来源**：第75页，第96页。
- Minimax搜索需要遍历搜索树中所有状态，时间开销巨大。
- **Alpha-Beta剪枝**：在保证与Minimax得到**同样搜索结果**的前提下，**剪去不影响最终结果的分支**，减少被搜索的结点数。
- 关键思想：如果在搜索过程中已经知道某个分支不可能影响最终决策，则无须继续探索该分支。

**2. Alpha值（α）和Beta值（β）的含义**
- **位置来源**：第75-76页，第96-97页。

| 符号 | 含义 | 初始化 |
| :--- | :--- | :--- |
| **α（Alpha）** | MAX结点**当前已知的最好下界**（即MAX至少能获得的得分） | \(-\infty\) |
| **β（Beta）** | MIN结点**当前已知的最好上界**（即MIN至多能允许的得分） | \(+\infty\) |

**3. 剪枝的两种情况**
- **位置来源**：第76-78页，第97-99页，图3.12、图3.13。

| 剪枝类型 | 触发条件 | 说明 |
| :--- | :--- | :--- |
| **α剪枝** | MIN结点 \(n\) 的当前值 ≤ 其祖先MAX结点的当前α值 | 该MIN结点不可能被MAX选择，其后继无需继续搜索 |
| **β剪枝** | MAX结点 \(n\) 的当前值 ≥ 其祖先MIN结点的当前β值 | 该MAX结点不可能被MIN选择，其后继无需继续搜索 |

**4. α和β的更新规则**
- **位置来源**：第76-77页，第97-98页。
- **MAX结点**：如果其后继（MIN结点）的收益 > 当前α值，则**更新α**为该收益。
- **MIN结点**：如果其后继（MAX结点）的收益 < 当前β值，则**更新β**为该收益。
- **剪枝条件**：当一个结点的 **α ≥ β** 时，该结点尚未访问的后继结点可全部剪枝。

**5. 教材示例：完整Minimax树的Alpha-Beta剪枝过程**
- **位置来源**：第78-80页，第99-101页，图3.14、图3.15。
- 图3.14展示一棵完整的Minimax搜索树（叶子结点标注终局得分）。
- 图3.15逐帧展示了Alpha-Beta剪枝的执行过程：
  - 帧(a)→(b)：扩展最左路径，计算第一个叶子结点得分，向上传递并更新α/β值
  - 帧(c)：第二个叶子得分导致当前结点β值下降，触发剪枝条件
  - 帧(d)→(e)：继续扩展右子树，更新α值
  - 帧(f)：剪掉右子树的冗余分支
  - 帧(g)：完成整棵树的剪枝搜索
- 剪枝后扩展的结点数**明显少于**完整Minimax树。

**6. Alpha-Beta剪枝算法的流程（算法3.3）**
- **位置来源**：第78-80页，第99-101页。
- `MaxValue(s, α, β)`：返回MAX结点得分。遍历子结点：得分 \(v = MinValue(s', α, β)\)；更新 \(\alpha = \max(\alpha, v)\)；若 \(\alpha \ge \beta\)，剪枝返回 \(\alpha\)。
- `MinValue(s, α, β)`：返回MIN结点得分。遍历子结点：得分 \(v = MaxValue(s', α, β)\)；更新 \(\beta = \min(\beta, v)\)；若 \(\alpha \ge \beta\)，剪枝返回 \(\beta\)。
- `AlphaBetaDecision(s)`：调用 \(MaxValue(s, -\infty, +\infty)\) 选择最优动作。

**7. Alpha-Beta剪枝的性能分析**
- **位置来源**：第80页，第101页（含习题13\*）。
- **最优情况**：如果结点扩展顺序使得剪枝效果最大化（先搜索最优分支），时间复杂度可降至 **\(O(b^{m/2})\)**——即有效分支因子从 \(b\) 降低到 \(\sqrt{b}\)。
- **最优情况证明**：习题13\*要求证明在最优情况下，算法扩展结点数量的上界为 \(O(b^{\lfloor (m+1)/2 \rfloor})\)。
- **最坏情况**：如果结点扩展顺序不佳，剪枝效果为零，复杂度仍为 \(O(b^m)\)。
- 在现实应用中，通过合理的结点排序策略（如先探索最有希望的分支），Alpha-Beta剪枝能显著提高搜索效率。


#### 知识点3-6：蒙特卡洛树搜索（MCTS）（对应表格“蒙特卡洛树搜索”）

**位置来源**：第80-91页（3.6节全文），第102-113页

**1. 探索与利用的困境**
- **位置来源**：第80-81页，第102-103页。
- **多臂赌博机问题**（Multi-Armed Bandit）：智能体面前有 \(K\) 个赌博机，每次摇动摇臂获得随机收益，总共摇动 \(\tau\) 次，目标是最大化总收益。
- **核心矛盾**：
  - **利用（Exploitation）** ：选择当前收益最高的摇臂，但不一定能准确估计。
  - **探索（Exploration）** ：尝试其他摇臂以获得更准确的估计，但会牺牲短期收益。
- **贪婪算法**：总是选择平均收益最高的摇臂，但容易“错过”更好的选择。
- **ε-贪心算法**：以 \(1-\epsilon\) 概率选择最优摇臂，以 \(\epsilon\) 概率随机探索。

**2. UCB1算法（上限置信区间）**
- **位置来源**：第84-85页，第106-107页。
- **UCB1策略**：选择**置信上界**最大的动作，同时考虑均值估计和探索次数。
- **计算公式**：

\[
l_t = \arg\max_i \left( \bar{x}_{i, T(i,t-1)} + C \sqrt{\frac{2\ln t}{T(i,t-1)}} \right)
\]

- 第一项：动作 \(i\) 的历史平均收益（**利用**）
- 第二项：置信上界（**探索**），对访问次数少的动作赋予更高优先级
- **理论基础**：霍夫丁不等式（Hoeffding's inequality），保证UCB1的悔值函数上界为 \(O(K \ln T / \Delta)\)。

**3. 蒙特卡洛树搜索（MCTS）的四步循环**
- **位置来源**：第85-86页，第107-108页，图3.20。

| 步骤 | 名称 | 操作 |
| :--- | :--- | :--- |
| **1** | **选择（Selection）** | 从根结点开始，使用UCB1策略向下递归选择子结点，直到到达叶子结点或未完全扩展的结点 \(L\) |
| **2** | **扩展（Expansion）** | 如果 \(L\) 不是终止结点，随机扩展它的一个未被扩展过的后继结点 \(M\) |
| **3** | **模拟（Simulation）** | 从 \(M\) 出发，使用简单策略（如随机策略）模拟后续博弈直到终局 |
| **4** | **反向传播（Backpropagation）** | 用模拟结果更新路径上所有结点的统计信息（总奖励和访问次数） |

**4. UCT算法（上限置信区间树搜索）**
- **位置来源**：第86页，第108页。
- **UCT = MCTS + UCB1**，是MCTS中常用的选择策略。
- **结点选择公式**：

\[
\text{UCB}(v') = \frac{Q(v')}{N(v')} + C \sqrt{\frac{2\ln N(v)}{N(v')}}
\]

- \(Q(v')\)：结点 \(v'\) 的累积奖励
- \(N(v')\)：结点 \(v'\) 的访问次数
- \(C\)：探索与利用的平衡因子

**5. 教材示例：MCTS执行过程**
- **位置来源**：第86-87页，第108-109页，图3.21、图3.22。
- 结点内数字记录：**总奖励/访问次数**。
- **选择阶段**：计算每个子结点的UCB值，选择值最大的路径。
- **扩展阶段**：当被选中的结点L存在未扩展子结点时，随机扩展一个子结点C，初始化其总奖励和访问次数为0。
- **模拟阶段**：从C出发随机模拟直到终局。
- **反向传播阶段**：
  - **MIN层**：现有总分 **加上** 终局得分
  - **MAX层**：现有总分 **减去** 终局得分（因为MIN层实际选择最小化终局得分的动作）
  - 所有路径上的结点访问次数 +1

**6. MCTS算法流程（算法3.4）**
- **位置来源**：第88-91页，第110-113页。
- `UCTSearch(s0)`：主函数，迭代执行SelectPolicy→SimulatePolicy→BackPropagate，达到最大迭代次数后选择根结点UCB值最大的动作。
- `SelectPolicy(v0)`：从v0开始，若当前结点存在未扩展子结点则调用Expand，否则用UCB1选择子结点。
- `SimulatePolicy(s)`：从s出发，使用随机策略模拟直至终局。
- `BackPropagate(v, st)`：自底向上更新每个结点的 \(N\) 和 \(Q\)，注意MIN层对 \(Q\) 进行**减法**更新。
- `Expand(v)`：随机选择一个未探索动作，创建新结点并初始化。

**7. MCTS的主要优势**
- **位置来源**：第91页，第112页。
- 不依赖穷尽式枚举，基于**采样**决定搜索树的扩展方式。
- 既能保证搜索效率，又能通过蒙特卡洛模拟准确评估每个分支的优劣。
- 特别适用于搜索空间极大（如围棋）的场景。
