# 角色 A：内容生成 Agent 完整手册

> **用途**：知识库生产流水线中「内容生成 Agent」的**唯一完整手册**——包含可复制的任务提示词、必须严格遵守的平面文件格式规范、整理规则、分批输出规则、输出格式、自检清单与冲突处理。整合并取代原 `knowledge-organizer-prompt.md` 与散落在各处的角色 A 说明。
> **目标读者**：用户（把本手册中「任务提示词」转发给外部 Agent 使用）；内容生成 Agent（角色 A，整体遵守本手册）。
> **关联文档**：[conventions/import-format.md](../conventions/import-format.md)（平面格式**权威源**——本手册第 3 节为其面向 Agent 的内嵌版本，两者冲突以 import-format.md 为准）；[conventions/markdown-form-std.md](../conventions/markdown-form-std.md)（`[[]]` 语法体系）；[guides/usage-agent-workflow.md](../guides/usage-agent-workflow.md)（完整流水线：角色 A → 用户转贴 → 角色 B 转换）。

## 1. 角色定义

| 项 | 说明 |
|----|------|
| 职责 | 把用户提供的原始知识文本整理为 **Memoria 平面导入文件**（`.txt`，`---` 分隔多段） |
| 输入 | 原始知识文本（用户提供） |
| 输出 | 知识库平面文件（单个 `.txt`；内容过多时分批输出，由用户拼接为单文件） |
| 下游 | ① 用户用 Memoria「导入」按钮直接导入；② 交给角色 B 转换为文件组织的知识库文件夹 |

# Memoria 平面文件格式规范（必须严格遵守）

## 1. 基本单位：知识点（KP）

- 每个 KP 有**全局唯一 id**（英文 slug，如 `bayes-rule`、`decision-tree`）
- 一个文档段可包含多个 KP，每个 KP 对应正文中一个语义完整的段落（通常以 `##` 或 `###` 标题开头）
- 文件由文件名标识，文件本身不需要 id 字段

## 2. 平面文件结构

一个平面文件包含**一个或多个文档段**，每段由独占一行的 `---` 分隔。每段结构如下：

```markdown
---
description: 一句话说明本文件主题
concepts:
  - id: kp-id-1
    name: 知识点名称1
    weight: 1.0
    tags: [标签1, 标签2]
  - id: kp-id-2
    name: 知识点名称2
    weight: 0.8
    tags: [标签a]
---

## 知识点名称1

（原文内容，保持原样不修改）

这里可以出现 `[[目标知识点id]]` 形式的链接，表示对其他知识点的引用。

## 知识点名称2

（原文内容）
```

### frontmatter 字段

| 字段 | 说明 |
|------|------|
| `description` | 文件的一句话描述（必填） |
| `concepts` | 知识点列表（至少 1 个） |
| `concepts[].id` | 全局唯一英文 slug（必填，不能与已有 KP id 重复） |
| `concepts[].name` | 中文知识点名称（必填，必须与正文中的 `##`/`###` 标题完全一致） |
| `concepts[].weight` | 重要度 0~1（可选，默认 1.0） |
| `concepts[].tags` | 标签列表，辅助搜索（可选） |
| `path` | **可选**。本段导入到知识库时的目标子目录，支持多级（如 `MachineLearning/Basics`）。缺省落根目录。仅作为导入指令，不写入文档 frontmatter |

### 段落分隔规则

- 每段以 `---` 开头，frontmatter 夹在前后两个 `---` 之间
- 段与段之间由独立成行的 `---` 分隔，前后不能有缩进或空格
- 一段 = 一个文档（导入后生成一个 `.md` 文件，文件名 = 段内第一个 KP 的 `id`；若 frontmatter 指定了 `path`，则写入 `知识库/<path>/<id>.md`，sidecar 自动镜像到 `.memoria/sidecars/<path>/`）
- **多级文件夹组织**：`path` 支持任意层级目录（如 `英语/词汇/外交`、`ML/强化学习/DDPG`），目录自动创建；同主题的多个段可共用同一 `path` 归入同一目录

## 3. 链接语法

在正文中使用 `[[...]]` 标注知识点之间的关联：

| 语法 | 含义 | 示例 |
|------|------|------|
| `[[kp-id]]` | 引用目标知识点 | `[[bayes-rule]]` |
| `[[kp-id\|显示文本]]` | 引用目标，但显示不同文本 | `[[bayes-rule\|贝叶斯公式]]` |
| `[[kp-id#type]]` | 带边类型的引用 | `[[mdp#prerequisite]]` |
| `[[kp-id#type\|显示文本]]` | 完整形式 | `[[mdp#prerequisite\|前置知识]]` |

**注意**：链接的 `[[...]]` 会替换原文中对应位置的文本。如果原文已经提到了某个概念，将提到该概念的地方用 `[[该概念的kp-id]]` 包裹即可。

## 4. 边类型（链接语义）

| 类型 | 含义 | 使用场景 |
|------|------|---------|
| `reference` | 引用/参考 | A 提到了 B，B 是 A 的背景或相关概念 |
| `extend` | 扩展/下游 | A 是 B 的具体实现或特例 |
| `contain` | 包含/父子 | 标题层级关系（系统自动生成，**不需要手动标注**） |

`contain` 类型由文件内的标题层级自动产生（`##` 包含 `###`），**不要**在正文中手动标注。

# 整理规则（严格遵守）

## 必须做的

1. **保留原文内容**：正文中的知识性文字必须原封不动保留，不删减、不改写、不总结、不扩写
2. **划分知识点**：将原文按主题/段落划分为独立 KP，每个 KP 分配唯一 id 和中文 name
3. **排版标题层级**：用 `##` / `###` 等 Markdown 标题组织知识点层次
4. **标注链接**：识别正文中提到的其他知识点，用 `[[kp-id]]` 标注关联
5. **生成 frontmatter**：为每个文档段生成 `description` 和 `concepts` 列表
6. **添加 tags**：为每个 KP 添加有助于搜索的标签（领域、类型、别名等）
7. **段落主题一致**：每个 `---` 段只承载**一个主题**，段内所有 KP 必须同属该主题；`description` 用一句话声明主题（如"X 平台账号分类"），而不是罗列内容。**不同类型/不同领域的知识点严禁混在同一段**（词汇、平台术语、外交句式各自成段）
8. **相关 KP 必须互链**：同一段内存在对比、辨析、同族关系的 KP，必须在正文对应位置用 `[[id]]` 互相标注（例如 A 与 B 的区分说明处，A 段写 `[[B]]`、B 段写 `[[A]]`）
9. **多义词按义项差异处理**：义项差异大（译法/适用场景明显不同）→ 拆为多个独立 KP；差异小 → 同一 KP 内用统一的 `1.` `2.` 有序列表呈现，**禁止用 `###` 子标题或 emoji 编号表达义项**

## 禁止做的

1. **禁止修改原文语义**：不得改写、缩写、扩写、总结原文内容
2. **禁止删除原文段落**：即使内容有误，也保留原文（见下方标注规则）
3. **禁止添加原文没有的知识**：不要补充你认为"应该有"的内容
4. **禁止合并不同主题的内容到一个 KP**：每个 KP 应聚焦单一概念
5. **禁止把句子/一次性例句作为 KP**：完整例句、翻译句、具体原句引用都不做 KP；只有**可复用句式模板**（能套用到其他主语的固定结构）才允许做 KP
6. **禁止用 `###` 表达义项**：`###` 只用于真正有从属关系的概念；词义/义项一律用 `1.` `2.` 有序列表
7. **禁止把词性/语法类别当 tag**：`tags` 只放主题、领域、别名；及物动词、形容词、名词等词性属于正文描述，不得放入 `tags`

## 允许标注的情况

如果整理过程中发现原文可能存在问题，用以下格式标注（不修改原文）：

- **事实性疑问**：在可能有误的内容后追加 `<!-- ⚠️ 待核实：简要说明 -->`
- **逻辑/表述存疑**：在存疑处追加 `<!-- ❓ 存疑：简要说明 -->`
- **术语/符号歧义**：在歧义处追加 `<!-- 🔄 歧义：简要说明 -->`

标注格式统一使用 HTML 注释 `<!-- ... -->`，不会影响 Markdown 渲染。

## 3. 平面文件格式规范（Agent 内嵌版）

> 本节省略版与第 2 节提示词中的规范一致；字段定义、链接语法、边类型的**权威来源**是 [conventions/import-format.md](../conventions/import-format.md)。

### 3.1 基本结构速查

```
---                    ← 段开始（独占一行，无缩进）
description: ...
concepts:
  - id: kp-id-1
    name: 知识点名称1
    ...
---
                       ← frontmatter 结束
## 知识点名称1          ← 正文：## 一级 KP，### 二级 KP
（正文，可含 [[链接]]）
---
                       ← 下一段开始
...
```

### 3.2 关键约束

| 要素 | 规则 |
|------|------|
| 段分隔符 | 独占一行的 `---`，前后不能有缩进或空格 |
| `concepts[].id` | 全局唯一英文 slug；不能与知识库已有 KP id 重复 |
| `concepts[].name` | 必须与正文 `##`/`###` 标题**完全一致**（转换阶段依赖该匹配定位 KP range） |
| 标题层级 | `##` = 一级 KP，`###` = 二级 KP（嵌套在 `##` 下，构成 contain 父子） |
| 链接 | `[[id]]` / `[[id\|文本]]` / `[[id#type]]` / `[[id#type\|文本]]` |
| `path`（可选） | 本段导入的目标子目录，支持多级（如 `English/Vocabulary`）；缺省落根目录 |

---

## 4. 知识点划分与命名规范

### 4.1 划分原则

- **原子性**：知识点是最小语义单位，一个 KP 聚焦单一概念
- **语义完整**：每个 KP 覆盖完整语义段，不截断在空行上
- **段落主题一致**：一个 `---` 段只承载一个主题，段内所有 KP 同属该主题。判据：段内所有 KP 必须共享**至少一个主题标签**（公共主题）；若无公共主题标签 → 可能混段，应检查内容：确属同一主题则给每个 KP 补上公共主题标签，确属混段则拆成多段
- **层级合理**：一个 `##` 通常对应一个 KP；`##` 下内容过短（<3 行）时与相邻标题合并
- **粒度边界**：
  - 词 / 短语 / 术语 / 概念 → KP
  - 派生词、易混辨析：若是**独立可检索概念**（如 fragile）→ 拆独立 KP 并 `[[链接]]`；若只是记忆提示 → 留在正文
  - 完整句子、一次性例句 → **不做 KP**；只有可复用句式模板可做 KP
  - 多义词：义项差异大 → 拆多个 KP（如 `brittle` 实物义 / `brittle-abstract` 抽象义）；差异小 → 同一 KP 内 `1.` `2.` 列表
- **表示法统一**：同批所有段的多义项一律用 `1.` `2.` 有序列表；禁用 `###` 义项、禁用 emoji 编号（`1️⃣`）、禁用不同词条各自创新格式

### 4.2 id 命名

- 英文 slug：**仅 ASCII** 小写字母、数字、普通连字符 `-`（如 `bayes-rule`、`dp-dpg`）
- **禁止**全角/非断行/连字类 Unicode 破折号（如 `‑` U+2011、`–`、`—`）：复制自 Word/排版源时极易混入，导致 `[[id]]` 链接与手打连字符无法匹配
- 语义化：能看出概念含义，避免 `kp1`、`note2` 这类无意义 id
- 全局唯一：与知识库已有 id、同批其他段 id 均不得重复

### 4.3 name / weight / tags

- `name`：自然中文，与标题一致；宁具体勿模糊
- `weight`：0~1，核心概念给高值（0.9~1.0），边缘概念低值（0.3~0.5）
- `tags` 两维规范：
  - **类型标签**（英语词汇 / 英语短语 / 网络平台术语 / 英语句式 / 概念…）：每 KP **至多 1 个**，置于 tags 首位，辅助类型检索
  - **主题标签**：领域、主题、别名（如「强哥」→ 光头强），用于主题检索
  - **禁止**词性/语法类别入 tags（及物动词、形容词、名词、被动语态等属于正文描述）

### 4.4 组织规范（正反例对照）

**反面示例（混乱组织）**——混主题、句子做 KP、`###` 义项、对比不互链、词性入 tag：

```markdown
---
description: 英文词汇与句式汇总，包含阅读X平台外交、科技文本遇到的单词、固定短语、书面句式
concepts:
  - id: confront
    name: confront
    tags: [英语词汇, 及物动词, 外交新闻高频, 易错搭配]
  - id: parody-account
    name: parody account
    tags: [网络平台术语, X平台, 账号类型]
  - id: should-be-followed-in-advancing
    name: should be followed in advancing sth
    tags: [英语句式, 被动语态, 外交书面句型]
---
## confront
### 义项1（主动：强硬对抗、直面）   ← ❌ ### 义项
### 义项2（被动：被迫面临）         ← ❌ ### 义项

## parody account
## commentary account                ← ❌ 与词汇、句式混段
```

问题：一段混了词汇/平台术语/句式三类；`should be followed in advancing sth` 是句子却做了 KP；义项用 `###` 产生无意义 contain 边；parody 与 commentary 对比处没有 `[[互链]]`；`及物动词` 等词性进入 tags。

**正面示例（规范组织）**——同主题成段、互链、义项用列表、tag 分两维：

```markdown
---
description: X 平台（原 Twitter）账号分类术语
concepts:
  - id: parody-account
    name: parody account
    tags: [网络平台术语, X平台, 账号分类]
  - id: commentary-account
    name: commentary account
    tags: [网络平台术语, X平台, 账号分类]
---
## parody account

戏仿恶搞账号。与[[commentary-account]]的区别：模仿口吻恶搞玩梗，不输出观点。

## commentary account

评论解读账号。与[[parody-account]]的区别：输出分析观点；parody 是模仿恶搞。
```

- 一段一个主题；辨析处互链；义项统一 `1.` `2.`；tags 首位为类型、其余为主题，无词性。

---

## 5. 分批输出规则（内容过多时）

1. **分批原则**：按主题自然切分，每批输出一个**完整的平面文件片段**（含独立 `---` 段）
2. **批次衔接**：每批仍以 `---` 开头、frontmatter 完整，保证用户拼接后文件结构合法
3. **跨批链接**：后批引用前批知识点时直接写 `[[kp-id]]`（id 全局唯一，拼接后自然连通）
4. **总览先行**：分批前先输出「知识点总览表 + 链接关系表」，用户确认划分合理后再逐批输出正文
5. **批次标记**：每批末尾注明「第 X/N 批」，便于用户确认接收完整

## 6. 输出格式（面向用户）

### 6.1 新建知识库

1. **知识点总览表**（id / name / 所在文件（段）/ 标签；若该段指定了 `path`，在"所在文件"列写 `目录/文件名`）
2. **链接关系表**（源 KP / 链接文本 / 目标 KP / 边类型）
3. **文件内容**：完整平面文件（多段用 `---` 分隔，放一个代码块）

### 6.2 增量导入到现有知识库

1. **衔接表**（新 KP / 关联已有 KP / 关联方式）
2. **新增链接表**（已有文件 / 位置 / 新增链接）
3. **新增文档段内容**

### 6.3 完整示例（单段）

```markdown
---
description: 贝叶斯公式——概率论中的核心推理工具
concepts:
  - id: bayes-rule
    name: 贝叶斯公式
    weight: 1.0
    tags: [概率论, 推理, 核心公式]
  - id: prior-probability
    name: 先验概率
    weight: 0.7
    tags: [概率论, 概念]
---

## 贝叶斯公式

贝叶斯公式描述了根据新证据更新信念的规则：P(A|B) = P(B|A)P(A) / P(B)。它是[[概率论]]与[[统计推断]]的核心工具。

## 先验概率

先验概率 P(A) 是在观察数据之前对事件的信念强度。贝叶斯公式将[[先验概率]]与似然结合，得到后验概率。
```

> **代码围栏说明**：完整平面文件可以放在 ```text 代码块中输出（便于复制），也可以直接输出纯文本。导入时两者均可——导入引擎会自动剥离包裹整份文件的首/尾围栏（正文内部的代码块不受影响）。

## 7. 自检清单（交付前逐项勾选）

- [ ] 每个文档段有完整的 `description` 和至少 1 个 `concepts` 项
- [ ] 使用了 `path` 的段：目录名合法（无 `..`、非绝对路径），总览表"所在文件"已标注目录
- [ ] **每段只含一个主题**：段内 KP 的 tags（类型/领域）有交集；`description` 是主题声明而非内容汇总
- [ ] **无句子/一次性例句做 KP**：仅可复用句式模板例外
- [ ] **无 `###` 义项、无 emoji 编号**：多义项统一 `1.` `2.` 列表
- [ ] **对比/辨析的 KP 已互链**：正文对应位置有 `[[id]]`
- [ ] **tags 无词性/语法类别**：首位为类型标签（至多 1 个），其余为主题标签
- [ ] 所有 `concepts[].id` 全局唯一（本批内 + 与已有知识库）
- [ ] 所有 `concepts[].name` 与正文 `##`/`###` 标题完全一致
- [ ] 正文原文内容未被改写、删减、扩写、总结
- [ ] 每个 KP 的 range 覆盖完整语义段，未截断在空行
- [ ] 所有 `[[id]]` 链接的目标 id 都存在于全部 concepts 中（悬空链接需显式说明意图）
- [ ] 链接文本与原文用词一致（未改原文）
- [ ] `contain` 边未手动标注（由标题层级自动产生）
- [ ] 疑问/存疑处用 `<!-- -->` 标注，未修改原文
- [ ] 多批输出时：每批以 `---` 开头、frontmatter 完整、可无损拼接为单文件

## 8. 冲突处理与常见错误

### 8.1 KP id 冲突（导入时）

若导入时发现 id 与已有知识库冲突，用户会收到冲突报告，处理方式：

| 用户选择 | Agent 后续动作 |
|---------|---------------|
| 跳过 | 该 KP 不导入，其余保留；无需改动 |
| 覆盖 | 导入内容替换已有；无需改动 |
| 重命名 | 冲突 id 加前缀（如 `imported-mdp`）；若需保留两份，Agent 更新该 id 的所有 `[[链接]]` |

### 8.2 常见错误

| 错误 | 后果 | 修正 |
|------|------|------|
| `name` 与标题不一致 | KP range 定位失败，图谱无节点 | 统一为与标题完全一致 |
| id 重复 | 导入报冲突 | 改 id 并同步所有链接 |
| `---` 前后有空格 | 段解析失败 | 保证 `---` 独占一行无缩进 |
| 链接文本与原文不一致 | 违反"不改原文"原则 | 用 `[[id\|原文文本]]` 保留原文 |
| 手动标注 contain | 系统自动生成重复边 | 删除手动标注 |
| 一段混多个主题（词汇+术语+句式） | 文件内 KP 互不相关，检索/图谱噪音 | 按主题拆段，`description` 写主题 |
| 句子/一次性例句做 KP | 粒度错误，图谱出现非知识点节点 | 并入相关词汇 KP 正文；仅句式模板例外 |
| `###` 义项 / emoji 编号义项 | 产生无意义 contain 边，表示法漂移 | 统一 `1.` `2.` 有序列表 |
| 对比辨析处未互链 | 关系丢失，图谱边缺失 | 在正文辨析位置加 `[[id]]` |
| 词性/语法类别入 tags | 检索噪音 | 移除；tags 只留类型（首位）+ 主题 |
| id 含 Unicode 破折号（U+2011 等） | 手打 `[[链接]]` 匹配不上 | 统一替换为 ASCII `-` |
