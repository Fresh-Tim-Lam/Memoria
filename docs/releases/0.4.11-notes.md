# Memoria v0.4.11

> 0.4.10 → 0.4.11：agent 首次可以自己整理“整体—部分”语义包含（带审计身份、可撤销）；7 项交互/词法修复；首个以 AGPL-3.0-only 发布的版本。多层级图谱只完成 S0–S5 设计冻结（docs-only），S6 进行中——**图谱功能不在本版**。

## English

### Why upgrade

Three reasons to install this PATCH release:

1. **The agent can now curate semantic whole–part containment itself.** `curate_contain` is a first-class `propose_write` operation: it compiles to an atomic primitive that reuses the existing pre-image backup / undo / audit chain, and records `curated_by` (`human:<id>` or `agent:<session>`) plus `curated_at` in the curation overlay. "Who confirmed this and when" is now product data, not a claim. Humans still confirm from the KP edges tab through an in-app dialog; the agent’s own writes are recorded as `agent:plan`.
2. **Seven interaction/lexer defects are fixed**, including the preview-image edit that jumped back to the top of the document, the mermaid popup scroll and close-button placement, the link panel’s mermaid rendering, and inline math containing markdown-active characters such as `[`, `]`, `_`, `*`, `~`, `` ` `` and `!`.
3. **Licensing is now unambiguous.** This is the first release after v0.4.10, so **Memoria v0.4.11 is licensed under AGPL-3.0-only**. v0.4.10 and earlier versions, and all commits made before the change, remain under MIT — that grant is irrevocable. If you need a commercial license outside AGPL-3.0, contact the maintainer.

### New: semantic whole–part curation (v0.3)

- **`contain_kind` separates structure from semantics** (KG ontology v0.2, schema_version still 1). System-derived containment is always `structural`; a missing field means `structural` (fail-safe, never inferred as semantic). Semantic containment requires an `assertion_source`, and the schema rejects semantic values without one.
- **The agent has a first-class curation path.** `propose_write` op `curate_contain(file, source_id, target_id, assertion_source)` is validated and compiled by the normal plan/apply pipeline; apply writes one sidecar overlay, the pre-image is backed up, and the existing undo chain can revert it. It is deliberately **not** a standalone write tool, so it cannot bypass plan evidence, atomic batching or audit.
- **Audit identity is enforced.** Overlays must carry `curated_by` and `curated_at`; the collector rejects overlays without them (fail-closed). Agent-originated writes record `curated_by=agent:plan`; human UI confirmation records `human:ui` (or the human id).
- **The UI shows the real state.** In the KP edges tab, a structural contain edge shows “确认为整体-部分” / “Confirm whole–part”, a semantic edge shows “撤销语义确认” / “Remove semantic confirmation”. Confirmation names parent/child/file/line, hashes the confirmed child range client-side and re-verifies it server-side, and uses the in-app modal (never a native browser prompt). The edge geometry stays derived; only `contain_kind`, `derived_by` and `assertion_source` are overridden by the overlay. Orphan overlays produce warnings and never fabricate an edge.

### Fixes

- **Preview image editing no longer jumps to the top.** Image property/name write-back goes through the keep-scroll re-render entry instead of a full preview re-render; the source pane’s scroll position is restored as well.
- **Mermaid popup scroll and close-button placement** (task-198): the popup keeps its stable scroll position while the diagram is being laid out, and the close control is positioned as a proper button.
- **Link panel mermaid rendering** now goes through the main post-processor (B2).
- **Block editing focus** uses `preventScroll`; image-property writes use `renderPreviewKeepScroll` (B1).
- **Ask snapshots carry pending summons** (R4-3), so the panel state no longer silently drops them.
- **Inline math keeps markdown-active characters literal.** Inside an unclosed inline formula, only `$` and backslash escapes are syntax; `[ ] _ * ~ `` ` `` and `!` are emitted as literal text and joined back into the formula. The reported line now parses to exactly 5 `math_inline` nodes plus one link with the correct URL (16 tests in `tests/test_math_inline_lexer.py`).

### Docs and engineering (not user-facing features)

- **Multilevel-graph seminar: S0–S5 are frozen as design documents only.** S0 terms, S1 dimensions, S2 clustering/subgraph rules, S3 node visuals/render interface, S4 selective rendering, and S5 navigation state machine each have a freeze record under `docs/design/multilevel-graph/`. **S6 (data contract) is in progress** (charter, proposals and evidence only). No multilevel-graph UI or behaviour is implemented in v0.4.11; implementation is deferred to the 0.5 scope after S6 freezes.
- KG ontology v0.2 and edge-provenance schema v0.1 landed as data-contract documents; provenance backfill/apply tooling is copy-only research tooling and never writes a user knowledge base.
- Team governance and agent-internal tooling: protocols registry v1 (P-01…P-08), component-library registry/tooling v0.1–v0.2.1, audit improvements, the split todo index, and the AGPL packaging/marketing copy follow-up.

### Upgrade notes

- **License:** AGPL-3.0-only applies **from v0.4.11 onward**. v0.4.10 and earlier remain MIT and that grant is irrevocable. The repository `LICENSE`, README, `pyproject.toml`, packaging metadata, the release package README and the marketing claims were aligned. - **Semantic curation is confirmed, not inferred.** The agent proposes and can apply `curate_contain` with an audit identity; nothing in the product silently infers semantic containment. Only containment edges are eligible.
- The full test suite and packaging gates are run by the Lead on the release candidate; the numbers below are the local targeted run at notes-writing time, not a substitute for the release gate.

## 中文

### 为什么要升级

本次 PATCH 版本值得安装的三件事：

1. **agent 第一次可以自己整理“整体—部分”语义包含。** `curate_contain` 是 `propose_write` 的一等操作：编译成原子原语，复用既有「写前备份 / 撤销 / 审计」链，并在 curation overlay 中记录 `curated_by`（`human:<id>` 或 `agent:<session>`）与 `curated_at`——“谁确认的、什么时候确认”从此是产品数据，不是一句声明。人仍可在 KP 边面板通过应用内弹窗确认；agent 自己的写入记录为 `agent:plan`。
2. **修复 7 项交互/词法缺陷**，包括预览图片编辑后闪回文档开头、mermaid 小窗滚动与关闭按钮定位、链接面板 mermaid 渲染，以及行内公式中出现 `[`、`]`、`_`、`*`、`~`、`` ` ``、`!` 等 Markdown 活跃字符时被错误解析的问题。
3. **许可边界明确。** 本版本是 v0.4.10 之后的下一个发布，因此 **Memoria v0.4.11 起使用 AGPL-3.0-only**。v0.4.10 及更早版本、以及本次变更之前的所有提交，仍适用 MIT —— 该授权不可撤回。如需 AGPL-3.0 之外的商业授权，请联系维护者。

### 新功能：语义整体—部分 curation（v0.3）

- **`contain_kind` 把“结构包含”与“语义包含”分开**（KG 本体 v0.2，`schema_version` 仍为 1）。系统派生的 contain 边一律是 `structural`；字段缺失按 `structural` 处理（fail-safe，绝不自动推断为语义）。语义包含必须带 `assertion_source`，schema 会拒绝缺来源的语义值。
- **agent 拥有一等 curation 路径。** `propose_write` 的 `curate_contain(file, source_id, target_id, assertion_source)` 走正常 plan/apply 校验；apply 只写一条 sidecar overlay，写前备份，可用既有 undo 链撤销。它**不是**独立写工具，因此不能绕过计划证据、原子批次或审计。
- **审计身份强制。** overlay 必须带 `curated_by` 与 `curated_at`，缺失由 collector fail-closed 拒绝；agent 写入记录 `curated_by=agent:plan`，人工 UI 确认记录 `human:ui`（或具体 human id）。
- **UI 显示真实状态。** KP 边面板中，结构边显示「确认为整体-部分」，语义边显示「撤销语义确认」。确认弹窗会列出父/子/文件/行号，客户端对确认的子节点文本做 SHA-256、服务端复核；使用应用内 modal，不弹浏览器原生 prompt。overlay 只覆盖 `contain_kind` / `derived_by` / `assertion_source`，几何仍由系统派生；孤儿 overlay 只产生 warning，绝不凭空造边。

### 修复

- **预览图片编辑不再闪回文档开头**：图片属性/名称写回改走 keep-scroll 重渲染入口，不再整篇重渲染；源码区滚动位置也一并恢复。
- **mermaid 小窗滚动与关闭按钮定位**（task-198）：小窗在图表排版期间保持稳定滚动位置，关闭控件改为正确的按钮定位。
- **链接面板 mermaid 渲染**改走主 post-processor（B2）。
- **块编辑聚焦**使用 `preventScroll`；图片属性写回使用 `renderPreviewKeepScroll`（B1）。
- **ask 快照携带 pending summons**（R4-3），面板状态不再静默丢失。
- **行内公式保留 Markdown 活跃字符**：未闭合的行内公式中，只有 `$` 与反斜杠转义是语法，`[ ] _ * ~ `` ` `` !` 作为字面文本发出并拼回公式。报告中的那一行现在解析为恰好 5 个 `math_inline` 节点 + 1 个 URL 正确的链接（`tests/test_math_inline_lexer.py` 共 16 个测试）。
