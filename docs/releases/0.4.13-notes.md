# Memoria v0.4.13

> 0.4.12 → 0.4.13：品牌化的「星穹帷幕」加载蒙层、按时间新旧加权的轮次定位条、长会话窗口化、待发送队列携带附件、断线重连后的遗留作业恢复，以及 E35 的 dev 浏览器矩阵收口；无数据迁移。**P08 使用频次统计与 0.5 多层级图谱均未完成，不在本版承诺范围内。**

## English

### Why upgrade

Three user-facing reasons to install this PATCH release:

1. **Startup now carries the identity and the accumulated shape of your knowledge base.** The loading veil was rebuilt as the **Astral Veil (星穹帷幕)**: a centred Memoria mark with a gradient wordmark and the existing heartbeat pulse, over a procedurally generated, depth-layered starfield and knowledge-shaped nebulas. The nebulas are derived from the file/KP/group counts of the KB you are opening, and the last profile is cached locally per KB, so a cold start can show its accumulation before the graph has loaded. The mask is ref-counted and stays up until the composer is actually ready — the previous timer-based splash could disappear while a load was still pending, and pasting an attachment during startup could silently lose it. It now also matches the editor background and respects `prefers-reduced-motion` with a single static frame.
2. **Long conversations are navigable and fast again.** The turn rail now uses **recency-weighted spacing** (older turns compress, newer turns spread out), keeps a 28-turn window over the full message list, pages older history with the **mouse wheel** over the rail (3 turns per step, without scrolling the transcript), and clicking an older mark **expands the rendered window** to that turn and jumps to it. The rail moved to the left gutter so it no longer competes with the native scrollbar on the right, and scroll updates read cached offsets instead of querying every turn.
3. **Long and queued sessions recover instead of getting stuck.** Initial rendering is limited to the **most recent 60 messages**; a top button prepends the previous 60 while preserving scroll position, and folded process rows build their DOM only when expanded. In a temporary copy of a real KB, the largest session went from **>120 s (timeout)** to **0.74 s** for the initial window (~1.5 s to load the earlier 60). On an unexpected reconnect, a stale backend `busy` job from the old panel is **cancelled once and the same start is retried**, while normal same-window queueing is untouched. Queue items now **snapshot attachments** (images, document resources and the resource note) with the message; a failed queued send returns to the **front of the queue**, pauses auto-drain and offers a retry.

### New and changed

- **Astral Veil loading mask**: modular `loading-overlay.js` with ref-counted begin/end/track; boot and window-restore use the same layer; the mask cannot disappear while another load is pending. Centre stage contains the Memoria icon, wordmark and a hint; the theme follows the app tokens; the starfield is canvas-generated at runtime (not a GIF or CSS keyframes).
- **Knowledge-shaped nebulas**: `MemoriaLoading.setKnowledgeProfile({files,kps,groups})` adjusts star density and produces 2–7 procedural nebula clouds from the KB's file/KP/subgraph counts; one measured profile (812 files / 1,359 KPs / 6 subgraphs) produced 7 coloured clouds and 420 stars. The last graph profile is cached per KB in `localStorage` so the next cold start can show the accumulated shape before graph data arrives.
- **Recency-weighted turn rail**: one mark per known user turn (including single-turn conversations); 28-turn `RAIL_WINDOW_TURNS`; nonlinear spacing `top = usable * (i/(n-1))^1.75`; wheel paging by 3 turns; clicking an older mark sets `renderStart` to that turn and re-renders the message window; themed hover preview and active tick; fixed 10 px minimum hit gap.
- **Long-session windowing**: `INITIAL_RENDER_MESSAGES = 60`; a top "load earlier" control prepends 60 messages with scroll-position preservation while the full `messages[]` array is kept; rail turn numbers use the global offset; compact process folds are created lazily on expand.
- **Queued attachments**: queue items snapshot ready images (`rel_path`/`media_type`/`name`), ready document resources (`rel_path`/`kind`/`name`) and the resource note at enqueue time; the composer draft is cleared only after the push; the queue renders an attachment-count badge and user bubbles keep queued image thumbnails. Drain sends the snapshotted payload through `ask({text, images, resources, resourceNote})` with detached snapshots.
- **Reconnect recovery**: when `agent_ask_start` returns `busy` with a `job_id` and the panel has neither a local job nor busy state, it calls `agent_ask_cancel(job_id)` once and retries the same start; the waiting tool wakes as cancelled/closed and releases the single-flight slot.
- **E37 and AG110 fixes**: source line/column selection is captured before `setViewMode` rebuilds the editor and restored after reflow (source → split keeps the selection/focus); session mentions `@[...](dsh-session:...)` are tokenized with one `(^|\s)` prefix for all token kinds, so a mention after whitespace stays one session chip instead of being split into a file chip plus trailing URI.
- **E35 closure evidence**: the code fix `a1810ce9` already shipped in v0.4.12; this release adds the **dev WebView2/CDP browser matrix** (currency `$`, escaped `\$`, inline/display math, table/link/code, CJK standalone `$`, save/reopen) that was previously missing. E35 is closed with residual unverified combinations listed below rather than claimed as universally proven.

### Fixes and disclosures

- **Loading mask** now matches the editor background (`var(--bg-primary)`, no radial gradients), waits for agent config/history readiness before hiding, and can no longer be removed by a timer while `initKb` or a restore token is pending; this fixes the reported loss of an attachment pasted during startup.
- **Turn rail** no longer shares the scrollbar side (left gutter, right native scrollbar), no longer performs O(turns) layout reads per scroll event, and no longer hides itself for single-turn sessions.
- **Queue failure path** keeps the failed message at the head, pauses automatic drain and exposes retry; `queueGeneration` prevents a failed in-flight send from resurrecting a queue that was cleared or whose KB was switched.
- **E35 disclosure**: the dev matrix closed the previously missing browser-level proof, but multi-cursor undo, nested `details`/mermaid, full-width punctuation adjacency, and split-context-menu/paste remain **explicitly unverified** (not known failures).
- **P08 (usage-frequency statistics) is not implemented.** Only documentation/architecture decisions landed; it is blocked on a Worker endpoint contract. No token, no `site/**` change and no counter exists in this release.
- **No data migration and no `schema_version` bump.**
- The release-test copy under `Memoria-release-test/` is a local update-test install, not a build output; its inherited low-integrity label failure and repair are documented in `operations.md §6` and do not affect the distributed package.

### Upgrade notes

- **This is a PATCH: no data migration, no `schema_version` change, and replacing the application folder is safe.** Existing knowledge bases are not rewritten.
- Settings and API key remain in `%LOCALAPPDATA%\Memoria\config`.
- The in-app update check/download behaviour is unchanged; v0.4.13 is the package used to exercise the local-build → Release asset → in-app update path.
- The pending conversation queue is still **in memory** (survives turn completion, not application restart). Attachments are now snapshotted per queued item, but queued items themselves are not persisted across restarts.
- The loading veil is a visual layer only; it does not alter startup ordering or add network calls. The KB profile cache is local `localStorage` data, not part of the knowledge base.

## 中文

### 为什么要升级

本次 PATCH 版本值得安装的三件事：

1. **启动画面现在承载产品身份，也承载你知识库的积累形态。** 加载蒙层重做为 **星穹帷幕（Astral Veil）**：中心是 Memoria 图标 + 渐变艺术字 + 既有心跳脉冲，底图是程序化生成的分层星场与知识库形态星云。星云由本次打开的知识库的 files / KPs / groups 数量推导，并按库在本地缓存上一次形态，因此冷启动可以在图谱数据到达前就显示它的积累。蒙层改为引用计数，并且**等到输入框真正可发送才消失**——旧的定时 splash 可能在加载尚未结束时提前淡出，启动期间粘贴的附件会静默丢失；现在蒙层还与编辑器背景一致，并在 `prefers-reduced-motion` 下只绘制一帧静态星图。
2. **长会话重新变得可导航、也更快。** 轮次定位条改为**按新旧加权**的间距（旧轮次压缩、新轮次展开），在完整消息列表上保持 28 轮窗口；在定位条上**滚轮**可翻页找更旧历史（每步 3 轮，不滚动正文）；点击旧轮次会把渲染窗口扩展到该轮并跳转。定位条移到左侧留白，不再和右侧原生滚动条抢位置；滚动更新改为读取缓存偏移，不再每轮做布局查询。
3. **长会话和排队会话会恢复，而不是卡死。** 首屏只渲染**最近 60 条消息**；顶部「加载更早」按钮在保持滚动位置的前提下再加载前 60 条，折叠的过程行改为展开时才建 DOM。在真实知识库的临时副本上，最大会话从 **>120 秒（超时）** 降到初始窗口 **0.74 秒**（加载更早 60 条约 1.5 秒）。异常断线重连后，旧面板遗留的后端 `busy` 作业会**先取消一次，再重试同一次 start**；正常同窗排队不受影响。待发送队列现在把**附件快照随消息一起排队**（图片、文档资源、note）；排队发送失败会放回**队首**、暂停自动 drain 并提供重试。

### 新增与变更

- **星穹帷幕加载蒙层**：新增模块化 `loading-overlay.js`，用引用计数 begin/end/track；启动与窗口恢复共用同一层，只要还有加载任务就不会消失。中心舞台是 Memoria 图标、艺术字与一行提示；主题跟随应用 token；星场在运行时由 canvas 程序化生成（不是 GIF / CSS keyframes）。
- **知识库形态星云**：`MemoriaLoading.setKnowledgeProfile({files,kps,groups})` 调整星点密度并生成 2–7 团程序化星云；实测一个 profile（812 files / 1,359 KPs / 6 subgraphs）生成 7 团彩色星云与 420 颗星。最近一次图谱 profile 按库缓存在 `localStorage`，使下一次冷启动能在图谱数据到达前显示积累形态。
- **按新旧加权的轮次定位条**：每个已知用户轮次一个标记（单轮会话也显示）；`RAIL_WINDOW_TURNS = 28`；非线性间距 `top = usable * (i/(n-1))^1.75`；滚轮每步翻 3 轮；点击旧标记会把 `renderStart` 设为该轮并重渲染消息窗口；主题化悬浮预览与激活刻度；最小点击间距 10 px。
- **长会话窗口化**：`INITIAL_RENDER_MESSAGES = 60`；顶部「加载更早」在保持滚动位置的情况下再前置 60 条，`messages[]` 始终保留完整会话；定位条轮次编号使用全局偏移；折叠过程行仅在展开时创建 DOM。
- **待发送队列携带附件**：入队时快照就绪的图片（`rel_path`/`media_type`/`name`）、就绪的文档资源（`rel_path`/`kind`/`name`）与 resource note；草稿仅在入队成功后清空；队列显示附件计数徽标，用户气泡保留排队图片缩略图。drain 通过 `ask({text, images, resources, resourceNote})` 发送快照，并以 detached snapshot 避免清掉下一条草稿。
- **断线重连恢复**：当 `agent_ask_start` 返回 `busy` 且带 `job_id`、而本面板既无本地 job 也无 busy 状态时，调用一次 `agent_ask_cancel(job_id)` 再重试同一次 start；旧 waiting tool 以 cancelled/closed 唤醒并释放 single-flight 槽。
- **E37 与 AG110 修复**：`setViewMode` 重建编辑器前捕获源码行列选区，重排后恢复（源码 → 分栏后选区/焦点保持）；会话引用 `@[...](dsh-session:...)` 的所有 token kind 统一使用 `(^|\s)` 前缀，空白后的引用保持一个 session chip，不再被拆成文件 chip + 尾随 URI。
- **E35 收口证据**：代码修复 `a1810ce9` 已在 v0.4.12；本次补上此前缺失的 **dev WebView2/CDP 浏览器矩阵**（货币 `$`、转义 `\$`、行内/块级公式、表格/链接/代码、CJK 独立 `$`、保存/重开）。E35 以「已收口 + 残余未验证组合」记录，而不是宣称所有组合都已证明。

### 修复与披露

- **加载蒙层**改用与编辑器相同的 `var(--bg-primary)`（去掉径向渐变），并等到 agent config/history 就绪才隐藏；不再由定时器在 `initKb` 或窗口恢复 token 未释放时移除——修复了启动期间粘贴附件会丢失的问题。
- **轮次定位条**不再与滚动条同侧（左侧留白，右侧保留原生滚动条）；滚动路径不再对每一轮做 O(turns) 布局读取；单轮会话不再隐藏定位条。
- **队列失败路径**把失败消息留在队首、暂停自动 drain 并显示重试；`queueGeneration` 防止失败的在途发送把已经清空/切换知识库的队列「复活」。
- **E35 披露**：dev 矩阵补齐了此前缺失的浏览器级证明；但多光标撤销、嵌套 `details`/mermaid、全角标点相邻、分栏右键菜单/粘贴这些组合仍**明确未验证**（不是已知失败）。
- **P08（使用频次统计）未实现**。本版只有文档/架构决策落地；它被 Worker 端点契约阻塞，仓库里没有 token、没有 `site/**` 改动、也没有计数器。
- **无数据迁移，`schema_version` 不变。**
- `Memoria-release-test/` 下是本地更新测试副本，不是构建产物；它继承的低完整性标签故障与修复记录在 `operations.md §6`，不影响分发包。

### 升级注意

- **这是 PATCH：无数据迁移、`schema_version` 不变，直接替换应用目录是安全的。** 已有知识库不会被改写。

- 应用内更新检查/下载行为本次未改；v0.4.13 用于验证「本地构建 → Release 资产 → 应用内更新」这条路径。
