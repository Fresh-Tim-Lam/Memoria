# Memoria v0.4.15

> 0.4.14 → 0.4.15：**更新页加入“一键自动更新并重启”（用户显式确认后执行）**。下载完成后，Memoria 写更新作业、启动独立 helper、退出并等待 helper 替换应用目录，然后自动重启；失败自动回滚。无数据迁移、无 `schema_version` 变化。0.4.14 已有的 Release notes Markdown 渲染与 C10 弹窗层级修复继续保留。

## English

### Why upgrade

1. **No more manual folder replacement for the normal path.** After the installer is downloaded and verified, the Updates tab now offers **Update and restart automatically**. Memoria writes a job, launches a hidden updater helper, exits, and the helper replaces only the application folder before starting the new build.
2. **It is opt-in, not silent.** Nothing is replaced until you click the button and confirm the dialog. The dialog shows the target version, backup directory, and the fact that the package is verified by digest/structure **but not by a digital signature**.
3. **Rollback is part of the path.** The helper re-checks sha256 and the new `VERSION`, extracts to a sibling staging directory, renames the old app folder to a timestamped backup, and starts the new build. If activation or startup fails, it restores the backup and writes `update-result.json`.
4. **Lite keeps `hf/`.** A lite package has no models; the helper moves the installed `hf/` from the backup into the new app folder. The app config in `%LOCALAPPDATA%\Memoria\config` is never inside the replaced folder.

### New and changed

- `src/memoria/services/update_auto.py`: prepare/start/result for the automatic path; consumes only a completed download job, re-verifies the final zip, writes an atomic job JSON, and spawns a detached PowerShell helper.
- `resources/updater/apply_update.ps1`: waits for Memoria to exit, re-checks sha256, extracts staging, validates `VERSION`/`Memoria.exe`, preserves `config/`, swaps the app directory with backup/rollback, preserves `hf/` for lite, restarts, and records the result.
- `src/memoria/presentation/api/ui.py`: RPCs `prepare_auto_update`, `start_auto_update`, `get_auto_update_result`.
- `src/memoria/ui/static/app/js/update-settings.js` + `i18n/{en,zh-CN}.js`: one-click button, confirmation, progress state and next-launch result banner; manual steps remain as fallback.
- `packaging/build.py`: `resources/updater/apply_update.ps1` is a required packaged resource.

### Fixes and disclosures

- **Explicit consent:** automatic replacement is never silent. The default/manual path remains visible as fallback.
- **No digital signature:** only the GitHub asset sha256, zip structure and in-package `VERSION` are checked. This is not code signing and does not claim tamper-proofing.
- **Windows/frozen only:** development builds and read-only install directories return `unsupported` and fall back to manual steps.
- **No data migration and no `schema_version` change.** Knowledge bases are not rewritten; only the application folder is replaced.
- **Scope:** automatic update is for the downloaded release asset only; it does not download deltas, delete backups, or change the update source.

### Known debts

- Full pytest is not rerun for this PATCH; targeted update/C10/auto-helper tests are the release-candidate verification.
- Automatic update is only available on Windows packaged builds; existing 0.4.14 clients must upgrade manually once to receive it.
- P08 usage-frequency statistics and 0.5 multilevel graph remain undelivered.

## 中文

### 为什么要升级

1. **常规更新不再需要手动替换文件夹。** 安装包下载并校验完成后，更新页提供 **“自动更新并重启”**：Memoria 写更新作业、启动隐藏的 helper、退出，由 helper 只替换应用目录并启动新版本。
2. **必须显式确认，不做静默替换。** 只有点击按钮并在确认框确认后才执行；确认框展示目标版本、备份目录，并明确说明只校验了下载包摘要/结构，**没有数字签名**。
3. **回滚是路径的一部分。** helper 会重新校验 sha256 与新包 `VERSION`，解压到同盘 staging，把旧应用目录改名为带时间戳的 backup，再启动新版本；激活或启动失败会恢复 backup，并写 `update-result.json`。
4. **lite 保留 `hf/`。** lite 不含模型，helper 会把旧 `hf/` 从 backup 移入新目录；`%LOCALAPPDATA%\Memoria\config` 不在被替换的文件夹里，配置不受影响。

### 新增与变更

- `src/memoria/services/update_auto.py`：准备/启动/读取结果；只接受“下载已完成”的 job，重新校验最终 zip，原子写 job JSON，并启动独立 PowerShell helper。
- `resources/updater/apply_update.ps1`：等待 Memoria 退出、复核 sha256、解压 staging、校验 `VERSION`/`Memoria.exe`、保留 `config/`、备份/替换/回滚、lite 保留 `hf/`、重启并记录结果。
- `src/memoria/presentation/api/ui.py`：新增 `prepare_auto_update`、`start_auto_update`、`get_auto_update_result` RPC。
- `src/memoria/ui/static/app/js/update-settings.js` + `i18n/{en,zh-CN}.js`：一键按钮、确认框、启动状态和下次启动结果横幅；手动步骤保留作兜底。
- `packaging/build.py`：`resources/updater/apply_update.ps1` 登记为必带资源。

### 修复与披露

- **显式确认：** 自动替换绝不静默执行；默认手动路径仍保留。
- **没有数字签名：** 只校验 GitHub asset sha256、zip 结构、包内 `VERSION`；这不是代码签名，也不声称防篡改。
- **仅 Windows 发布态：** 开发态、只读安装目录返回 `unsupported`，降级为手动步骤。
- **无数据迁移、`schema_version` 不变。** 知识库不会被改写，只替换应用目录。
- **范围：** 只处理已下载的发布资产；不做增量包、不自动删除 backup、不改变更新源。

- 本次 PATCH 未重跑全量 pytest；以上更新/自动更新/C10/console 定向测试是发布候选验证。
- 自动更新只在 Windows 打包态可用；停留在 0.4.14 的客户端必须先手动升级一次才能收到该功能。
