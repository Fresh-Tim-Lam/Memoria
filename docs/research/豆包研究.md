# Memoria vs Obsidian / Logseq 横向架构&功能对比
> Memoria：Python后端 + Web前端，本地文件驱动；Obsidian：Electron+TS；Logseq：Clojure+Electron

## 一、核心底层差异
|项目|存储方案|双链解析位置|图谱引擎|复习系统|跨平台|
|---|---|---|---|---|---|
|**Memoria**|`.md` + `.memoria.yaml`，无SQLite|Python后端，**片段级链接（精确到行范围）**|内存图，2D+3D渲染|自研KP间隔复习，嵌入笔记片段|仅Windows，路径硬编码|
|**Obsidian**|`.md` + 内嵌SQLite（缓存/元数据）|前端TS，文件级双链为主|前端D3，仅2D|依赖Anki插件/第三方|全平台，移动端|
|**Logseq**|`.md`，块引用|前端，**块级链接（块ID）**|前端2D图谱|内置简易间隔复习|全平台|

## 二、功能粒度对比
### ✅ Memoria独有亮点
1. **片段级WikiLink**：链接可以定位到某一段文字，不是整个文件。Obsidian原生只能跳文件，需要插件才能块引用；Logseq天然块，但语法独立。
2. **原生3D知识图谱**，Three.js空间可视化；Obsidian/Logseq只有2D。
3. 内置**离线中文分词检索 + 可选本地向量语义检索**，不用额外插件。
4. 复习系统原生集成：KP标记直接写在笔记里，卡片就是原文片段，不用单独摘抄卡片（Anki/Obsidian插件要手动抽卡）。
5. 元数据分离：正文是标准md，yaml单独存图谱、复习记录，md文件完全通用，不会污染笔记正文。

### ✅ Obsidian优势
1. 插件生态爆炸，上千插件，自定义空间极大。
2. 成熟稳定，大库（上万笔记）性能更好，底层SQLite缓存。
3. 移动端、同步方案多，社区成熟。
4. 自定义CSS、主题、Canvas白板。
> 短板：原生双链是文件级；块引用靠插件；复习能力依赖Anki插件，需要双向同步，有同步冲突风险。

### ✅ Logseq优势
1. **块优先（block-first）**，所有内容是块，块引用是一等公民，适合Zettelkasten、每日日志。
2. 大纲写作体验极强，适合线性思考、每日记录。
> 短板：Markdown兼容性弱于Obsidian，图谱简单，中文检索一般，生态远小于Obsidian。

## 三、技术架构取舍对比
1. **Memoria**
    - 优点：业务逻辑后端集中，适合扩展NLP、向量检索、图算法；浏览器前端，UI开发成本低。
    - 缺点：**全量图载入内存**，笔记量大时内存压力大；仅Windows；项目新，单人开发，生态≈0；打包exe体积大。
2. **Obsidian**
    - 优点：Electron单应用，前端完成绝大多数逻辑，本地SQL缓存，大库性能更好。
    - 缺点：插件生态带来版本兼容坑；块引用属于附加能力，不是原生设计。
3. **Logseq**
    - 优点：Clojure的不可变数据模型，块结构天然适合双向引用。
    - 缺点：Clojure小众，二次开发门槛高；渲染和性能上限一般。

## 四、适用人群
- **Memoria**：喜欢Zettelkasten，需要**片段链接+原生复习+3D图谱**，Windows用户，愿意接受早期项目bug，想二次开发（Python友好）。
- **Obsidian**：绝大多数人，追求稳定、插件、多端同步，通用笔记知识库。
- **Logseq**：重度大纲、日志、块思维用户。

## 五、核心缺陷总结
- Memoria：**早期独立项目，生态空白，不适合上万笔记生产库，跨平台差**
- Obsidian：块/片段引用不是原生，复习需要对接Anki，有同步成本
- Logseq：markdown兼容性差，中文检索弱，生态有限
