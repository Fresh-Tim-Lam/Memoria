## 知识文件整理导入提示词

> **用途**：将此提示词连同你的知识文件一起发给 AI agent，agent 会将原始内容整理为 Memoria 可识别的格式，然后你可以将输出结果导入 Memoria 知识库（新建或增量追加）。

```markdown
# 任务

你是一个知识文件整理助手。用户会提供一份或多份原始知识文本，你需要将其整理为 **Memoria 知识库格式**，以便导入 Memoria 系统。

**核心原则：不修改原文内容，只做整理、排版、知识点标注和链接标注。**

---

# Memoria 数据格式规范（必须严格遵守）

## 1. 基本单位：知识点（KP）

- 每个 KP 有**全局唯一 id**（英文 slug，如 `bayes-rule`、`decision-tree`）
- 一个 `.md` 文件可包含多个 KP，每个 KP 对应文件中一个语义完整的段落（通常以 `##` 或 `###` 标题开头）
- 文件由文件名标识，文件本身不需要 id 字段

## 2. 文件结构：Markdown frontmatter + 正文

每个输出文件格式如下：

```markdown
---
description: 一句话说明本文件主题
concepts:
  - id: kp-id-1
    name: 知识点名称1
    weight: 1.0
    tags: [标签1, 标签2, 标签3]
  - id: kp-id-2
    name: 知识点名称2
    weight: 0.8
    tags: [标签a, 标签b]
---

## 知识点名称1

（原文内容，保持原样不修改）

这里可以出现 `[[目标知识点id]]` 形式的链接，表示对其他知识点的引用。

## 知识点名称2

（原文内容，保持原样不修改）
```

### frontmatter 字段说明

| 字段 | 说明 |
|------|------|
| `description` | 文件的一句话描述 |
| `concepts` | 知识点列表 |
| `concepts[].id` | 全局唯一英文 slug（必填） |
| `concepts[].name` | 知识点中文名称（必填） |
| `concepts[].weight` | 重要程度 0~1（可选，默认 1.0） |
| `concepts[].tags` | 标签列表，辅助搜索（可选） |

## 3. 链接语法

在正文中使用 `[[...]]` 标注知识点之间的关联：

| 语法 | 含义 | 示例 |
|------|------|------|
| `[[kp-id]]` | 引用目标知识点 | `[[bayes-rule]]` |
| `[[kp-id\|显示文本]]` | 引用目标，但显示不同文本 | `[[bayes-rule\|贝叶斯公式]]` |

**注意**：链接的 `[[...]]` 会替换原文中对应位置的文本。如果原文已经提到了某个概念，将提到该概念的地方用 `[[该概念的kp-id]]` 包裹即可。

## 4. 边类型（链接语义）

| 类型 | 含义 | 使用场景 |
|------|------|----------|
| `reference` | 引用/参考 | A 提到了 B，B 是 A 的背景或相关概念 |
| `extend` | 扩展/下游 | A 是 B 的具体实现或特例 |
| `contain` | 包含/父子 | 标题层级关系（系统自动生成，**不需要手动标注**） |

`contain` 类型由文件内的标题层级自动产生（`##` 包含 `###`），**不要**在正文中手动标注。

## 5. 知识点划分原则

- 一个 `##` 二级标题通常对应一个 KP
- 如果二级标题下内容很短（<3 行），可与相邻标题合并为一个 KP
- 每个 KP 的范围应覆盖**完整语义段**，不要截在空行上
- KP 的 `id` 用英文 slug（小写、连字符分隔），`name` 用中文

## 6. 目录结构

```
knowledge-base/
  topic-a.md
  topic-b.md
  subdir/topic-c.md
  .memoria/
    sidecars/
      topic-a.memoria.yaml
      topic-b.memoria.yaml
      subdir/topic-c.memoria.yaml
```

# 整理规则（严格遵守）

## 必须做的

1. **保留原文内容**：正文中的知识性文字必须原封不动保留，不删减、不改写、不总结、不扩写
2. **划分知识点**：将原文按主题/段落划分为独立 KP，每个 KP 分配唯一 id 和中文 name
3. **排版标题层级**：用 `##` / `###` 等 Markdown 标题组织知识点层次
4. **标注链接**：识别正文中提到的其他知识点，用 `[[kp-id]]` 标注关联
5. **生成 frontmatter**：为每个文件生成 `description` 和 `concepts` 列表
6. **添加 tags**：为每个 KP 添加有助于搜索的标签（领域、类型、关键词等）

## 禁止做的

1. **禁止修改原文语义**：不得改写、缩写、扩写、总结原文内容
2. **禁止删除原文段落**：即使内容有误，也保留原文（见下方标注规则）
3. **禁止添加原文没有的知识**：不要补充你认为"应该有"的内容
4. **禁止合并不同主题的内容到一个 KP**：每个 KP 应聚焦单一概念

## 允许标注的情况

如果整理过程中发现原文可能存在问题，用以下方式标注（不修改原文）：

- **事实性疑问**：在可能有误的内容后追加 `<!-- ⚠️ 待核实：简要说明 -->`
- **逻辑/表述存疑**：在存疑处追加 `<!-- ❓ 存疑：简要说明 -->`
- **术语/符号歧义**：在歧义处追加 `<!-- 🔄 歧义：简要说明 -->`

标注格式统一使用 HTML 注释 `<!-- ... -->`，不会影响 Markdown 渲染。

### 使用方法

2. **导入 Memoria**：在 Memoria UI 中点击「导入」按钮，选择 agent 输出的 `.txt` 文件，系统自动完成导入
3. **多文件整理**：一次提供多份知识文件时，agent 会自动识别跨文件关联并标注 `[[kp-id]]` 链接
4. **分步确认**：文件较多时，可要求 agent 先输出知识点总览表，确认 KP 划分合理后再输出完整文件
5. **冲突处理**：若导入时发现 KP id 与已有知识库冲突，Memoria 会弹出详细冲突报告（可复制给 agent 修正 id 后重新导入）

## 平面导入文件格式规范

> Memoria 导入引擎接受的文件格式。agent 输出的整理结果必须严格遵循此格式，否则导入会失败。

### 基本结构

一个平面导入文件（`.txt`）包含**一个或多个文档段**，每个段由 `---` 分隔：

```
---
description: 第一份文档的描述
concepts:
  - id: kp-id-1
    name: 知识点名称1
    weight: 1.0
    tags: [标签1, 标签2]
  - id: kp-id-2
    name: 知识点名称2
    weight: 0.8
    tags: [标签a]
---

## 知识点名称1

正文内容，可包含 [[其他kp-id]] 链接。

## 知识点名称2

正文内容。

---
description: 第二份文档的描述
concepts:
  - id: kp-id-3
    name: 知识点名称3
    weight: 1.0
    tags: [标签x]
---

## 知识点名称3

另一份文档的正文。
```

### 格式要点

| 要素 | 规则 |
|------|------|
| **段分隔符** | 独占一行的 `---`，前后不能有缩进或空格 |
| **frontmatter** | 每段开头的 YAML 块，夹在两个 `---` 之间 |
| **description** | 文件的一句话描述（必填） |
| **concepts** | 知识点声明列表（至少 1 个） |
| **concepts[].id** | 全局唯一英文 slug（必填，不能与知识库中已有 KP id 重复） |
| **concepts[].name** | 中文知识点名称（必填，必须与正文中的 `##`/`###` 标题完全一致） |
| **concepts[].weight** | 重要度 0~1（可选，默认 1.0） |
| **concepts[].tags** | 标签列表（可选） |
| **正文** | frontmatter 第二个 `---` 之后的内容，标准 Markdown |
| **标题层级** | `##` = 一级 KP，`###` = 二级 KP（嵌套在 `##` 下） |
| **链接** | `[[kp-id]]` 或 `[[kp-id\|显示文本]]`，指向其他 KP |

### 一段 = 一个 .md 文件

导入引擎将每个 `---` 段生成一个独立的 `.md` 文件：
- 文件名 = 段内第一个 KP 的 `id` + `.md`（如 `bayes-rule.md`）
- 同时自动生成对应的 sidecar `.memoria.yaml`（含 KP range、links）
- 自动调用 `build_knowledge_base()` 生成图谱

### 多文件导入

Memoria 支持同时选择多个 `.txt` 文件导入（适用于 agent 分批输出的场景）。所有文件会被合并处理：
- 先统一预扫描所有段的 KP id
- 检测冲突（段间重复 + 与已有库重复）
- 无冲突则一次性全部导入

### 冲突报告格式

如果存在 KP id 冲突，Memoria 弹出对话框并生成如下格式的报告（可复制给 agent 修正）：

```
[导入冲突报告]
共扫描 3 个文件、15 个 KP 声明，发现 2 个冲突：

冲突 1：
  KP id: mdp
  导入来源: batch2.txt 段2 (第67行)
  已有位置: mdp.md → 马尔可夫决策过程

冲突 2：
  KP id: bayes-rule
  导入来源: batch3.txt 段1 (第3行)
  已有位置: probability.md → 贝叶斯公式

建议操作：
- 若需保留两者，请将导入文件中的 id 改为不同值
- 若需覆盖已有，请在导入界面选择"覆盖"
- 若需跳过，请在导入界面选择"跳过"
```

用户对每个冲突可选择：
- **跳过**：该 KP 所在的整段不导入
- **覆盖**：用导入内容替换已有 KP
- **重命名**：给冲突 id 加前缀（如 `imported-mdp`），保留两份

### Memoria UI 导入操作步骤

1. 打开 Memoria，先「打开」一个知识库目录（或新建空目录作为知识库根）
2. 点击工具栏「导入」按钮
3. 在文件选择器中选择一个或多个 `.txt` 平面导入文件
4. 如果无冲突：直接导入完成，显示结果摘要（文件数、KP 数、边数）
5. 如果有冲突：弹出冲突对话框 → 查看报告 → 逐条选择处理方式 → 确认导入
6. 导入完成后，文件树和图谱自动刷新
