# 写技能（skill-creator）

> 本技能**随应用分发**（在知识库目录之外），它**没有**需要你另外读取的资源文件——照着下面做即可，
> 不要去读技能的资源目录（库外路径会被读取工具拒绝）。

## 1 技能是什么、不是什么

技能是**可复用的任务说明书**：一段 Markdown 正文 + 几行 frontmatter。系统在「可用技能」目录里只显示
它的一句话摘要；模型（或用户）用 `skill` 工具按名加载全文，照它执行。

它**只加指令、不加工具**：正文说"怎么做"，但它能用的工具仍只有系统里已有的那套，也不会引入任何
执行体。所以技能再怎么说"改库"，也绕不过 `propose_write` 的校验 / 备份 / 撤销——这是它的边界，别在
正文里教模型绕过它。

## 2 放哪里

库内技能根：`<知识库>/.memoria/agent/skills/`，两种形态二选一：

- 目录包（推荐，能带 `assets/`）：`<skills>/<name>/SKILL.md`；
- 平铺包：`<skills>/<name>.md`。

技能名必须是 **kebab-case**（小写字母/数字，`-` 连接），如 `kb-maintenance`、`web-research`。
同名时**库内永远盖过随包内置**：想改内置技能，就在库内建同名那份，别指望改随包文件。

## 3 frontmatter（`description` 是触发键）

```yaml
---
name: 技能名                 # 必填；kebab-case，唯一
description: 一句话用途       # 必填；第三人称，写明"什么时候用"——这是目录里唯一的文字
whenToUse: 更细的触发场景     # 可选；补 description 没写下的触发条件（注意它用 camelCase）
disable-model-invocation: true  # 可选；true ⇒ 模型目录里看不见，只能靠 /name 手势
user-invocable: true            # 可选；默认 true
---
```

三条硬约定：

- **`description` 是目录里唯一能看到的文字**，模型靠它决定"要不要加载你"。写清**触发条件**，
  别只写"处理文件"这种空话；好例子见 `web-research` 的 description。
- **旧键一律拒**：`disable-model-invocation` / `user-invocable` 用 kebab 形式，别写
  `modelInvocable` / `userInvocable` 这类 camelCase 旧名（会被拒并指路）；`whenToUse` 是唯一
  保留 camelCase 的键。
- frontmatter 首行必须是 `---`，闭合 `---` 独占一行，YAML 必须是**对象**；任一不满足整份被跳过。

## 4 正文怎么写（四条精华）

1. **单一职责**：一个技能只做一件事；要做两件事就拆两个技能。
2. **可操作**：给步骤 / 表格 / 示例 / 检查清单，别只给原则——模型是照它执行的。
3. **自足**：内置技能（`resources/agent-skills/**`）正文必须**自足**——它的资源目录在库外、模型读不到，
   所以所有要点都写进正文，并明说"别去读我的目录"。库内技能可带 `assets/`，正文引相对路径时要说清
   "相对技能目录解析、按需读"。
4. **何时停下问人**：写清哪些情况必须停、把错误码/症状如实转述给用户；不要绕、不要编。

## 5 不许做的事

- 技能**不含代码**、不能新增工具、不能新增执行体；它只改模型"怎么做"的指令。
- 不要写太长：正文每次加载都进上下文，精简到能跑通流程即可，重参考放资源文件（见 §4.3）。
- 不要在正文里教模型绕过写路径 / 审批 / 只读纪律。
