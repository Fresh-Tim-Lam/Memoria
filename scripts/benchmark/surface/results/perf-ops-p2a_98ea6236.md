## 滚动专项（Lead 重点项）

**单位是「帧间隔」，不是「操作耗时」** —— 帧间隔的物理下限就是 vsync 周期 `1000/60 ≈ 16.67 ms`。
所以 `p95 ≤ 16ms` 在 60Hz 上**物理不可达**（那是把刷新率当要求）。scroll 预算改用：**p95 ≤ 20 ms（下限+一帧容差）且 卡顿比例 ≤ 0.05 且 长任务 = 0**，并保留「不退化 >1.15× P_old」回归判据。

| 条件 | 实测 | 门槛 | 结果 |
|---|---|---|---|
| 帧间隔 p95 | **18.45 ms** | ≤ 20.0 ms | ✅ |
| 卡顿比例（帧间隔 > 25ms） | **0.02** | ≤ 0.05 | ✅ |
| 长任务 | 中位 0 个 / 最长 0 ms | = 0 | ✅ |

- 帧间隔明细：p50=16.7 ms，max=32.3 ms（150 帧）；滚动距离 2000 px
- **滚动判定：🟢 PASS**

## 预算口径

**绝对预算 = min(用户可感知阈值, P_old × 1.15)**；无用户阈值的取 `P_old × 1.15`。

| 操作 | 用户可感知阈值 | 依据 |
|---|---|---|
| `typing` | 16.0 | 60fps 单帧预算（gate §0 G1' 既定目标 16ms）；单位是「操作耗时」，16ms 合理 |
| `open` | 1000.0 | 可接受首开阈值（gate 已用 1434ms 观测作参照） |
| `scroll` | **不含固定 ms 阈值** | 帧间隔物理下限 = vsync 16.67 ms，`≤16ms` 不可达 ⇒ 改用三重判据（见「滚动专项」） |
