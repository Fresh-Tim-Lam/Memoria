# task-79 — `17ee05d9`（淘汰饥饿修复）是否引入“淘汰抖动/回流”

结论：**否（阈值 4 下未引入可测的抖动/回流）**。唯一例外是**阈值降到 3** 时会出现“淘汰比物化还勤”的轻量回流（2.25%/最坏 5%），因此**不建议把 4 改小**；阈值 6 虽无回流，但 `maxMaterialized` 逼近 8 屏上限且帧成本更差。

## 1. 方法与可信门

- 真机 pywebview + WebView2（`MEMORIA_MODE=dev`、`MEMORIA_FRAMELESS=0`、CDP 9635），`MEMORIA_KB` 为 `_kbwork_perf_edu` 的逐字节副本；每 run 冷启动 app（新页面、新配置目录）。
- 文档 `教材/08_第8章_差错控制编码.md`，**4001 块**。
- app.js 变体通过**临时静态根**在启动时替换（`_t79_launch.py` 只重定向 `static_server._STATIC_ROOT` + `UI_APP_INDEX`），**未修改 `src/**`**；其余静态资源逐字节同仓库。
- 测量可信门（每 run 强制）：WebGL 可用 + 打开后空转 rAF p50 ≤ 20ms + `totalBlocks ≥ 3900`。9/9 run：GPU = RTX 5060 Ti (D3D11)、idle p50 = **8.3ms**、totalBlocks = **4001**。
- 串行化：与惰性门禁共用 `%TEMP%/memoria_lazy_gate.lock`，每 run 取锁后才启动 app。测量期间并发快照：`py=5 wv2=24 node=6 cpu≈18%`，可用内存 12.8GB。
- 重建污染防护：openFile 后偶发一次整篇重渲染（`previewToken+1`、`evictTotal` 归零）。探针用“预热跳转 + token 稳定 3s + 重建批跳过 + 位置重试”处理；最终 **9/9 run 的 W1/W2/W3 污染计数均为 0/0/0**。

### 臂定义（同 build，仅 app.js 不同）

| 臂 | app.js | 说明 |
|---|---|---|
| **V4** | HEAD | 压力阈值 4（含 task-72 typeset 缓存） |
| **Voff** | HEAD + 阈值=1e6 | **隔离本次修复的唯一控制臂**：关闭 P1 压力升级，保留 re-arm 修复 |
| V3 / V6 | HEAD + 阈值=3 / 6 | 阈值敏感性 |
| Vpre | `git show 9c940796:...app.js` | 真实“修复前提交”；**同时缺 typeset 缓存**，非纯隔离 |

执行顺序：`V4, Voff, Voff, V4, V3, V6, Vpre, V3, V6`（交错）。每 run 工作负载：

- **W1**：19 个位置（5%..95%，5% 一步）第一遍 down、第二遍 up；每位置瞬时跳转 + 600ms rAF 采样 + ≤900ms 稳定等待。
- **W2 压力场景**：每 60ms 注入一个 8ms 忙等 P2 作业 + 每帧 900px 连续下拖 6s（17ee05d9 的复现场景），重复 2 次。
- **W3 振荡**：以 120px/帧 下拖 6 屏再上拖 6 屏，循环 6s（无注入），重复 2 次。

回流定义：同一 `data--block-index` 被换出（真块→占位）后 **≤2000ms** 又被物化（占位→真块）。

## 7. 明确结论

**该修复未引入可测的“淘汰抖动/回流”**（阈值 4）：

1. 正常滚动回流 0；压力拖拽回流 0；振荡场景与修复前同水平（差值在噪声内，且帧更好）。
2. 压力场景淘汰块数 ≈ 物化块数（1:1），淘汰作业数仅为物化作业的 0.62× —— 不存在“淘汰跑得比物化还勤”。
3. 第一遍 down 的 rAF max 中位 64.25 vs 修复前 75.45ms（好 18%），`max_frame_ms` 17.0 vs 19.7ms；仅 5% 位置单点 +13%（74.55 vs 65.90ms，绝对值 <100ms）。
4. P1 淘汰占墙钟 ~4.8%，typeset 未被挤占。
5. 唯一风险点是**阈值 3**：会稳定出现 2.25%（最坏 5%）回流且淘汰作业数超过物化作业数；**当前默认值 4 恰好避开**。

## 8. 未验证 / 局限

- 只在有 GPU 的 RTX 5060 Ti 真机测；慢机/软光栅下阈值 4 是否仍合适未验证。
- 未测 >10k 块超长文档、多标签页并发、真实用户 30s+ 连续拖拽（本测 6s/次）。
- W3 的 ~90% 回流是 6 屏振荡 vs 4 屏 keep 的固有现象；未额外用 3 屏振荡证明 0 回流，但已用 Voff/Vpre 双臂对比排除“修复增量”。
- 每臂 2 run（Vpre 1 run）；位置级 `max` 是长尾指标，对样本敏感，结论以中位/比值 + 三项一致性为准。
- Vpre 是真实修复前提交，但同时缺 task-72 typeset 缓存 ⇒ 与 V4 的差包含缓存收益；**纯隔离对照是 Voff**。
